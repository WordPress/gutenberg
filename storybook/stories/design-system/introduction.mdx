# WordPress Design System

The WordPress Design System is a collection of reusable components, design tokens, and guidelines for building consistent, accessible user interfaces in the WordPress administrative dashboard.

It is what WordPress itself is built with, and it is available to plugin developers too. Interfaces made from the same components and tokens look and behave like the rest of WordPress, so your plugin's screens feel native to the dashboard instead of bolted on.

## Build with the Design System

Use [Admin UI](?path=/docs/admin-ui-page--docs), [DataViews](?path=/docs/dataviews-dataviews--docs) and [DataForm](?path=/docs/dataviews-dataform--docs) to build new table and form based interfaces. Use the [components](?path=/docs/design-system-components-introduction--docs) to build completely new custom interfaces.

When building your own components, use [design tokens](https://github.com/WordPress/gutenberg/blob/trunk/packages/theme/docs/tokens.md) as part of your component styles to stay aligned with the design system's own components. The [theming system](?path=/docs/design-system-theme-introduction--docs) provides them as custom CSS properties that you can use in your own stylesheet.

When working with AI agents, use the [WordPress Design System MCP Server](?path=/docs/design-system-using-with-ai--docs). It gives agents the latest component documentation, usage examples, and design tokens.

Designers can find the matching design resources in the [WordPress Design System on Figma](https://www.figma.com/@wordpressds).

## Contributing

If a component, token, or guideline falls short of what you need, report it rather than working around it quietly. [Contributing to the Design System](?path=/docs/design-system-contributing--docs) covers how to report a shortcoming and how to fix it at the source. It applies to AI agents as much as to people.
