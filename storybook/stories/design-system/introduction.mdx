# WordPress Design System

The WordPress Design System is a collection of reusable components, design tokens, and guidelines for building consistent, accessible user interfaces in the WordPress administrative dashboard.

It is what WordPress itself is built with, and it is available to plugin developers too. Interfaces made from the same components and tokens look and behave like the rest of WordPress, so your plugin's screens feel native to the dashboard instead of bolted on.

## Build with the Design System

Foundational packages provide the primitives for building any interface: [components](?path=/docs/design-system-components-introduction--docs), [icons](?path=/docs/icons-icon--docs) and [design tokens](?path=/docs/design-system-theme-introduction--docs).

Compositional packages combine those primitives into complete experiences. Use [Admin UI](?path=/docs/admin-ui-page--docs), [DataViews](?path=/docs/dataviews-dataviews--docs) and [DataForm](?path=/docs/dataviews-dataform--docs) to build table and form based interfaces quickly and consistently.

When building your own components, use [design tokens](https://github.com/WordPress/gutenberg/blob/trunk/packages/theme/docs/tokens.md) in your component styles to stay aligned with the design system's own components. The [theming system](?path=/docs/design-system-theme-introduction--docs) exposes these tokens as custom CSS properties you can use in your own stylesheet.

When working with AI agents, use the [WordPress Design System MCP Server](?path=/docs/design-system-using-with-ai-mcp--docs). It gives agents the latest component documentation, usage examples, and design tokens.

Designers can find the matching design resources in the [WordPress Design System on Figma](https://www.figma.com/@wordpressds).

## Principles of the Design System

The design system is guided by a few principles that distinguish it from the existing [@wordpress/components](https://github.com/WordPress/gutenberg/tree/trunk/packages/components) package:

<PrincipleCards>
  <PrincipleCard title="Cohesive by design">
    Unlike `@wordpress/components`, which grew organically as a collection of unrelated UI elements, this design system guarantees user- and developer-facing cohesion through a unified token system and consistent component patterns.
  </PrincipleCard>
  <PrincipleCard title="Flexible theming">
    Built from the ground up to support customizable color schemes and user personalization—capabilities needed to support the [Phase 3 admin redesign initiative](https://github.com/WordPress/gutenberg/issues/71196).
  </PrincipleCard>
  <PrincipleCard title="Modern distribution">
    Distributed as a versioned npm package following [semantic versioning](https://semver.org/), rather than being bundled as a WordPress script on the `window.wp` global.
  </PrincipleCard>
  <PrincipleCard title="Composable architecture">
    Components follow consistent patterns with proper composability, ref forwarding, and flexible rendering—avoiding the bloated abstractions that emerged from historical scope creep.
  </PrincipleCard>
</PrincipleCards>

For more context on the motivations and goals behind this work, see the [Design System: Support for admin redesign](https://github.com/WordPress/gutenberg/issues/71196) overview issue.

## Contributing

If a component, token, or guideline falls short of what you need, report it rather than working around it quietly. [Contributing to the Design System](?path=/docs/design-system-contributing--docs) covers how to report a shortcoming and how to fix it at the source. It applies to AI agents as much as to people.
