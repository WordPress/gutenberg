# Selecting local files

Use `FormFileUpload` from `@wordpress/components` to open the native file picker. Its `render` prop receives `openFileDialog`, so any control can open the picker, while the file input stays hidden. It also handles browser quirks, such as `accept="audio/*"` on iOS.

These patterns cover choosing files before a form uses them. Uploading, progress, and the Media Library belong to the screen that sends the files.

<Markdown>{ `
| Pattern | Use it when |
| --- | --- |
| [Drop area](#drop-area) | A form field takes one file, such as a cover image. |
| [Drop area for several files](#drop-area-for-several-files) | A form field collects a list of files, such as receipts and photos. |
| [Button](#button) | There is no room for a drop area, or dropping files would be unusual. |
| [Menu item](#menu-item) | Choosing a file is one of several actions, such as in a Replace menu. |
` }</Markdown>

## Drop area

Lay the field out like other form fields: the label, then the drop area, then the description. The whole drop area is a `Button` with `variant="unstyled"`, so a click, Enter, or Space opens the picker. Dropping a file is an extra way to choose one, not the only way.

<Canvas
	of={ FilePickerDropZoneStories.ChooseFile }
	source={ { code: FilePickerDropZoneSource, language: 'tsx', type: 'code' } }
/>

- **Place `DropZone` inside the drop area.** Its overlay covers the nearest positioned ancestor, so the drop area needs `position: relative`.
- **Send chosen and dropped files through one handler.** Both paths then follow the same rules. `accept` only filters the picker, and people can still choose or drop any file, so check every file in the handler.
- **Keep the last valid file when a new one is rejected.** Show the error below the description, in a live region, and link it to the button with `aria-describedby`.
- **Show what was chosen.** The drop area shows a thumbnail and the filename. Other files show a file icon in place of the thumbnail.
- **Say that dropping works.** The drop area names the action, such as "Add an image", and the description says a file can be dropped there. A dashed border alone doesn't tell people that.
- **Put the remove button beside the drop area, not inside it.** A button can't contain another button. Name it after the file, such as "Remove cover.png", and move focus back to the drop area after a removal.
- **Name the drop area after its action.** When it shows a file, its accessible name is "Replace cover.png".

A `Fieldset` groups the drop area and the remove button under one legend. Disable the fieldset to disable the button, the remove button, and the hidden input together. Remove the `DropZone` and stop a dropped file from opening in the browser tab.

## Drop area for several files

Set `multiple` on `FormFileUpload` and show each file in its own row, above the drop area. The drop target covers the rows as well, so a large area accepts files.

<Canvas
	of={ FilePickerMultipleStories.ChooseFiles }
	source={ { code: FilePickerMultipleSource, language: 'tsx', type: 'code' } }
/>

- **Keep the remove button visible in every row.** Don't show it only on hover. Each name includes the filename, so a list of "Remove" buttons can be told apart.
- **Move focus after a removal.** Focus the next row's remove button, or the drop area when the list is empty.
- **Add the valid files and list the rejected ones.** One wrong file shouldn't block the others.
- **Show the file type next to the name.** Long filenames are cut at the end, so the details line shows the type, and people can tell `report.pdf` from `report.png`.
- **Give each row its own key.** The same file can be chosen twice, so don't derive the key from the filename.

## Button

Use an outline, neutral `Button` when a drop area doesn't fit. Show the chosen file below the button with the same row as the drop area.

<Canvas
	of={ FilePickerButtonStories.ChooseFile }
	source={ { code: FilePickerButtonSource, language: 'tsx', type: 'code' } }
/>

End the label with an ellipsis, because the button opens another interface. Read the file from `event.currentTarget.files`, then clear the input, so choosing the same file again fires another change. When the picker closes without a selection, keep the previous file. Check the file type too: `accept` only filters the picker, so people can still choose a PDF here.

## Menu item

Wrap the whole menu in `FormFileUpload`, not only the item. The menu closes when the item is activated and unmounts its content, so an input inside the item would be gone before the selection arrives.

<Canvas
	of={ FilePickerMenuStories.ChooseFile }
	source={ { code: FilePickerMenuSource, language: 'tsx', type: 'code' } }
/>

After the menu closes, focus returns to the trigger. The chosen file appears beside the trigger, and `speak()` announces it. A remove action can live in the menu here, because the menu is already where the file's actions are.

## Checklist

- **Keep a click target.** Dropping files never replaces a button that people can reach with a keyboard or a single tap.
- **Check every file.** Validate type and count in the handler, for files from the picker and from a drop.
- **Clear the input after reading it.** Otherwise choosing the same file again does nothing.
- **Announce changes.** Use `speak()` when a file is added or removed, and put errors in a live region beside the field.
- **Keep the `File` for later.** If a separate button submits the form, keep the chosen `File` in state and pass it to the submit handler.
