# Copy to Clipboard

Choose feedback that remains visible after the action runs. A control that stays on the page can confirm the copy itself. When a menu closes, show the result near its trigger where practical, or use the screen's existing snackbar region.

## Standalone button

Put the confirmation on the button so it stays with the control that produced the result. Use `variant="minimal"`, `tone="neutral"`, and `size="compact"`: a copy action is rarely the primary button on the page. Don't use a snackbar here: the button is still visible. Don't use a tooltip: touch users and many keyboard users never see it.

The visible label and the accessible name stay "Copy". A check icon shows success, and an error icon shows failure, so the control is not renamed while it has focus. Copy with `useCopyToClipboard` from `@wordpress/compose`, and use its `onError` callback when the write fails. Call `speak()` with "Copied to clipboard", or "Couldn't copy to clipboard." if copying fails, to announce the outcome politely. Focus stays on the button.

For an icon-only control, use `IconButton` with the same variant, tone, and size, and keep `label="Copy"`. That label is the accessible name and the tooltip. Swap the icon for a check on success or an error icon on failure, and announce the result with `speak()`. The success and error messages belong in that announcement rather than only in the tooltip.

Copying is a one-time action. `aria-pressed` describes a toggle that stays on or off, so this button does not use it.

Restart the feedback timeout after each copy result, including repeated successes or failures, so the icon remains visible for the full duration after the latest attempt completes.

## Copying from a menu

When a copy action appears inside a menu, the menu typically closes immediately after the action is activated. Feedback on the menu item disappears with it, but feedback beside the menu trigger can remain visible. Prefer that local feedback when there is room for a clear message, and announce the result with `speak()` without changing the trigger's accessible name or moving focus.

When local feedback isn't practical, such as an icon-only trigger in a crowded toolbar, a snackbar is another option. Use the screen's existing snackbar region where available. Closing a menu alone isn't a reason to require a snackbar.

Consider the placement and timing concerns tracked in [Snackbar Accessibility Issues (#16549)](https://github.com/WordPress/gutenberg/issues/16549). A message far from the trigger can fall outside a person's magnified view, and an automatically dismissed message can disappear before they read or reach it. Keep feedback near the action where possible. If a message contains information or actions that aren't available elsewhere, provide a persistent alternative or a way to turn off, adjust, or extend the time limit, as described in [WCAG Timing Adjustable](https://www.w3.org/WAI/WCAG22/Understanding/timing-adjustable.html). A polite announcement doesn't remove these placement and timing concerns.

This example uses `useCopyToClipboard` for the write and `SnackbarList` for the message. ## Guidance

<Markdown>{ `
| Context | Recommended feedback | Rationale |
| --- | --- | --- |
| Standalone copy button | Temporary check or error icon; the label stays "Copy" | The control remains visible. The name stays the action, and the icon shows success or failure. |
| Copy action in a menu with room beside its trigger | Feedback beside the trigger, with a polite announcement | The message stays near the action after the menu closes. |
| Copy action in a menu without room for local feedback | The screen's existing snackbar region | The message survives the menu closing; assess its placement and timing. |
` }</Markdown>

- **Prefer local feedback when possible.** A snackbar shouldn't be the default for every copy operation.
- **Keep menu feedback visible after closing.** Prefer a message beside the trigger where practical; otherwise assess whether a snackbar is suitable.
- **Always announce the outcome accessibly.** Visual feedback alone isn't sufficient.
- **Avoid redundant feedback.** Don't show both inline confirmation and a snackbar for the same action unless there's a compelling reason.
