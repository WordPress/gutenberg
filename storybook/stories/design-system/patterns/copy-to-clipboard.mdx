# Copy to Clipboard

Choose the feedback from where the action remains after it runs. A control that stays on the page can confirm the copy itself. An action inside a menu cannot, because the menu closes.

## Standalone button

Put the confirmation on the button so it stays with the control that produced the result. Don't use a snackbar here: the button is still visible. Don't use a tooltip: touch users and many keyboard users never see it.

<Canvas of={ CopyToClipboardStories.CopyExample } />

The accessible name stays "Copy" while the visible label changes to "Copied". A changed name on the focused button is an unreliable announcement. Mount a `role="status"` region before the click, then fill it with "Copied to clipboard" or an error. The region announces the outcome politely and leaves focus on the button.

For an icon-only control, use `IconButton` and keep `label="Copy"`. That label is the accessible name and the tooltip. Swap the icon, and announce the result from the same status region. The success and error messages belong in that region rather than only in the tooltip.

Copying is a one-time action. `aria-pressed` describes a toggle that stays on or off, so this button does not use it.

## Copying from a menu

When a copy action appears inside a menu, the menu typically closes immediately after the action is activated. This means the inline feedback used by a standalone copy button isn't appropriate, because the user won't see the updated state.

In these situations, a temporary snackbar can provide useful visual confirmation that the action succeeded, without interrupting the user's workflow or requiring another interaction.

A snackbar isn't strictly necessary for accessibility. The essential requirement is that the outcome is communicated to assistive technology through an appropriate status announcement. However, because the originating control is no longer visible, a snackbar provides an equivalent confirmation for sighted users.

<Canvas of={ CopyFromMenuStories.CopyFromMenu } />

This example uses `SnackbarList` for that message. The list animates the snackbar in and out, and `Snackbar` announces "Link copied to clipboard", or "Couldn't copy link to clipboard." if copying fails, through its own polite live region. That region stays on the page after the menu closes, so the example does not add a second one. The item label stays "Copy link".

## Guidance

<Markdown>{ `
| Context | Recommended feedback | Rationale |
| --- | --- | --- |
| Standalone copy button | Temporary inline "Copied" state | The control remains visible, allowing feedback to appear directly at the point of interaction. |
| Copy action in a menu | Temporary snackbar | The menu closes after activation, so inline feedback would disappear before it could be perceived. |
` }</Markdown>

- **Prefer local feedback when possible.** A snackbar shouldn't be the default for every copy operation.
- **Use snackbars when the originating surface disappears.** This makes the feedback visible independently of the action's original location.
- **Always announce the outcome accessibly.** Visual feedback alone isn't sufficient.
- **Avoid redundant feedback.** Don't show both inline confirmation and a snackbar for the same action unless there's a compelling reason.
