# Copy to Clipboard

Choose feedback that remains visible after the action runs. A control that stays on the page can confirm the copy itself. When a menu closes, a snackbar can keep the confirmation visible.

## Standalone button

Put the confirmation on the button so it stays with the control that produced the result. Use `variant="minimal"`, `tone="neutral"`, and `size="compact"`: a copy action is rarely the primary button on the page. Don't use a snackbar here: the button is still visible. Don't use a tooltip: touch users and many keyboard users never see it.

/>

The visible label and the accessible name stay "Copy". A check icon shows success, and an error icon shows failure, so the control is not renamed while it has focus. Copy with `useCopyToClipboard` from `@wordpress/compose`, and use its `onError` callback when the write fails. Call `speak()` with "Copied to clipboard", or "Couldn't copy to clipboard." if copying fails, to announce the outcome politely. Focus stays on the button.

For an icon-only control, use `IconButton` with the same variant, tone, and size, and keep `label="Copy"`. That label is the accessible name and the tooltip. Swap the icon for a check on success or an error icon on failure, and announce the result with `speak()`. The success and error messages belong in that announcement rather than only in the tooltip.

Copying is a one-time action. `aria-pressed` describes a toggle that stays on or off, so this button does not use it.

Restart the feedback timeout after each copy result, including repeated successes or failures, so the icon remains visible for the full duration after the latest attempt completes.

## Copying from a menu

When a copy action appears inside a menu, the menu typically closes immediately after the action is activated. A snackbar can provide visual confirmation after the menu item disappears. Use the screen's existing snackbar region where available.

Consider the placement and timing concerns tracked in [Snackbar Accessibility Issues (#16549)](https://github.com/WordPress/gutenberg/issues/16549). A message far from the trigger can fall outside a person's magnified view, and an automatically dismissed message can disappear before they read or reach it. A polite announcement doesn't remove these concerns.

This example uses `useCopyToClipboard` for the write and `SnackbarList` for the message. The list animates the snackbar in and out, and `Snackbar` announces "Link copied to clipboard", or "Couldn't copy link to clipboard." if copying fails, through its own polite live region. That region stays on the page after the menu closes, so the example does not add a second one. The item label stays "Copy link".

The local `SnackbarList` and its positioning styles keep this preview self-contained. In a WordPress screen, use `core/notices` to create notices with `type: 'snackbar'` for the screen's existing snackbar region instead of adding a second list.

## Guidance

<Markdown>{ `
| Context | Recommended feedback | Rationale |
| --- | --- | --- |
| Standalone copy button | Temporary check or error icon; the label stays "Copy" | The control remains visible. The name stays the action, and the icon shows success or failure. |
| Copy action in a menu | The screen's existing snackbar region | The confirmation remains visible after the menu closes; assess its placement and timing. |
` }</Markdown>

- **Keep standalone feedback on the button.** A snackbar isn't needed when the button can show the result.
- **Keep menu feedback visible after closing.** Use the screen's existing snackbar region and assess its placement and timing.
- **Always announce the outcome accessibly.** Visual feedback alone isn't sufficient.
- **Avoid redundant feedback.** Don't show both inline confirmation and a snackbar for the same action unless there's a compelling reason.
