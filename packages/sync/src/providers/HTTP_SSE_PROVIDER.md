# HTTP SSE Provider

A Yjs provider that uses Server-Sent Events (SSE) for real-time document synchronization through a central server, instead of peer-to-peer WebRTC connections.

## Features

- **Server-mediated sync**: All updates go through a central WordPress server
- **SSE for real-time updates**: Uses EventSource API for efficient server-to-client streaming
- **Awareness protocol**: Full support for presence information (cursors, selections, etc.)
- **Automatic reconnection**: Handles connection drops with configurable retry logic
- **WordPress integration**: Uses REST API endpoints and wp_cache for state management

## Architecture

### Client-Side (TypeScript)

The `HttpSseProvider` class manages:
- Connection to the SSE endpoint via EventSource
- Sending document updates via POST requests
- Receiving updates from other clients via SSE stream
- Awareness state synchronization
- Automatic reconnection on connection loss

### Server-Side (PHP)

The `HttpSseRoomServer` class provides:
- REST API endpoints for SSE connections and message posting
- Room management using WordPress caching
- Message broadcasting to all clients in a room
- Hybrid approach: caches document state while relaying messages

## Usage

### Basic Setup

```typescript
import { createHttpSseProvider } from '@wordpress/sync';
import * as Y from 'yjs';

// Create a Yjs document
const doc = new Y.Doc();

// Create the provider
const providerCreator = createHttpSseProvider({
	endpoint: '/wp-json/sync/v1/rooms',
});

// Use the provider for a specific document
const provider = await providerCreator( 'post', '123', doc );

// Later, destroy the provider
provider.destroy();
```

### Using with the Sync Manager

```typescript
import { getProviderCreators } from '@wordpress/sync';
import { addFilter } from '@wordpress/hooks';

// Add the HTTP SSE provider to the default providers
addFilter(
	'sync.providers',
	'my-plugin/add-http-sse-provider',
	( providers ) => {
		return [
			...providers,
			createHttpSseProvider({
				endpoint: '/wp-json/sync/v1/rooms',
			}),
		];
	}
);
```

### Custom Configuration

```typescript
const provider = new HttpSseProvider( doc, {
	endpoint: '/wp-json/sync/v1/rooms',
	room: 'post:123',
	timeout: 30000, // Connection timeout in ms
	reconnectInterval: 5000, // Reconnection delay in ms
} );

// Listen to events
provider.on( 'status', ( event ) => {
	console.log( 'Provider status:', event.status );
} );

provider.on( 'synced', ( event ) => {
	console.log( 'Document synced:', event.synced );
} );
```

## Server-Side Setup

The PHP server component needs to be loaded in your WordPress plugin or theme:

```php
<?php
// In your plugin's main file
require_once __DIR__ . '/path/to/http-sse-room-server.php';
```

The server will automatically register the REST API endpoint at:
- `GET /wp-json/sync/v1/rooms/{room}` - SSE connection endpoint
- `POST /wp-json/sync/v1/rooms/{room}` - Message posting endpoint

### Required Parameters

- `room`: Room identifier (e.g., "post:123")
- `client_id`: Unique client identifier (automatically generated by the provider)

### Caching

The server uses WordPress object cache with these keys:
- `sync_room_clients_{room}`: Active clients in a room
- `sync_room_messages_{room}`: Recent messages in a room
- `sync_room_state_{room}`: Current document state (hybrid approach)

For production use, configure a persistent object cache (Redis, Memcached, etc.) for better performance.

## Message Flow

1. **Initial Connection**:
   - Client opens SSE connection to GET endpoint
   - Server registers client in room
   - Client sends sync step 1 (state vector)

2. **Document Updates**:
   - Client A makes a change
   - Provider sends update to POST endpoint
   - Server stores message in cache
   - Server broadcasts to all connected clients via SSE
   - Other clients apply the update

3. **Awareness Updates**:
   - Client moves cursor or changes selection
   - Provider sends awareness update
   - Server broadcasts to other clients
   - Clients update collaborator indicators

## Comparison with WebRTC Provider

| Feature | HTTP SSE Provider | WebRTC Provider |
|---------|-------------------|-----------------|
| Architecture | Client-Server | Peer-to-Peer |
| Scalability | Limited by server | Better for many peers |
| Latency | Higher (server hop) | Lower (direct) |
| NAT/Firewall | Works everywhere | May have issues |
| Server Load | High | Low (just signaling) |
| State Management | Server can persist | Client-only |

## Permissions

By default, only logged-in users can access the sync endpoints. Customize permissions in the PHP file:

```php
public static function check_permissions() {
	// Custom permission check
	return current_user_can( 'edit_posts' );
}
```

## Security Considerations

1. **Authentication**: Endpoint requires logged-in users
2. **Authorization**: Verify users can access specific rooms/documents
3. **Rate Limiting**: Consider adding rate limits to prevent abuse
4. **Input Validation**: All inputs are sanitized
5. **XSS Prevention**: Messages are JSON-encoded

## Performance Tips

1. **Use persistent object cache**: Redis or Memcached for better performance
2. **Adjust cache expiration**: Balance between memory usage and sync reliability
3. **Limit message history**: Configure `MAX_MESSAGES_PER_ROOM` based on your needs
4. **Monitor server resources**: SSE connections are persistent
5. **Consider connection pooling**: For high-traffic scenarios

## Troubleshooting

### Connection keeps dropping

- Check server timeout configuration
- Verify object cache is working
- Check for proxy/CDN interference with SSE

### Messages not received

- Verify cache is persistent (not object cache disabled)
- Check client_id is unique and consistent
- Look for PHP errors in server logs

### High server load

- Enable persistent object cache
- Reduce `MESSAGE_CACHE_EXPIRATION`
- Limit concurrent connections per room
- Consider load balancing
