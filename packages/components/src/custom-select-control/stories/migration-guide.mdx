# CustomSelectControl migration guide

Migrate the legacy [`CustomSelectControl`](?path=/docs/components-customselectcontrol--docs) from `@wordpress/components` to [`SelectControl`](?path=/docs/design-system-components-form-selectcontrol--docs) from `@wordpress/ui`. Prefer the complete control for standard labels and descriptions, including custom triggers and popup items. Use [`Select`](?path=/docs/design-system-components-form-primitives-select--docs) primitives when you need a custom field layout, a small trigger, or item values outside the wrapper's string-or-null shape.

## Convert options and callbacks

Rename `key` to `value`, `name` to `label`, and `hint` (or `__experimentalHint`) to `description`. The controlled value is still an item object. `onValueChange` receives that item, or `null`, as its first argument and event details as its second argument. Remove the legacy `selectedItem` destructuring. The old change object's `highlightedIndex`, `inputValue`, `isOpen`, and `type` fields have no equivalent callback payload. Use `onOpenChange` separately if you track the popup state.

Before:

```jsx
import { useState } from 'react';
import { CustomSelectControl } from '@wordpress/components';

const options = [
	{ key: 'thumbnail', name: 'Thumbnail', hint: '150 × 150' },
	{ key: 'medium', name: 'Medium', hint: '300 × 300' },
	{ key: 'full', name: 'Full size', hint: 'Original dimensions' },
];

function ImageSize() {
	const [ imageSize, setImageSize ] = useState( 'medium' );

	return (
		<CustomSelectControl
			label="Image size"
			options={ options }
			value={ options.find( ( option ) => option.key === imageSize ) }
			onChange={ ( { selectedItem } ) => setImageSize( selectedItem.key ) }
		/>
	);
}
```

The legacy README mentions `__unstable-large`, but the current legacy type supports only `default` and `small`. Do not carry `__unstable-large` into the new control. `compact` is a supported new size, not an automatic equivalent of legacy `small`.

## Resolve the selection

Legacy `CustomSelectControl` chooses the first option when `value` is omitted, without calling `onChange` on mount. An unavailable key displays the first option as a fallback. Do not apply assumptions about the native `SelectControl` to this component. Preserve the intended selection explicitly in your migration.

The new control starts with no selection unless you supply `value` or `defaultValue`. To preserve the initial first choice in an uncontrolled control, use `defaultValue={ items[ 0 ] ?? null }`. For a controlled field, initialize the stored value deliberately and resolve it against the current items on each render.

Legacy selection matching uses the option's key and its callback returns the original option object. New object values use reference equality by default. Use the same object from the current `items` array for `value` and custom `Item` values. When you retain an object across item refreshes, supply `isItemEqualToValue={ ( item, value ) => item.value === value.value }` or resolve the stored identifier against the refreshed items instead. Rebuilding the array is safe when you also resolve the selected object from that array, as in the example above.

A failed lookup must not become `undefined` in a controlled field. Choose a policy: `items.find( matchesStoredValue ) ?? null` displays the placeholder, while `items.find( matchesStoredValue ) ?? items[ 0 ] ?? null` deliberately preserves the legacy display fallback. These lookup expressions only choose the displayed selection. A change handler may still receive `null` when choices are removed, so decide whether that should clear application state. If an unavailable stored value must be cleared or replaced, update application state explicitly, or add a labeled item representing that value.

Handle `items={ [] }`, including an explicitly supplied empty custom-options array. Do not replace that array with defaults just because it is empty. Resolve the selection to `null` and guard it before accessing `.label` or `.description`. Disable the control or omit it when there are no choices, according to your interface's needs. The selected-hint example below lets you try an empty custom list while preserving the stored font. Its popup has no clearing action, so its change handler ignores `null` callbacks. In a field that offers clearing, handle that action explicitly instead.

## Customize the trigger

Use `trigger={ <SelectControl.Trigger … /> }` for focus and mouse handlers, button attributes, a trigger class, or selected-value content. Props on that trigger override the wrapper's `size` and `placeholder`. Event handlers on the trigger do not require primitives. The final PresetInputControl migration uses this slot for focus and hover handlers.

Trigger children customize only the selected display. They can be static content or a function receiving the selected item. Guard nullable selections before reading a label. When no selection exists, leave children `undefined` to retain the normal placeholder. Popup item content is configured separately with the control's children.

## Style popup items

For plain hints, set `description` on each item and let `SelectControl` render the standard popup. For custom styling, pass `SelectControl.Item` children, with each `value` referencing its corresponding object in `items`. Put a class or style affecting the entire row on `Item`. Put font previews or other label-only styling on `ItemLabel`, so the hint and selection indicator remain unaffected.

Make `ItemLabel` the first direct child of every `Item`, followed by zero or more direct `ItemDescription` children. Use `ItemDescription` for supplementary text or non-interactive inline markup. Keep the primary label separate from the description. Supply a plain string `label` prop on custom items for typeahead, particularly when the visible label contains markup. The trigger label still comes from the selected item's `label` or custom trigger children, not the popup JSX.

The selected-hint example combines custom popup styling with a separate trigger display. For other compositions, reuse the existing [grouped](?path=/story/design-system-components-form-selectcontrol--grouped) and [custom-item](?path=/story/design-system-components-form-selectcontrol--with-custom-items) examples.

## Preserve selected hints

Legacy `showSelectedHint` adds the selected option's hint to the trigger. Its `describedBy` prop contains text, with a generated "Currently selected: …" description when no text is provided. The new control does not generate that legacy description or copy an item's description into the trigger.

FontFamilyControl preserves its selected hint by rendering it beside the selected label with `aria-hidden="true"`, then combining the hint and `describedBy` text in a visually hidden `Field.Description`. With the public wrapper, render that text in `VisuallyHidden` with a unique ID and pass the ID through `SelectControl.Trigger`'s `aria-describedby`. The wrapper's `description` prop accepts plain text and displays it below the field. Use primitives if you need to customize `Field.Description` itself. Keep the selected label visible, hide the duplicate visual hint from the accessibility tree, and include the hint in the associated description. If the hint should also be visible below the control, pass plain description text instead.

These are description associations visible in the source and rendered markup. They do not establish the words or order spoken by a screen reader. Verify your consumer with its supported assistive technology when preserving announcements matters.

## Separate clearing from empty strings

Use `null` for no selection. An item with `value: null` offers a clearing action in the popup, and its label takes precedence over the `placeholder`. A placeholder is display text when no value is selected, not a selectable item. Reuse the existing clearing example:

<Canvas of={ SelectControlStories.WithNullValueOption } />

An empty string can instead be a real application choice, such as "Use theme font". Do not convert every empty key to `null`, and do not use `item?.value || fallback`, which loses that choice. Use nullish checks such as `item?.value ?? null`.

By default, empty-string item values are treated as empty selections. To preserve a real `''` choice, provide `itemToStringValue` that returns a unique, nonempty string for that item and every ordinary choice. The example below prefixes ordinary values with `font:` and leaves the clearing item serialized as an empty string. Choose "Use theme font" and submit: the stored value remains `""`, while the submitted value is `"font:"`. Clear the selection and try submitting again: the required field prevents submission.

<Canvas of={ MigrationStories.EmptyStringChoice } sourceState="shown" />

Serialization changes `FormData` and required-field behavior. A nonempty serialization makes the real empty-string choice satisfy `required`, and the form submits that serialized value. The callback still receives the original item with `value: ''`. Adjust the form consumer to decode the submitted value, or adapt submission yourself if your application requires a different payload.

Mapping application values to nonempty identifiers and converting them in callbacks can also represent special choices. For example, PresetInputControl maps numeric indexes to strings for the wrapper. This is not a `FormData` compatibility fix: the form submits those identifiers unless you explicitly adapt submission.

## Keep labels and disabled state

Retain a meaningful `label` even with `hideLabelFromVision`. Use [`Field`](?path=/docs/design-system-components-form-primitives-field--docs) and `Select` primitives for a custom label element or field layout. Preserve inherited-value label styling on your own label class when a consumer needs it, as the migrated font controls do.

Use `disabled` on `SelectControl` to disable the selection, or `disabled: true` on an item to disable just that choice. Legacy `CustomSelectControl` has no declared `disabled` prop, so inspect any consumer wrapper that previously forwarded one rather than copying all its props to the new root. In a primitive composition, pass `disabled` to `Field.Root` and `Select.Root` so both the field presentation and selection behavior reflect it.

Use `Select.Trigger size="small"` only when the consumer requires that size. FontFamilyControl and FontAppearanceControl retain primitives for their small size and custom field-label styling.
