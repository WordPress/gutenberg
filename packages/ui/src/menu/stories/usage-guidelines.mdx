# Menu usage guidelines

Choose between Menu, Select, and Autocomplete based on what the options represent and whether users need to search them.

> If the trigger represents a current value and opens choices for replacing that value, use Select. If the trigger opens commands, actions, or navigation destinations, use Menu. If users need to type to filter a menu-like list of commands or suggestions, use Autocomplete.

## Quick reference

<Markdown>{ `
| Goal | Component | Expected behavior |
| --- | --- | --- |
| Choose one predefined value | [SelectControl](?path=/docs/design-system-components-form-selectcontrol--docs) | The trigger represents the current value. Choosing an option replaces it. |
| Build a custom value-selection control | [Select](?path=/docs/design-system-components-form-primitives-select--docs) | The primitives provide a custom composition while preserving Select semantics. |
| Offer commands, actions, or destinations | [Menu](?path=/docs/design-system-components-menu--docs) | Activating an item runs a command, opens a submenu, or navigates to a destination. |
| Search commands or suggestions with free-form input | [Autocomplete](?path=/docs/design-system-components-form-primitives-autocomplete--docs) | Typing filters the suggestions while focus remains in the input. |
| Change settings within a broader command menu | [Menu](?path=/docs/design-system-components-menu--docs) | Checkbox items toggle independent states. Radio items choose one state within a group. |
` }</Markdown>

## Use `SelectControl` to choose a value

Use [SelectControl](?path=/docs/design-system-components-form-selectcontrol--docs) when choosing one predefined value is the control's primary purpose. The selected value is often submitted as part of a form, but form submission does not define Select semantics.

The trigger should represent the current value. The popup options should represent the available replacement values, not commands or navigation destinations.

Use the lower-level [Select](?path=/docs/design-system-components-form-primitives-select--docs) primitives only when a custom composition cannot be expressed with `SelectControl`.

## Use `Menu` for commands and destinations

Use `Menu.Item` for commands or actions. Use `Menu.LinkItem` for navigation destinations. Activating a regular item usually performs its command and closes the menu.

<Canvas of={ UsageGuidelinesStories.MenuForCommands } />

## Use `Autocomplete` when users need to search

Use [Autocomplete](?path=/docs/design-system-components-form-primitives-autocomplete--docs) for a menu-like list of commands or suggestions that users filter by typing. Unlike `Menu`, focus remains in a text input while users navigate the suggestions.

Autocomplete accepts free-form text. If the control must contain one predefined value, use `SelectControl` or the lower-level `Select` primitives instead.

## Use checked items for settings within a menu

Use `Menu.CheckboxItem` for independent states, such as showing or hiding individual table columns.

Use `Menu.RadioItem` within `Menu.RadioGroup` for mutually exclusive states, such as choosing one density or view mode within a broader command menu.

`Menu.RadioGroup` already provides grouping. Put `Menu.GroupLabel` inside it to label the radio group. Do not wrap it in `Menu.Group` or put `Menu.Group` inside it. This also applies to combining the two components with the `render` prop. A label in an outer group does not label the inner group. Development builds throw an error for either nesting direction, including through wrapper components.

```tsx
<Menu.RadioGroup defaultValue="compact">
	<Menu.GroupLabel>Density</Menu.GroupLabel>
	<Menu.RadioItem value="compact">
		<Menu.ItemLabel>Compact</Menu.ItemLabel>
	</Menu.RadioItem>
	<Menu.RadioItem value="comfortable">
		<Menu.ItemLabel>Comfortable</Menu.ItemLabel>
	</Menu.RadioItem>
</Menu.RadioGroup>
```

Use `Menu.Group` for related commands, links, or checkbox items. `Menu.Group` and `Menu.RadioGroup` can be siblings in the same popup. Each submenu has its own groups.

Keep prefix icon usage consistent within each group. Use icons on every item in the group, or omit them from the whole group. Different groups can make different choices. See [Add prefix icons](#add-prefix-icons) for alignment details and an example.

<Canvas of={ UsageGuidelinesStories.CheckedOptionsWithinACommandMenu } />

Do not use checked menu items only to recreate a Select. If choosing a value is the whole purpose of the control, use `SelectControl`, even when the options could look like radio menu items.

## Disable the trigger or individual items

Set `disabled` on `Menu.Trigger` when the menu cannot be opened, such as when no actions are available. Set `disabled` on individual items when their actions are unavailable. Disabling the trigger does not disable items in an already open menu.

Disabling only the trigger lets users dismiss a menu that was open when the trigger became disabled. For submenus, set `disabled` on `Menu.SubmenuTrigger`. Neither `Menu.Root` nor `Menu.SubmenuRoot` supports `disabled`.

When rendering an `@wordpress/components` `Button`, keep `accessibleWhenDisabled` on the button if it should remain focusable. Put `disabled` on `Menu.Trigger`, which passes it to the rendered button and prevents the menu from opening with the keyboard or pointer.

```tsx
import { Button } from '@wordpress/components';
import { Menu } from '@wordpress/ui';

<Menu.Root>
	<Menu.Trigger
		disabled={ isUnavailable }
		render={ <Button accessibleWhenDisabled /> }
	>
		Actions
	</Menu.Trigger>
	<Menu.Popup>
		<Menu.Item disabled={ isUnavailable } onClick={ duplicate }>
			<Menu.ItemLabel>Duplicate</Menu.ItemLabel>
		</Menu.Item>
	</Menu.Popup>
</Menu.Root>;
```

## Add prefix icons

Use prefix icons when familiar symbols help users recognize and find actions, such as Copy or Print. Choose icons that match the labels and have a clear meaning in context. Omit icons when the labels are already easy to scan or no clear icon exists. Do not add icons only for decoration or to draw attention to a single item.

> Use prefix icons on every item in a group, or omit them from the whole group. If only one item would benefit from an icon, prefer omitting it rather than adding unnecessary icons to the other items.

Item labels align within the same group. When any item has a prefix icon, the group reserves an icon column for all its items. Items without icons keep their labels aligned, but have empty space before them. A group with only one or a few icons can look visually unbalanced.

Each `Menu.Group` and `Menu.RadioGroup` has its own icon column, so one group can have icons while another has none. Items directly inside `Menu.Popup` share an icon column, even when separated by `Menu.Separator`. Apply the same guidance within each submenu. Checkbox and radio selection indicators are separate from prefix icons; they do not count toward this recommendation.

Use `Menu.PrefixIcon` in an item's `prefix` prop for an SVG icon. It defaults to 16px and centers on a single label line at the top of the item's content row. Prefer the default size for consistent menu icons.

```tsx
import { archive, copy } from '@wordpress/icons';
import { Menu } from '@wordpress/ui';

<Menu.Group>
	<Menu.Item prefix={ <Menu.PrefixIcon icon={ copy } /> }>
		<Menu.ItemLabel>Duplicate</Menu.ItemLabel>
	</Menu.Item>
	<Menu.Item prefix={ <Menu.PrefixIcon icon={ archive } /> }>
		<Menu.ItemLabel>Archive</Menu.ItemLabel>
	</Menu.Item>
</Menu.Group>;
```

In the following example, every item in the Actions group has an icon, while the Navigation group has none. Labels align within each group.

<Canvas of={ UsageGuidelinesStories.ConsistentPrefixIconsWithinGroups } />

The prefix slot already hides its contents from assistive technology. Keep the action clear in `Menu.ItemLabel`; do not rely on the icon to convey its meaning.

Other non-interactive React content can still be passed directly to `prefix`. It retains its natural height and starts at the top of the item. `Menu.PrefixIcon` does not change the sizing of other prefix content.

## Keep labels clear and descriptions rare

Write short, clear item labels that users can understand on their own. Most items should not need a description. Improve an unclear label before adding supporting text.

Use `Menu.ItemDescription` only when an item needs essential context that the label cannot convey concisely, such as a consequence users need to know before choosing it. Keep descriptions brief and limit them to the few items that need them. Do not repeat the label or describe an obvious action.

Avoid combining a prefix icon and a description in the same item. Both add visual detail and can make the menu harder to scan. Prefer a clear label with only the supporting element the item needs.

```tsx
<Menu.Group>
	<Menu.Item>
		<Menu.ItemLabel>Rename…</Menu.ItemLabel>
	</Menu.Item>
	<Menu.Item>
		<Menu.ItemLabel>Duplicate</Menu.ItemLabel>
	</Menu.Item>
	<Menu.Item>
		<Menu.ItemLabel>Delete…</Menu.ItemLabel>
		<Menu.ItemDescription>
			Also deletes all versions of this item.
		</Menu.ItemDescription>
	</Menu.Item>
</Menu.Group>;
```

## Use an ellipsis for actions that need more input

Append an ellipsis (`…`) when activating an item opens another interface that requires more user input before the command can finish, such as a dialog.

-   Use **Rename…** when activation opens a dialog where the user enters a new name.
-   Use **Delete…** when activation opens a confirmation dialog that requires a decision.
-   Use **Preferences** without an ellipsis when activation completes the command by opening the preferences interface.
-   Use **Duplicate** when activation completes the command immediately.
-   Use **Move to** without an ellipsis when the item opens a submenu.

The consumer must add the ellipsis because `Menu.Item` cannot infer what happens after activation. See the [WAI-ARIA APG Menu and Menubar Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/) and the [WordPress ellipsis guidance](https://github.com/WordPress/gutenberg/issues/64555#issuecomment-5244971187).

## Common mistakes

-   **Using Menu to choose the control's only value.** Use `SelectControl` so the trigger and options communicate value selection.
-   **Putting commands or links in Select.** Use `Menu.Item` for commands and `Menu.LinkItem` for destinations.
-   **Using Menu for a large set of searchable commands.** Use `Autocomplete` when users need to filter commands or suggestions by typing.
-   **Using radio items to recreate a Select.** Use `Menu.RadioItem` only when the state belongs inside a broader command menu.
-   **Adding a prefix icon to only one or a few items in a group.** The icon column leaves empty space beside the other items. Omit icons from the whole group when clear, useful icons are not available for every item.
-   **Combining a prefix icon and a description in the same item.** Prefer a clear label with only the supporting element the item needs.
-   **Adding descriptions to most or all items.** Write labels that stand on their own. Reserve descriptions for essential context on a few items.
-   **Adding an ellipsis to every item that opens another interface.** Reserve it for commands that require more input before completion. Do not add it when opening the interface completes the command, as with **Preferences**.
