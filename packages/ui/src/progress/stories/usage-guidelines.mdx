# Progress usage guidelines

## When to use Progress

Use `Progress` to show how much of a task has completed, such as uploading files, exporting data, or installing an update. Keep the indicator close to the task it describes.

Use [Meter](?path=/docs/design-system-components-meter-usage-guidelines--docs) for a measurement within a known range, such as storage usage or battery charge. A meter describes a quantity rather than task completion. See the [WAI-ARIA meter pattern](https://www.w3.org/WAI/ARIA/apg/patterns/meter/).

## Label the task

Use `Progress.Label` to describe the task. If you omit the visible label, give `Progress.Root` an accessible name through `aria-label` or `aria-labelledby`.

Place `Progress.Indicator` inside `Progress.Track`. Keep `Progress.Label` and `Progress.Value` outside Track so its clipping does not hide the text. Use `Stack` to arrange the label and value together.

## Choose a progress value

Pass a numeric `value` when the amount of completed work is known. The default range is 0 to 100. Use `min` and `max` for tasks with different units.

Pass `value={ null }` when the amount of completed work is unknown. Indeterminate progress shows activity without suggesting a completion percentage.

## Set the width for the layout

`Progress.Root` has a default width of 160px, and `Progress.Track` fills that width. Override the width on Root with `className` or `style` when the layout needs a different size. For example, use `style={ { width: '100%' } }` to fill the container.

## Migrate from ProgressBar

Replace `ProgressBar` from `@wordpress/components` with `Progress.Root`, `Progress.Track`, and `Progress.Indicator` from `@wordpress/ui`. Root requires a `value`. For indeterminate progress, pass `value={ null }` explicitly; ProgressBar allowed its value to be omitted.

Give each task an accessible name with `Progress.Label`, `aria-label`, or `aria-labelledby`. Progress does not supply the generic loading label that ProgressBar used. Both components have a default width of 160px:

```jsx
import { Progress } from '@wordpress/ui';
import { __ } from '@wordpress/i18n';

<Progress.Root value={ null } aria-label={ __( 'Uploading files' ) }>
	<Progress.Track>
		<Progress.Indicator />
	</Progress.Track>
</Progress.Root>;
```

Pass numeric values to Root for determinate progress. If an existing value can be `undefined`, convert it to `null` with `value={ value ?? null }`. Move any track styling to `Progress.Track`; `className` on Root styles the container. A ref on Root points to that container, a `div` by default, rather than ProgressBar's native `progress` element.

## Format values for the task

`Progress.Value` displays a percentage by default. Use `format` and `locale` to change number formatting. For task-specific text, provide a child function to Value and use `getAriaValueText` on Root to give assistive technology the same information. Check whether the numeric value is `null` before displaying a completion amount.

## Customize the indicator color

The indicator uses a neutral color by default. Its optional `color` prop accepts CSS colors, including CSS variables. Use `currentColor` to inherit the surrounding text color. Only the indicator changes color.
