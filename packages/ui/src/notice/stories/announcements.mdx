# Notice announcements

Use a standalone `Notice.Root` for information that's already on the page, such as a site's privacy setting. Screen reader users can read it as they navigate. Use `Notice.List` when someone needs to hear about a change, such as the result of saving a draft.

<Canvas of={ AnnouncementStories.StaticNotice } />

## Announce new or updated notices

Keep `Notice.List` mounted, even when it's empty. Notices already in the list when it mounts stay silent. After that, adding a notice or changing its message announces it without moving focus.

Give each notice a stable key. Keep the key when updating that notice. Use a new key for a new notification, even if it repeats an earlier message.

<Canvas of={ NoticeStories.DynamicNotices } />

### Choose the message

By default, the list announces the visible text of `Notice.Title` and `Notice.Description`, preserving paragraph and line breaks and leaving out action labels. Set `spokenMessage` on `Notice.Root` when a shorter message would be clearer, such as “Save failed. Check your connection and try again.”

<Canvas of={ AnnouncementStories.FormattedMessage } />

### Choose the urgency

Announcements are polite by default, including errors. A successful save can wait until the screen reader finishes speaking. Set `politeness="assertive"` on `Notice.Root` for a time-sensitive message, such as a failed save that needs attention before the user leaves the page.

If your app moves focus to the notice so the user can read it immediately, set `politeness="off"` on that notice to avoid a second announcement.

### Announce while a dialog is open

If a background update needs to reach someone using a dialog, pass the app's document body to `liveRegionContainer` on `Notice.List`. Set `spokenMessage` on the notice so it can be announced while the dialog hides the rest of the app from screen readers.

## Announce an application event

If your app uses a standalone notice and needs to announce each save attempt, call `speak()` from the handler that receives the result. If a list already announces the result, a separate call to `speak()` would repeat it. See the [`@wordpress/a11y` API](https://github.com/WordPress/gutenberg/tree/HEAD/packages/a11y#api).

For an urgent failure, **Save changes** shows the error and calls `speak( message, 'assertive' )`.
