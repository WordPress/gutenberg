# Notice announcements

`Notice` does not announce its content automatically. Its `intent` controls appearance, not live-region behavior. Choose whether to announce a message based on what happened in the application.

## Static information

Leave static notices without a live-region role. Users can read the message and reach its actions through normal navigation.

<Canvas of={ AnnouncementStories.StaticNotice } />

## Urgent errors

For an important error that appears while the user works, put `role="alert"` on `Notice.Description`. Keep action buttons, links, and dismiss controls outside that element so their labels do not become part of the announcement. Keep keyboard focus where it is.

Select **Save changes** to simulate a failed save. **Try again** clears the simulated error.

<Canvas of={ AnnouncementStories.UrgentError } />

## Non-urgent updates

Use `role="status"` for a non-urgent update such as a completed save. Keep the status element mounted before updating its text to improve announcement reliability across browsers and screen readers.

Select **Save draft** to update the message. The action label changes to **Undo** outside the status region.

<Canvas of={ AnnouncementStories.PoliteStatus } />

## Migrating existing notices

Remove `spokenMessage` and `politeness` from `Notice.Root`. These props are no longer supported.

-   If the notice is static, no replacement is needed.
-   If it needs an announcement, apply `role="alert"` or `role="status"` to the message, as shown above. Do not put the role on a root that also contains actions.
-   If the previous `spokenMessage` differed from the visible text, manage a separate live region with that message in the consumer. Do not also announce the visible description, or users may hear both messages.

This change applies to `@wordpress/ui` `Notice`. The `@wordpress/components` `Notice` API is unchanged.

Test dynamic announcements with the browsers and screen readers your application supports. DOM tests can check the live-region content and roles, but cannot verify speech output.

See the [WAI-ARIA alert pattern](https://www.w3.org/WAI/ARIA/apg/patterns/alert/) and the [WAI-ARIA status role](https://www.w3.org/TR/wai-aria-1.2/#status).
