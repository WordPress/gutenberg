# Breadcrumb usage guidelines

Use Breadcrumb to show a hierarchical path to the current page or selected item. Every ancestor must belong to that hierarchy. Commands such as Delete and Duplicate belong in a separate menu.

## Page navigation

Use `LinkItem` ancestors with meaningful destinations followed by exactly one `CurrentItem`. The root is a named navigation landmark containing an ordered list, and the non-activatable current item defaults to `aria-current="page"`. This follows the [APG breadcrumb pattern](https://www.w3.org/WAI/ARIA/apg/patterns/breadcrumb/).

## Hierarchy selection

Use `ButtonItem` ancestors followed by exactly one `CurrentItem` when ancestors select or activate a position in the hierarchy. For example, a block editor trail can show Document, Group, and Paragraph. Group selects the ancestor block; Document clears selection. Breadcrumb owns ordering, overflow, tooltips, and responsive focus handling. The consumer owns selection state and intentional focus moves into the editor.

The root is a named group containing an ordered list. Visible ancestors are native buttons with `type="button"`; collapsed ancestors are menu actions. The current item is non-activatable and defaults to `aria-current="true"`. This selection variant extends beyond the APG breadcrumb pattern, which describes links to ancestor pages.

<Canvas of={ BreadcrumbStories.HierarchySelection } />

Use `onClick` to activate an ancestor. Breadcrumb forwards refs and event handlers to an `HTMLButtonElement` in the visible trail and an `HTMLDivElement` in the overflow menu. Type refs and event `currentTarget` for both targets. A custom `render` must support both button and menu-item composition. Measurement copies receive neither public refs nor event handlers.

Activating an overflow action closes the menu. If selection removes the focused item or the overflow trigger, Breadcrumb focuses the current item when focus would otherwise fall back to the document body. A consumer focus move into the editor takes precedence. A focused ancestor stays visible during resize where space permits; if it no longer fits, focus moves to the overflow trigger.

## Current-only trails

A single `CurrentItem` is supported, including truncation when its label does not fit. Root infers its semantics from the complete ancestor collection. With no ancestors, it defaults to a navigation landmark on both the server and client. Removing the final button ancestor therefore changes the root from a group to a navigation landmark.

Use `aria-current` on `CurrentItem` to override its inferred value. For example, `<Breadcrumb.CurrentItem aria-current="true">Document</Breadcrumb.CurrentItem>` keeps an in-document current marker even when the trail becomes current-only. This changes the current marker, not the root role. The prop takes precedence over a custom `render` element and is omitted from hidden measurement copies.

## Supported collections

All ancestors must be links or all must be buttons. Mixed link/button collections produce a development validation error. Keep one final `CurrentItem`, use non-empty text labels, and give items generated from arrays stable React keys. The internal overflow trigger does not change the trail's variant.

A truncated current label remains accessible from the keyboard through its tooltip. It does not become an activation control.
