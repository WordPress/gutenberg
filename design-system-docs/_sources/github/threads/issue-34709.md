# Issue #34709: Components: refining `ItemGroup`

## Body

_This is an overview issue to track all of the tasks necessary to refine the `ItemGroup` component in the context of integrating with the new design and primitives._

## `ItemGroup` and `Item`

- [x] #35152
- [ ] Consider the best way to associate a `Heading` to `ItemGrop` (and to link it in a semantic way as the title of the group)
- [ ] Consider using the `@wordpress/components` `Button` element instead of vanilla HTML `button`
- [ ] Consider reworking how separators and borders are applied (at the CSS rule level too), as it currently assumes a rigid DOM structure (see https://github.com/WordPress/gutenberg/pull/37067#discussion_r761807702)
- [ ] Add tooltip support for `Item` (how would that work with screen readers? e.g. consider making sure that the `Item`'s computed "aria-label` is the same text used in the tooltip)
- [ ] #36653
- [ ] Improving the component's flexibility, especially around how it currently expects `Item` to be a direct child of `ItemGroup` (examples of where that fell short: https://github.com/WordPress/gutenberg/pull/37067#discussion_r761807702 , https://github.com/WordPress/gutenberg/pull/37546#discussion_r784263364)
- [ ] Clean up semantics (use `ul` / `li`) ([comment](https://github.com/WordPress/gutenberg/pull/40588#discussion_r857575916))

## Integration with other components

- [ ] Explore all text-related components, and see how they behave when inside an `Item`
  - [ ] For example, text inside `Truncate` changes color when hovered/focused, while text inside `Text` doesn't
- [ ] Find potential patterns and "sinergies" that may benefit from the Context System, so that the UI looks great "auto-magically" when using `ItemGroup` in combination with other components
- [ ] #35210
