## Body

## What?

Rename the `color.bg` prop of the `ThemeProvider` component in `@wordpress/theme` to `color.background`.

## Why?

Consistency, readability.

`background` is more explicit and readable than the abbreviated `bg`, and it reads more naturally alongside the sibling `color.primary` prop.

## How?

Renames the prop in the component's types and resolution logic, and updates every place it is referenced: docs, README, Storybook, and all in-repo consumers (`@wordpress/admin-ui`, `@wordpress/boot`, `@wordpress/ui`, and `@wordpress/edit-site`).

This is a breaking change, documented in the `@wordpress/theme` CHANGELOG.

## Testing Instructions

1. Run the `@wordpress/theme` and `@wordpress/admin-ui` unit tests.
2. In Storybook, open the `ThemeProvider` "Nesting And Inheriting" story and confirm the background colors still apply correctly.
3. Confirm there are no remaining references to the `color.bg` prop in the repo.

### ciampo on 2026-06-09T11:29:44Z

URL: https://github.com/WordPress/gutenberg/pull/79007#issuecomment-4659277053

> It does leave me wondering about being fully consistent here though. For example in token names, component variables, etc. We already have a bit of a mix, and these changes make that more pronounced:

Good observation.

This PR proposes renaming `bg` to `background` for clarity and consistency with the non-shortened "primary", specifically in the context of `ThemeProvider`. But I see why it may be seen as a departure from the `bg` naming scheme used in the DS tokens.

The main reason for using `bg` (and `fg`) is for shortening the token names (a need that doesn't really apply to `ThemeProvider`'s props), therefore, in that sense, I think it could be ok to keep `bg` and `fg` for the token names. Although I recognize that we have some inconsistencies there, too — for example, `surface` is not abbreviated.

@jameskoster @mirka  do you have an opinion on this matter?

### jameskoster on 2026-06-09T14:02:49Z

Not a strong opinion, but on reflection I'm not sure how much value we really get from abbreviating bg and fg in token names. Yes, the names are a bit shorter, but some of them are still very long e.g. `--wpds-color-bg-interactive-neutral-strong-disabled`. Like you said, it's not really clear _why_ these are the only abbreviations.
