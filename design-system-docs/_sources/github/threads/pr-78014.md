## Body

## What?

Closes WordPress/gutenberg#78005

`date-fns` was declared at `^3.6.0` in `packages/components`, `packages/dataviews`, and `packages/dependency-extraction-webpack-plugin`, while `packages/editor` was already on `^4.1.0`. This PR lifts all v3 declarations to v4 and patches the call-sites that break under tests.

## Why?

In `date-fns` v4, `toDate()` was rewritten to call `constructFrom(date, value)` which invokes `new date.constructor(value)` for any `Date` subclass. When `@date-fns/utc`'s `UTCDateMini` (used inside `inputToDate()`) is passed to a v4 helper such as `startOfMinute` or `isValid`, the runtime calls `new UTCDateMini(utcDateMiniInstance)`. Under tests that use `timezone-mock`, the global `Date` is replaced with `MockDate` whose constructor rejects object arguments — producing `Unhandled type passed to MockDate constructor: object` in 50+ unit tests.

## How?

| File | Change |
|------|--------|
| `packages/components/package.json` | Bump `date-fns` `^3.6.0` → `^4.1.0` |
| `time-picker/index.tsx` | Replace `startOfMinute(inputToDate(…))` with an inline `truncateToMinute()` helper that calls `date.setSeconds(0, 0)` directly on the `UTCDateMini` instance — the prototype shim routes `setSeconds` → `setUTCSeconds`, so UTC semantics are preserved |
| `parse-date-time.ts` | `isValid(parsed)` → `!isNaN(parsed.valueOf())` |
| `is-valid-date-boundary.ts` | `isValid(…)` → `!isNaN(new Date(value).valueOf())` |
| `dataform-controls/date.tsx` | Same `isValid` → `!isNaN` fix |

The remaining `date-fns` import sites (`date-picker/`, `calendar/`, `operators.tsx`) were audited and confirmed safe: they operate on plain `new Date()` instances, not `UTCDateMini`, so the v4 `constructFrom` path is never triggered.
