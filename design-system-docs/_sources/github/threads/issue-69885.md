# Issue #69885: ComboboxControl should allow additional props such as `required={true}` and `disabled={true}`

- URL: https://github.com/WordPress/gutenberg/issues/69885
- Author: MichelleBlanchette
- Created: 2025-04-11T02:16:47Z
- Updated: 2025-04-16T23:19:48Z
- Comments: 1 of 1

## Body

## What problem does this address?

It is currently impossible to set `<ComboboxControl required={true} />` for form validation. It's also not possible to make use of the internal ref to implement custom input validation.

This is inconsistent from the rest of the Control components, leading to confusion. It also means the developer must implement separate state variables just to determine if an error notice should be displayed—which is not consistent with the browser input validation messaging that other input controls use.

See `SelectControl` for example, which uses `...restProps`: https://github.com/WordPress/gutenberg/tree/2fc05aa08c2b6ef93951037ee28bf27f2965a358/packages/components/src/select-control

## What is your proposed solution?

`ComboboxControl` should accept `inputProps` to spread on the nested `<input />` element or otherwise explicitly expose common props `required` and `disabled`: https://github.com/WordPress/gutenberg/tree/2fc05aa08c2b6ef93951037ee28bf27f2965a358/packages/components/src/combobox-control

This seems to mean that `TokenInput` also needs to support `required`: https://github.com/WordPress/gutenberg/tree/2fc05aa08c2b6ef93951037ee28bf27f2965a358/packages/components/src/form-token-field

I support the enhancement proposed in this issue. Many existing `Controls` already support passing additional props, and since `ComboboxControl` uses `TokenInput`, which also accepts them, it makes sense to allow consumers to pass additional `input` props. Forwarding these props would enable valid use cases like conditionally disabling the `ComboboxControl`.
