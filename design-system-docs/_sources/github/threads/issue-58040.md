# Issue #58040: DropdownMenu V2: Focus goes out when pressing Tab key

## Body

### Description

The DropdownMenu V2 component allows you to use the arrow keys to move between menus in the same hierarchy without losing focus. However, if you press `Tab` or `Shift+Tab`, the focus will be lost from those menus.

In Dropdown V1, the Tab key does not remove focus, so the behavior in V2 feels like a bug to me.

### diegohaz on 2024-01-23T13:16:51Z

URL: https://github.com/WordPress/gutenberg/issues/58040#issuecomment-1906040532

> cc'ing @diegohaz to confirm that the behaviour is indeed intentional

Correct me if I'm wrong, but I think the DropdownMenu V2 in WordPress uses the [`modal`](https://ariakit.org/reference/menu#modal) prop, right? In this scenario, the <kbd>Tab</kbd> key press is managed by the browser or system as usual. It typically shifts focus to the next element outside the current window, including iframes. This behavior aligns with [native modals](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/dialog#creating_a_modal_dialog) (see `Creating a modal dialog`).

The reasoning behind this is that mouse users can already interact with elements outside the current window, whether it's the browser chrome or elements outside an iframe. So, this provides the same level of access to keyboard users.
