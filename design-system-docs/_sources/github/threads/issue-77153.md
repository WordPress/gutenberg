# Issue #77153: Theme: Some color token values that should differ do not

- URL: https://github.com/WordPress/gutenberg/issues/77153
- Author: jameskoster
- Created: 2026-04-08T14:27:08Z
- Updated: 2026-06-12T12:39:41Z
- Comments: 13 of 13

## Body

A certain category of color tokens share values when they should be different. For example `--wpds-color-fg-interactive-brand` and `--wpds-color-fg-interactive-brand-active` map to the exact same value:

https://github.com/WordPress/gutenberg/blob/32b24bd4a7317b9bb8084dbf61d2049f360438b8/packages/theme/src/prebuilt/css/design-tokens.css#L64-L65

So while `--wpds-color-fg-interactive-brand-active` is used for the hover color applied to `Link`, there's no visible change when hovering. [Storybook](https://wordpress.github.io/gutenberg/?path=/docs/design-system-components-link--docs).

This issue seems to affect all `--wpds-color-fg-interactive-*` tokens, and their `-active` counterparts.

My expectation is that the `-active` token would map to a slightly darker (or lighter) value, as the `bg` tokens do:

https://github.com/WordPress/gutenberg/blob/32b24bd4a7317b9bb8084dbf61d2049f360438b8/packages/theme/src/prebuilt/css/design-tokens.css#L15-L16

### ciampo on 2026-04-10T11:23:14Z

URL: https://github.com/WordPress/gutenberg/issues/77153#issuecomment-4223398397

@jameskoster it seems like all `fg-interactive-*` tokens share the same value between the "resting" and "active" states — which I believe is the result of us working on those tokens with the `Button` component in mind, where the "active" state is mostly communicated via background color and border changes.

Therefore, I think this needs to first get some design feedback. @jameskoster , in your opinion, assuming the default WordPress color theme (light theme, blueberry blue), should "active" fg color variants get darker or lighter compared to the resting state? Let's make sure these changes can work both in components like `Button` (ie. with a dedicated bg color) and `Link` (ie. rendered on top or app surfaces).

This decision will have implications on the solution — notably, not all "resting" tokens are mapped to a color that has a darker variant. For example:
- `--wpds-color-fg-interactive-brand` maps to `primitive.primary.fgSurface3` and therefore the `active` variant could be mapped to the darker `primitive.primary.fgSurface4`;
- `--wpds-color-fg-interactive-neutral` maps to `primitive.bg.fgSurface4`, and there isn't a `primitive.primary.fgSurface5` token (yet).

Happy to schedule a pairing session on this (and maybe collate it with other DS tokens work such as [this one](https://github.com/WordPress/gutenberg/pull/76937#discussion_r3050580481))
