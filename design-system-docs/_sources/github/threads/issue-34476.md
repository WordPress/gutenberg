## Body

### Description

When running a test with the default `test-unit-js` command provided by `@wordpress/scripts`, I'm getting this failure: `ReferenceError: CSS is not defined`

I can track it back to this line:

https://github.com/WordPress/gutenberg/blob/4623cf1e90db7373b63acd750380ee6ea0e60bac/packages/components/src/ui/utils/space.ts#L33

I can fix it by adding a local `jest.config.js` to define an empty CSS global, but I think this should be handled in the provided jest config.

### Step-by-step reproduction instructions

I created a very simple demo using `create-block`, you can see it here: https://gist.github.com/ryelle/221233ba154225475300649dc485f3e0 -- I made no changes to the default code, just stripped it down a bit and added a test.

Run `npm test` and you'll see the error.

### ciampo on 2021-09-03T17:28:07Z

> Should we use a fallback in the code when CSS is not defined?

We can change the code to something like `CSS?.supports?.( ... )`, although that won't prevent an error if in the future another call to `CSS.supports` will be added to the codebase.

In addition to that, in order to prevent similar errors in the future, I would also consider adding the `CSS` global to the Jest configuration.
