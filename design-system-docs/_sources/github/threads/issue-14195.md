# Issue #14195: Modal Component: rename to Dialog

- URL: https://github.com/WordPress/gutenberg/issues/14195
- Author: davewhitley
- Created: 2019-03-01T17:04:39Z
- Updated: 2021-07-13T13:37:57Z
- Comments: 9 of 9

## Body

**Is your feature request related to a problem? Please describe.**

Currently, we define a Modal as a smaller window that appears on top of the primary parent window. It usually has a shadow and a darker background. This can be problematic since "modal" can also be used to describe other elements with a shadow and similar behavior. For example, you can have a sidebar with a modal behavior, meaning it has a shadow and transitions in/out of the primary window.

Take a lot at this recent discussion and some of the confusion it can cause:

https://github.com/WordPress/gutenberg/issues/13663

> the next step to explore might be to make the sidebar behave like a modal

> When you press the cog button, the sidebar opens in a modal behavior. The means it has a drop shadow, and when you click outside or press Escape, it closes and sets focus back on the block you invoked it from.

> You'd still be able to see the main content in context, despite the behavior being modal.

> the sidebar would open as a modal with a shadow

> Is there a half-way point we could explore, where the sidebar would behave in a "modal-ish" way

> One idea posed early on, was **making the inspector into a modal dialog**.

**Describe the solution you'd like**

We should rename the Modal component to "Dialog". Other systems have followed this pattern, like [Material](https://material.io/design/components/dialogs.html#usage) and [GNOME](https://developer.gnome.org/hig/stable/dialogs.html.en). Dialog is more clear when talking about the component. "Modal" is commonly used to describe the behavior or visual look of other elements in a generic way:

- "a modal sidebar"
- "a dialog is a type of modal window"

Also the dialog API uses the ARIA role "dialog" so it would be consistent with that.

https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Roles/dialog_role

By aligning on the terminology we use, we will reduce confusion and communication will be efficent.

