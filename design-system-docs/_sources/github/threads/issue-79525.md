# Issue #79525: ui/Text: medium font-weight doesn't apply to all fonts/OS/browser combinations

- URL: https://github.com/WordPress/gutenberg/issues/79525
- Author: ciampo
- Created: 2026-06-25T09:12:07Z
- Updated: 2026-06-25T15:40:52Z
- Comments: 4 of 4

## Body

Following the conversation in https://github.com/WordPress/gutenberg/pull/78872#issuecomment-4796837148, I realised that the `Text` component from `@wordpress/ui` uses only `regular` and `medium` font weights.

But all fonts support the medium font-weight, and when that happens, the browser fall backs to regular (more context [here](https://github.com/WordPress/gutenberg/pull/70787#issuecomment-3091992333)).

This means that, effectively, our `Text` variants lose quite some visual hierarchy:


| Expected (Chrome on Mac OS) |  Simulated (ie. forced all font weights to `400`) | Windows (system font doesn't support medium font weight) |
|---|---|---|
| <img width="1386" height="1134" alt="Image" src="https://github.com/user-attachments/assets/b87dbe9b-1869-4a99-8c77-a83024d893d1" /> | <img width="1372" height="1130" alt="Image" src="https://github.com/user-attachments/assets/066c9211-edd2-4afa-955e-bf489a9f3d9a" /> | <img width="1062" height="824" alt="Image" src="https://github.com/user-attachments/assets/eb0aebe4-aeee-43e9-98d4-76c9752de097" /> |



Not sure what's the best decision here: maybe we can prepare two different `medium` font weight tokens:

- One like the current one, which nudges the browsers to fallback to regular when the medium weight is not supported;
- Another one, which nudges the browsers to fallback to semibold instead?


Alternatively, use a heavier font weight directly in the `Text` variants?

cc @t-hamano @WordPress/gutenberg-components @WordPress/gutenberg-design

### simison on 2026-06-25T14:03:27Z

URL: https://github.com/WordPress/gutenberg/issues/79525#issuecomment-4800168070

_"[Segoe UI Variable](https://learn.microsoft.com/en-us/windows/apps/design/downloads/#fonts) is the new system font for Windows. It is a refreshed take on the classic Segoe and uses variable font technology to dynamically provide great legibility at very small sizes, and improved outlines at display sizes."_ [via](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/typography)

So it might be worth trying to include both old and new font names:

```css
body {
  font-family: "Segoe UI Variable", "Segoe UI", sans-serif;
  font-weight: 500;
}
```

I don't know if that font name is directly available in new Windows machines, but worth testing! Another option would be shipping the font manually, kinda like [they did in FluentUI webcomponents](https://github.com/microsoft/fluentui/pull/22079/changes), but that isn't very ideal.
