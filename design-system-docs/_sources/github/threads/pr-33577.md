Those `fireEvent`s will just dispatch the specific events programmatically. I don't think JSDOM will fire the change event in response to that. In fact, I'm not even sure the browser would do that either (if it's not an actual user action).

One option is firing the change event directly:
```js
fireEvent.change( slider, { target: { value: '51' } } );
```

But we can also try [`@testing-library/user-event`](https://github.com/testing-library/user-event). It looks like it's been improved a lot since the last time I proposed it. I'm not sure it supports arrow keys on range inputs though.
