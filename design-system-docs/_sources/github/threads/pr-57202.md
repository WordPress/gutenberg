## What?
<!-- In a few words, what is the PR actually doing? -->

Allow nesting 2 or more `Tooltip` components without breaking the tooltip functionality. The contents of the tooltip will be the ones defined in the outer-most `Tooltip` instance.

## Why?
<!-- Why is this PR necessary? What problem is it solving? Reference any existing previous issue(s) or PR(s), but please add a short summary here, too -->

In #56490, we're trying to fix [an issue](https://github.com/WordPress/gutenberg/issues/56522) where `Button` could trash and re-create its children when the internal tooltip logic flips from showing to hiding the tootlip (or vice-versa).

The solution proposed in #56490 involves always rendering (in the react sense) the `Tooltip` component inside `Button`. But doing so would cause breakages, since the `Tooltip` component doesn't support that scenario.

This PR allows that scenario to work without causing breakages.

## How?
<!-- How is your PR addressing the issue at hand? What are the implementation details? -->

By using the internal context system to inform instances of `Tooltip` whether they are being rendered inside another instance of `Tooltip`. When that happens, the `Tooltip` component only renders the anchor and ignores the tooltip part.

### ciampo on 2023-12-19T11:42:00Z

URL: https://github.com/WordPress/gutenberg/pull/57202#issuecomment-1862606194

Before moving any further, I'd like to get a quick check from @diegohaz on the chosen approach. Diego, here is a quick recap:
- it was initially noticed that when `Button`'s internal logic flips between showing/not showing a tooltip, React is forced to trash/re-create the underlying HTML element, causing a loss of focus (see https://github.com/WordPress/gutenberg/issues/56522)
- After trying a few approaches, the only one that seems to work reliably is to always render a `Tooltip` component inside the `Button` element (#56490), although this approach caused issues if `Button` is already nested inside a `Tooltip` components (see https://github.com/WordPress/gutenberg/pull/56490#issuecomment-1825498243).
- Therefore, we decided to look into tweaking `Tooltip` so that if multiple instances are nested into each other, only the outer instance actually renders a tooltip (this PR)

Please let me know if this approach makes sense to you, or if there are better ways to handle this in `ariakit`. Thank you 🙏

### diegohaz on 2023-12-19T23:21:40Z

URL: https://github.com/WordPress/gutenberg/pull/57202#issuecomment-1863607072

I believe that's reasonable. If I'm interpreting the solution correctly, the only issue I foresee is if users typically display portaled content within those buttons. For example:

```jsx
<Tooltip>
  <Button />
  <Modal>
    <Tooltip>
      <Button />
    </Tooltip>
  </Modal>
</Tooltip>
```

If this scenario is unlikely, then I think it's perfectly fine.
