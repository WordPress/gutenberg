## Body

## What?

Updates the FontSizePicker control's header (label + toggle) so that it is consistent with our design tools spacing.
- 16px height
- Toggle button is 24px and "breaks out" of the 16px container height via negative margin


## Why?

Makes the font size picker spacing consistent with other design tools.

See https://github.com/WordPress/gutenberg/pull/50660#issuecomment-1556809865 for more context.

## How?

Replaces the direct use of the `HStack` and `Button` in the font size picker's header with new styled components based off them. The styled components then have the necessary styles to bring the component in line with other design tools.

## Testing Instructions

1. Edit a post, and select a paragraph block
2. Switch to the styles tab and inspect the label of the font size control
3. Check that the label's parent has a height of `16px`
4. Confirm the control's toggle button is still `24px` tall but is not offset via a `-4px` top margin.

### jasmussen on 2023-05-25T07:13:30Z

URL: https://github.com/WordPress/gutenberg/pull/50855#issuecomment-1562397231

Nice. As we discussed on the PR, the main question here is whether this needs to be fixed on a per-label basis, or whether it needs a dedicated component. The label + 24x24 icon button on the right is an increasingly common pattern.

### ciampo on 2023-05-25T07:58:46Z

URL: https://github.com/WordPress/gutenberg/pull/50855#issuecomment-1562455226

The tricky part is to balance the convenience of a ready-made pattern (label + icon) and the flexibility of composing components granularly. Having too many monolithic and/or specialized components can make it harder to make code changes in the future when, for example, we may migrate away from the label + icon pattern.

A good middle ground is usually for consumers of the components to create their own abstractions on top of such components, although I'm not sure it could be applied here since the icon is part of `FontSizePicker`'s implementation

### jasmussen on 2023-05-25T08:13:23Z

URL: https://github.com/WordPress/gutenberg/pull/50855#issuecomment-1562476900

I'll defer to you all on what the best approach is! No blockers to this one. So long as we follow the design pattern (labels are never taller than 16px), good on my end 👍 👍

### aaronrobertshaw on 2023-05-26T06:45:44Z

URL: https://github.com/WordPress/gutenberg/pull/50855#issuecomment-1563885750

Given the `FontSizePicker` is part of the components package, I think it makes sense to land this one as is. 

Any composed component including both a label and icon would have to be added to the components package to be used by the FontSizePicker. That doesn't seem ideal.

We can still look at introducing one to the block-editor package for other use cases if it makes sense.

For now, this fixes the spacing.
