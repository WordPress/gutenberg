It shouldn't be an issue — the type definitions should be the source of truth.

The fact that the `defaultIsEmpty` function doesn't accept any argument shouldn't change the behaviour of the function, which will still return a `boolean` nevertheless

```js
defaultIsEmpty(); // `false`
defaultIsEmpty( 'a string' ); // `false`
defaultIsEmpty( undefined ) // `false`
defaultIsEmpty( null ) // `false`
```

This non-breaking behaviour should be further certified by the lack of any TypeScript errors.


This is the same reason why it's usually not an issue that we sometimes assign `noop` as a default value of a callback, regardless of the callback signature. (even though I'm not a fan of that pattern myself).
