# Issue #51639: Remove "destructive" variant of Components

- URL: https://github.com/WordPress/gutenberg/issues/51639
- Author: getdave
- Created: 2023-06-19T08:16:21Z
- Updated: 2023-06-20T07:41:18Z
- Comments: 10 of 10

## Body

As mentioned by @jasmussen in https://github.com/WordPress/gutenberg/pull/50843 we should avoid the destructive variant of components.

Let's codify this convention by removing the props so as to avoid developers being able to introduce it into the codebase.       

-------

    > You should never see this. When there's only one menu, show it directly on this top level of the Navigation section, as per #50396:

This has been noted in https://github.com/WordPress/gutenberg/issues/51561 and we are fixing in https://github.com/WordPress/gutenberg/pull/51565

> Let's not use the red color for the button here. In general I think we should move away from "destructive colors" as they do not work well for color blindness

If that's the case then let's deprecate the props of the relevant `@wordpress/components` so that we _codify_ the convention 🙏

### ciampo on 2023-06-19T11:36:25Z

A bit late to this conversation!

`isDestructive` is a prop of [the `Button` component](https://wordpress.github.io/gutenberg/?path=/story/components-button--default&args=isDestructive:true). It serves uniquely to [add visual styles](https://github.com/WordPress/gutenberg/blob/19bcabfcbbc483028d1a429d9abe6a0fd595d233/packages/components/src/button/index.tsx#L129) to the `Button` component.

If we want to discourage using that prop, we could:
1. search across the Gutenberg and remove the prop from all usages of `Button`
2. deprecate the prop
3. We would need to understand if we also want to give a notice that, withing X WordPress released, the `isDestructive` prop (and related styles) will be removed from the component
