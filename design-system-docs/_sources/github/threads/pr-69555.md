## Body

## What?
Closes #69553

This PR introduces a new `overflowPadding` prop for the `Popover` component, allowing precise control over the offset between the popover container and the viewport edge.

## Why?

Previously, there was no way to adjust the offset when the popover container reached the viewport edge, often cutting it off or partially obscuring near screen boundaries.

## How?

- A new prop `overflowPadding` was introduced.
- The value of this prop is passed down to the `padding` property within `size` middleware from `floating-ui`.

## Testing Instructions

1. Navigate to Appearance -> Editor -> Templates.
2. Click on `View Options`.
3. Shrink the height of the `Browser Window`.
4. Confirm, the popover container doesn't overflow over the edit site page content.

Thanks for the suggestion, @ciampo!  

Using the `padding` prop within the `size` middleware is the best approach. As documented [here](https://floating-ui.com/docs/detectoverflow#padding), it accepts either a single number (applying uniform virtual padding) or an object for specifying padding per side.  This is how `Ariakit` implements it.

I've incorporated this in commit 5d9491b57d291296197193361123506a529dd859 and renamed the internal prop to `overflowPadding` for consistency with `Ariakit`.  

With this change, we can now apply virtual padding across all sides.

> Can we add 8px of space only if sizeProps.availableHeight is at least 8px?

We likely can’t use padding here since the size callback doesn’t have access to `sizeProps`—it only receives `middlewareStates` (see: [Floating UI docs](https://floating-ui.com/docs/size#options)).

The better approach in this context would be to subtract the value directly from `availableHeight`, which I’ve implemented in the latest commit.
