### ciampo on 2024-08-30T17:14:18Z

URL: https://github.com/WordPress/gutenberg/pull/64942#issuecomment-2322007462

This is just a different approach. IMO:

- Pros
  - Our styles continue to rely on the `data-focus-visible` selector and any logic that it represents
  - The workaround was proposed by the library author (@diegohaz )
- Cons
  - The current fix is CSS based (potentially more performant) and only a couple of lines of code

### diegohaz on 2024-08-30T18:16:29Z

URL: https://github.com/WordPress/gutenberg/pull/64942#issuecomment-2322097385

> * The current fix is CSS based (potentially more performant) and only a couple of lines of code

That's fine since WordPress does that only for composite items receiving actual DOM focus ([`virtualFocus`](https://ariakit.org/reference/composite-provider#virtualfocus) is `false`). Otherwise, the native `:focus-visible` is not applied to composite items managed by `aria-activedescendant`.

### diegohaz on 2024-08-31T12:54:02Z

URL: https://github.com/WordPress/gutenberg/pull/64942#issuecomment-2322889112

No, I think WordPress can keep the current solution until it needs to work with composite items with virtual focus.

If there are plans to introduce these components soon and they will also have distinct styles for active-item vs. focus-visible, then yes, the workaround in this PR is better.
