## What?
<!-- In a few words, what is the PR actually doing? -->

Related to:
- #50459
- #49271 

Useful links:
- [Radix UI DropdownMenu docs](https://www.radix-ui.com/docs/primitives/components/dropdown-menu)
- [Draft style specs](https://www.figma.com/file/oituj8yH1O6z1Y6EsHY6FA/DropdownMenu?type=design&node-id=16-621&t=m6LsE3SPBIZgNF44-0)

This PR introduces a new version of the `DropdownMenu` component, which adds extra capabilities to the component (notable, submenus) and introduces a refreshed design.

## Why?
<!-- Why is this PR necessary? What problem is it solving? Reference any existing previous issue(s) or PR(s), but please add a short summary here, too -->

With the need to support nested submenus, we're experimenting with using third-party libraries for UI patterns that are standardized and would be otherwise complex to implement and maintain.

## How?
<!-- How is your PR addressing the issue at hand? What are the implementation details? -->

- Introduced Radix UI as a dependency
- Added new set of high-level components that use Radix UI under the hood
- Exposed props are a modified subset of Radix's props
- Styled according to the specs
- Added Storybook examples, unit tests, and docs
- Moved the legacy version of the component to a `v1` folder, and added the new implementation into a `v2` folder
- Exported the new component via the `lock`/`unlock` private APIs
