## Body

## What?
See #76744.

Adds runtime style registration for styles imported from JavaScript, then adds an ESLint rule to prevent new non-module stylesheet imports in JavaScript files.

## Why?
Non-module stylesheet imports in JavaScript are easy to miss because they work at runtime, but they bypass the normal stylesheet pipeline. That can duplicate styles, omit styles from the enqueued stylesheet bundle, and skip build-time processing such as RTL generation.

## How?
- Adds `@wordpress/style-runtime` and updates `wp-build` inline styles to register through it.
- Adds `@wordpress/no-non-module-stylesheet-imports` with tests and documentation.
- Enables the rule for package source files and `routes`, with bulk suppressions for existing route/package cases that need separate migration.
- Moves straightforward existing stylesheet imports into package stylesheet entry points.

## Testing Instructions
1. Run `npm run test:unit -- packages/eslint-plugin/rules/__tests__/no-non-module-stylesheet-imports.js`.
2. Run `npm run lint:js -- packages/eslint-plugin/rules/no-non-module-stylesheet-imports.js packages/eslint-plugin/rules/__tests__/no-non-module-stylesheet-imports.js tools/eslint/config.mjs`.
3. Run `npm run lint:css -- packages/editor/src/style.scss packages/media-editor/src/style.scss`.
4. Run `npm run lint:js -- packages/boot/src packages/lazy-editor/src packages/notices/src packages/workflow/src --pass-on-unpruned-suppressions`.
5. Run `npm run lint:js -- routes --pass-on-unpruned-suppressions`.
