From my experience re: heading styles vs. tagNames.

This conflict usually exists when you need the semantics of an `h*` (e.g. `h2`), but the aesthetic sizing of another (e.g. `h4`).  For better or for worse, this workflow can be seen in many [Bootstrap based](https://getbootstrap.com/docs/5.0/content/typography/#headings) projects.

That aside, depending on how [we handle specificity of the Style System](https://github.com/ItsJonQ/g2/pull/284), `h1-h6` tagName selectors typically have some sort of global reset and possible top level styling. Some side-effects may result from that.

I think @diegohaz 's suggestion for using `role` is the best of both worlds:

```
<span role="heading" aria-level="1">
```
