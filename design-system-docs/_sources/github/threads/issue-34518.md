# Issue #34518: Dropdown menus are now very narrow

- URL: https://github.com/WordPress/gutenberg/issues/34518

- Created: 2021-09-03T03:32:47Z
- Updated: 2021-09-03T14:12:45Z

## Body

### Description

This week I've spotted that dropdown menus have become very narrow. This feels like a very recent regression.

In some cases the UI is not functional, in other cases it's not making use of the available space as well as it could be.

### Step-by-step reproduction instructions

1. Add an image block
2. Resize the screen to a small size
3. Click the Insert From URL button

Expected: the dropdown has adequate space to type in a URL
Actual: the dropdown is very narrow

1. Add a navigation block
2. Select the  'Add existing Menu' button.

Expected: the dropdown is a reasonable width
Actual: The dropdown is very narrow

There are other cases too, and this will probably have affected users of the components package, so I think the root issue with dropdowns.

### jasmussen on 2021-09-03T07:48:03Z

URL: https://github.com/WordPress/gutenberg/issues/34518#issuecomment-912332774

This is almost certainly a result of #33995, which removed a min-width that every popover was born with. The reasoning is this: the popover should be agnostic to its content, and be able to accommodate both wide content:

<img width="326" alt="Screenshot 2021-09-03 at 09 43 59" src="https://user-images.githubusercontent.com/1204802/131969408-0b7f16ad-15a8-48f8-b129-8d021bbfa628.png">

... but also content that is intentionally thin, like the vertical headings level indicator:

<img width="477" alt="Screenshot 2021-09-03 at 09 44 15" src="https://user-images.githubusercontent.com/1204802/131969449-2c287276-770b-4e36-9ff8-9d4b03b13927.png">

The second part of the reasoning is that it's up to each menu item individually to ensure that it has a reasonable width. Since the popover is now as wide as the smallest item inside, this can be done either using `white-space: nowrap;` on items inside, or by applying an appropriate min-width.

Sorry I missed this one, and thank you for the ticket. I'll prepare a patch in a moment, but short of restoring the basic min-width and overriding it in case of the vertical heading, would you agree the above reasoning makes for a good principle?
