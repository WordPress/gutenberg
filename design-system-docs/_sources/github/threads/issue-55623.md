# Issue #55623: Disabled controls should not use cursor: pointer

- URL: https://github.com/WordPress/gutenberg/issues/55623
- Author: afercia
- Created: 2023-10-25T13:50:14Z
- Updated: 2025-12-31T17:45:35Z

## Body

### Description

See trac ticket https://core.trac.wordpress.org/ticket/59733

Disanled ui  controls, whether they are disabled with a HTML `disabled` attribute or via `aria-disabled="true"` and no-ooping them, may still display a `cursor: pointer` styling when hovered. That feels just wrong as a disabled control shouldn't be highlighted as 'interactive'.

The main problem originates from the Core `forms.css` stylesheet. But I think the editor components styling should also provide a default cursor for disabled and aria-disabled controls.

Example screenshot:

![disabled controls gutenberg](https://github.com/WordPress/gutenberg/assets/1682452/039dba57-ad4f-4061-b903-a80c1e836f4b)

The lightbox control is disabled when the image is linked, but it still shows a 'pointer' cursor when hovered.

More details:
The core `forms.css` stylesheet provides a `cursor: pointer` styling for all form controls _and their label elements_.
Typically, the CSS selector in use is something like `input[type="checkbox"]`.
This overrides the user agent stylesheet for `input:disabled` which does provide a `cursor: default;` styling.
While this needs to be first addressed in Core, the editor should provide a default cursor as well for:
- All disabled and aria-disabled controls.
- All their relater `<label>` elements.
- All their clickable pseudo-labels, if any.

### Step-by-step reproduction instructions

- Edit a post
- Add an Image block and add a link to the image.
- Observe the lightbox control 'Expand on Click` in the settings sidebar gets disabled.
- Observe that hovering the disabled controls still displays a pointer cursor.
