### sirreal on 2020-10-23T15:43:29Z

URL: https://github.com/WordPress/gutenberg/pull/26176#issuecomment-715421254

The difficulty here seems to be that we have 2 interfaces that are very similar. They share some types but in a different structure.

- `useAnimate` -> `type` and `origin`. The design suggests that there could be additional options as well…
- `Animate` props -> `type`, `children` and `options`. `type` and `options` are merged as the options that need to be passed to `useAnimate`.

We should be able to describe this in the type system, but I haven't managed to do it yet in any way I consider acceptable.

I find that this often suggests we should step back and reconsider what this is telling us. In this case, I don't see any benefit to putting `options` in a separate object in Animate, then flattening for `useAnimate`.

I've pushed a change where I changed the Animate props a bit and I believe it cleans up nicely… but it's a bit more involved than simply annotating types. It is an interface change and `Animate` components would need an update.
