## What?
<!-- In a few words, what is the PR actually doing? -->

Part of #55023

Try creating a new `CustomSelectControl` using Ariakit to include new features, including an option to render children. 

## Why?
<!-- Why is this PR necessary? What problem is it solving? Reference any existing previous issue(s) or PR(s), but please add a short summary here, too -->

For more customization potential and a more intuitive API, allowing the use of JSX to add select values rather than a strict object like in our current `CustomSelectControl` component. 

## How?
<!-- How is your PR addressing the issue at hand? What are the implementation details? -->
 
By creating a compound component: 

```jsx
<CustomSelect>
	<CustomSelectItem value="Small">
		<span style={ { fontSize: '75%' } }>Small</span>
	</CustomSelectItem>
	<CustomSelectItem value="Something bigger">
		<span style={ { fontSize: '200%' } }>Something bigger</span>
	</CustomSelectItem>
</CustomSelect>
```

I'm sure there is a better solution, but this seems to fit for now. And it's likely to change when exploring controlled vs uncontrolled. 

If the `defaultValue` isn't a `string` or `undefined`, then it needs to be added a child to the Select button (`Ariakit.Select` styled as `CustomSelectButton`). If it is a `string` or left `undefined`, then it cannot be added as a child unless the state is controlled. Otherwise, it would be overwritten by the default value. 

I have it comparing against an `object` as I believe there may be other types I haven't accounted for. This will likely make for a good test to add.

I think that's the plan! Moreover current version of `CustomSelectControl` already has a `size` prop accepting `small`, `default` and `__unstable-large` values:

- `small` is `24px` (I guess we can keep it around for now)

 - we set a height of `auto`
