# Issue #23388: Slot/Fill: Error when provider is missing

- URL: https://github.com/WordPress/gutenberg/issues/23388
- Author: sirreal
- Created: 2020-06-23T11:35:06Z
- Updated: 2020-06-26T06:14:29Z
- Comments: 0 of 0

## Body

The design of Slot/Fill context hides problematic cases where a Consumer is not mounted under the necessary Provider.

It would be preferable to remove the stubbed context that hides misuse in applications. I'd like to see a descriptive error thrown immediately when the context is used without a provider:

https://github.com/WordPress/gutenberg/blob/67738605cb86dbb78828c6936ccd4c9d39d5a0d9/packages/components/src/slot-fill/bubbles-virtually/slot-fill-context.js#L1-L16

An error in `useSlot` seems ideal:

https://github.com/WordPress/gutenberg/blob/67738605cb86dbb78828c6936ccd4c9d39d5a0d9/packages/components/src/slot-fill/bubbles-virtually/use-slot.js#L12

```js
const SlotFillContext = createContext( undefined );
function useSlot( name ) {
  const registry = useContext( SlotFillContext );
  if ( ! registry ) {
    throw new Error( 'useSlot must be a descendent of SlotFillProvider' );
  }
  // …
}
```

https://github.com/WordPress/gutenberg/issues/23014 describes a bug where `SlotFillProvider` is not an ancestor of a SlotFillContext Consumer.

https://github.com/WordPress/gutenberg/pull/23108 fixes the error, but the caveats [were](https://github.com/WordPress/gutenberg/issues/23014#issuecomment-643065493) [noted](https://github.com/WordPress/gutenberg/pull/23108#issue-433457540) in [several](https://github.com/WordPress/gutenberg/pull/23108#pullrequestreview-429477187) [places](https://github.com/WordPress/gutenberg/pull/23108#issuecomment-648072639).
