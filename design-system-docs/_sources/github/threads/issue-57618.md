# Issue #57618: __experimentalNumberControl doesn't show correct saved value on Editor.

- URL: https://github.com/WordPress/gutenberg/issues/57618
- Author: Arifursdev
- Created: 2024-01-06T09:49:09Z
- Updated: 2024-12-14T11:10:07Z
- Comments: 5 of 5

## Body

### Description

the `__experimentalNumberControl` doesn't show correct saved value on Editor. it saves the number server side and shows on frontend correctly but in editor it remains what was default or min after a reload

### Step-by-step reproduction instructions


Steps:
- after changing number field to lets say 5
- update and successfully updated
- reload the editor, the number field is back to 1 (default)
- check the SSR frontend var dump attributes: it shows MyNumber as 5 `["MyNumber"]=> string(1) "5"`

### Screenshots, screen recording, code snippet

Attribute is defined when registering block as a number and default 1
```php
[
    'type'  => 'number',
    'default'   => 1
]
```

JS responsible for the field
```js
....

const { __experimentalNumberControl } = wp.components;
el(__experimentalNumberControl, {
    label: 'My Number',
    value: attributes.MyNumber,
    shiftStep: 1,
    min: 1,
    onChange: (value) => {
      setAttributes({ MyNumber: value });
    },
  }),

...
```
