# Issue #54055: Ensure appropriate labels are provided for color/gradient picker controls

- URL: https://github.com/WordPress/gutenberg/issues/54055
- Author: andrewhayward
- Created: 2023-08-30T11:48:17Z
- Updated: 2023-11-09T21:15:22Z
- Comments: 3 of 3

## Body

## What problem does this address?
Changes introduced in #52255 make it a requirement for the [`CircularOptionPicker`](https://github.com/WordPress/gutenberg/tree/trunk/packages/components/src/circular-option-picker) to have an `aria-label`/`-labelledby` prop provided, to make sure appropriate context is available for the control. The three consuming components ([`ColorPalette`](https://github.com/WordPress/gutenberg/tree/trunk/packages/components/src/color-palette), [`DuotonePicker`](https://github.com/WordPress/gutenberg/tree/trunk/packages/components/src/duotone-picker) and [`GradientPicker`](https://github.com/WordPress/gutenberg/tree/trunk/packages/components/src/gradient-picker)) all hide this requirement behind a default value, and should transition away from optional ARIA props to requiring a label of some sort.

## What is your proposed solution?
All of the higher-order controls that use these three foundational components should be updated to provide a more appropriate and relevant label for their context, passing either an `aria-label` or `aria-labelledby` prop.

## Acceptance Criteria

 - [x] Identify all of the controls that use `ColorPalette`, `DuotonePicker` and `GradientPicker`
 - [ ] Update them to provide context-appropriate labels with `aria-label` or `aria-labelledby`
 - [ ] Update `ColorPalette`, `DuotonePicker` and `GradientPicker` to require one of `aria-label` or `aria-labelledby` (see [related conversation](https://github.com/WordPress/gutenberg/pull/52255#discussion_r1311711606))
