I decided to take a deeper look at this, and ended up in a bit of a rabbit hole 🐰 

By reading the docs, it looks like `QueryControls` can be used with single or multiple category selection depending on which props are passed to the component. Based off that, the `onCategoryChange` prop changes its type (either `TreeSelectProps[ 'onChange' ]` for single selection, or `FormTokenFieldProps[ 'onChange' ]` for multiple selection).

The correct way to represent this duality in TypeScript is to split the "single selection props" from the "multiple selection props". Something like this (pseudo code):

```ts
type CommonProps = { ... };
type WithSingleSelection = CommonProps & {
  // props specific to single category selection
  onChange?: TreeSelectProps[ 'onChange' ];
};
type WithMultipleSelection = CommonProps & {
  // props specific to multiple category selection
  onChange?: FormTokenFieldProps[ 'onChange' ];
}; 
type QueryControlsProps = WithSingleSelection | WithMultipleSelection;
```

function isMultipleCategorySelection(

	return 'categorySuggestions' in props;

I then realized that using `TreeSelectProps[ 'onChange' ];` as the type for the `onChange` prop in the `CategorySelect` and `AuthorSelect` component is not necessary. We can instead type it as a simpler `( newValue: string ) => void` function, because:
- the `newValue` will never be `string[]` (because that only happens when passing the `multiple` prop to `TreeSelect`
- the second argument has never been assumed to exist for consumers of the component

I also decided to swap the type "dependency" from `CategorySelectProps` and `AuthorSelectProps` to `QueryControlsProps` — I think it's better if the prop types are defined in `CategorySelectProps` and `AuthorSelectProps` as those components defines the implementation details, and if the type definitions get reused in `QueryControlsProps`

- I realized that all `on.*` callbacks were not being shown in the `actions` tab because they were not being passed explicitly to the component. I went ahead and fixed that.
