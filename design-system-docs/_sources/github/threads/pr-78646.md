## Body

## What?

- Update `@wordpress/components` Button styles to use the shared `outset-ring__focus` mixin for outline-based focus rings across variants.

## Why?

Align legacy components Button focus styling with the design system and `@wordpress/ui` buttons.

## How?

- Replace box-shadow focus rings with the `outset-ring__focus` mixin on `:focus:not(:active)` (link variant included, with underline removed on focus to avoid clashing with the ring).
- Keep secondary borders as inset `box-shadow` so button dimensions match trunk.
- Move forced-colors button boundaries into `@media (forced-colors: active)` using `outline: 1px solid ButtonText` (focus ring and HC boundary still share `outline` in forced-colors; left as a known limitation for now).

## Testing Instructions

1. Open Storybook for the Button e2e variant matrix (`npm run storybook:e2e:dev`).
2. Tab through default, primary, secondary, tertiary, destructive, pressed, and link variants. Confirm a consistent outline focus ring.
3. Click the same variants with the mouse (as these can have different behavior from tabbing).
4. Test disabled primary with keyboard focus when `focusableWhenDisabled` is used. Confirm the focus ring still appears.
5. Compare button widths against trunk for primary, secondary, and tertiary. Confirm no layout shift from the border work.
6. Optional: test in Windows High Contrast / forced-colors mode. Note the focus ring may sit on the same outline layer as the HC boundary.

`border-color` was a no-op here. `.components-button` already sets `border: 0`, and primary never gives itself a non-zero border width, so `border-color` does not affect layout or appearance in normal mode.

Primary styling is background + color, not a border stroke (secondary uses inset `box-shadow` for that).

The forced-colors boundary did not come from `border-color` either. Trunk used `outline: 1px solid transparent` on primary (and `outline: none` on disabled). This PR moves that to `@media (forced-colors: active) { outline: 1px solid ButtonText }` on `.is-primary`. Removing `border-color` is unrelated to that change.

Same reasoning applies to the other removed `border-color` lines on primary (`:active`, `is-busy`): leftovers from when buttons may have used real borders, not something the current styles depend on.
