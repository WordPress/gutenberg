This issue stems from a discussion in [#65801](https://github.com/WordPress/gutenberg/issues/65801).

There are several instances in the WordPress UI where a reusable [TreeView](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/) component could improve both functionality and consistency:

* Category selection when writing a post.
* Category selection when creating a template for a specific category.
* Page selection when creating a template for a specific page.
* Filter by category in Posts data view (WIP).
* Potentially: Selecting a parent when creating a new page or category.

There are doubtless many more in the wider ecosystem.

## Why TreeView?
A dedicated TreeView component would serve as a foundational UI element, especially for hierarchical data scenarios like the examples outlined above. Considering those examples it should support both single and multi-select affordances.

## Existing Solutions
As [@ciampo](https://github.com/ciampo) noted in #65801, the existing [TreeSelect](https://wordpress.github.io/gutenberg/?path=/docs/components-treeselect--docs&globals=maxWidthWrapper:wordpress-sidebar) component may be a potential starting point. However, there are some considerations:

* A standalone TreeView (see [example](https://react-spectrum.adobe.com/react-aria/Tree.html)) could pave the way for more advanced interactions, such as integrating a searchable combobox for filtering records (e.g., [Ant Design TreeSelect](https://ant.design/components/tree-select)).
* Offering both a standalone TreeView and a TreeSelect might provide flexibility for diverse use cases.

## Design Considerations
This component will require design exploration, though it can likely leverage some existing visual patterns:

* `Listbox` (https://github.com/WordPress/gutenberg/issues/65801): For the general appearance and composition of the list.
* [`FormTokenField`](https://wordpress.github.io/gutenberg/?path=/docs/components-formtokenfield--docs): For displaying multi-selections in a compact manner.

By creating a reusable TreeView component, we can unify hierarchical data interactions across WordPress.
