<!-- How is your PR addressing the issue at hand? What are the implementation details? -->

### DaniGuardiola on 2024-09-13T02:06:19Z

URL: https://github.com/WordPress/gutenberg/pull/65175#issuecomment-2347901385

Well, that was an annoying rabbit hole. Without getting too deep into the details (which I don't know in much depth anyway), the issue was related to the fact that when an element changes, the time between that instant and the moment when the indicator position state is updated after the resize observer fires its first event observing the new element is... non-zero.

When updating the value at a very specific moment (somewhere around the end of the transition), it caused an obnoxious race condition that resulted in the reported skipping behavior. The fix is to track the element in sync with the rect observations, for which I have added a property to the stateful object returned by the utilities, and it seems to solve the whole thing.

That was a mouthful! Phew.

I backported the fix to Tabs, though it's interesting that we didn't see the issue there. Probably because it's just more obvious in this component.
