# Issue #30798: Bug: ColorPicker Input values don't trigger state in specific cases

- URL: https://github.com/WordPress/gutenberg/issues/30798
- Author: preda-bogdan
- Created: 2021-04-13T12:00:54Z
- Updated: 2021-04-22T13:45:50Z
- Comments: 0 of 0

## Body

## Description
The color picker input values don't update the state if the starting value is `rgb(0,0,0,0.5)` or any value that maps to `rgb(0,0,0)` where one r, g or b can be 0

## How to test
1. Create a Color Picker component with the default value set to (0, 0, 0, 0.5)
2. Try to change any input values to trigger an input change
3. Notice that the state does not change.

## Debugging
From my investigation this is caused by this function:
https://github.com/WordPress/gutenberg/blob/53e6424f6cdc7aae6e3117d15aee31d33d12c4cc/packages/components/src/color-picker/index.js#L49-L66

Because the checks are `falsy` for values of 0 this will return true.
Expected behaviour is that for `r: 0 g: 0 b:0` the return is `false` as the `data` is not empty.

Here is the only place where this is used, hence the specific edge case
https://github.com/WordPress/gutenberg/blob/53e6424f6cdc7aae6e3117d15aee31d33d12c4cc/packages/components/src/color-picker/index.js#L166-L181

The input will not commit the changes for values of 0.
