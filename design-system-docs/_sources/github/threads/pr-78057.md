<!-- In a few words, what is the PR actually doing? -->
This PR upgrades `date-fns` from v3.6.0 to v4.1.0 in the `@wordpress/components` and `@wordpress/editor` packages. This alignment ensures the monorepo uses a consistent version of the library.

## Why?
<!-- Why is this PR necessary? What problem is it solving? Reference any existing previous issue(s) or PR(s), but please add a short summary here, too -->
The Gutenberg monorepo had a version mismatch where some packages (like `dataviews`) were already on `date-fns` v4, while `components` and `editor` remained on v3. This caused fragmentation and testing complications.

Upgrading to v4.1.0 brings the repository up to date with the latest stable version, improves TypeScript support, and reduces bundle size via the optimized internal architecture of `date-fns` v4.

## How?
<!-- How is your PR addressing the issue at hand? What are the implementation details? -->
1. Updated `package.json` in `packages/components` and `packages/editor` to set `date-fns` to `^4.1.0`.
2. Verified that `@date-fns/utc` remains at `^2.1.1` for full compatibility.
3. This PR depends on the global mock fix introduced in **[Insert PR A URL here]** to prevent `MockDate` constructor errors during unit tests.

## Testing Instructions
<!-- Please include step by step instructions on how to test this PR. -->
1. Run unit tests for affected packages to ensure no regressions:
   - `npm run test:unit -- packages/components/src/date-time`
   - `npm run test:unit -- packages/editor/src/components/post-schedule`
2. All 118 tests in `components/date-time` and all tests in `editor/post-schedule` should pass.
3. Manually verify that date-picking and scheduling functionality remains stable in the editor.
