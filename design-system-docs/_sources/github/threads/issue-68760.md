My suggestion for a similar proposal would be to start discussing API changes in the issue before moving to implementation. Adding new APIs to public components can get tricky, so ironing out proposals first is always better.

While I can see how this proposal can be helpful, it also introduces confusing UX. Why?

* A suggestion is matched by `key`.
* There's no visual indication that the current suggestion is matched by `key` since the component only displays labels.

Here's a larger discussion for v2 of `Combobox` and related components.
