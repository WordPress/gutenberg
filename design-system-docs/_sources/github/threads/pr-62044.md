## Body

## What

Remove Framer Motion from the component and implement the previous animation using pure CSS.

## Why?

See the full list of reasons in https://github.com/WordPress/gutenberg/issues/60975. TL;DR is better runtime performance, bundle size, and following web standards, which are often leaner and simpler to maintain.


## How?

* Remove all imports and references to framer motion components. In Gutenberg, these are re-exported from a shallow wrapper called "Animate" in `@wordpress/components`.
* FIgure out how to re-implement the same animation using pure CSS (transitions or keyframes).

It might be acceptable to simplify he animation if it makes sense, provided everyone agrees with it.

However, it was a good compromise that I've found to handle the drop scenario without making the expressions in the component more complicated:

1. In the `shouldActivate` expression, the `isDraggingOverDocument` seems to be needed, or the drag-in sometimes is not detected.
2. However, you can't just negate that expression, as it doesn't work well to detect the **drag out**. For dragging-out, we should only check if `! isDraggingOverElement`.

4. However, when you drop inside the zone, then `inactive` is not applied. We could change the expression there to also apply it, but it's simpler to just then let it fallback to the property here, which it does, because when you drop, then `is-active` is not applied (nor `inactive`).
