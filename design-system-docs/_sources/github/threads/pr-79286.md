Closes  #79274 

Adds minimum width handling to @wordpress/components Button to align short-label buttons with @wordpress/ui and improve visual balance in paired actions.

## Why?
Short-label buttons such as "Add", "OK", or "Save" can appear visually undersized when paired with longer actions like "Cancel", creating an unbalanced interface and reducing the prominence of the primary action.

## How?
Applies the minimum width in Button’s own SCSS with enough selector specificity to override Flex/HStack child resets, while preserving existing variant-specific behavior for links, small buttons, icon-only buttons, and icon-with-text buttons.

## Testing Instructions

1. Open site-editor.
2. Go to Patterns.
3. Click Add Pattern.
4. Choose Add Template Part/Add Pattern.
5. Observe the increased width for `Add` button.

I think we may want to avoid or adjust the `min-width` altogether for any icon button. With the `@wordpress/ui` implementation, [`IconButton` styles reset inline padding to `0`](https://github.com/WordPress/gutenberg/blob/5ccc16d600593fc89744df641e2be1e54c7447e0/packages/ui/src/icon-button/style.module.css#L7), and so the logic in #75133 to compute as `calc(4ch + 2 * var(--wp-ui-button-padding-inline))` would result in `4ch`. In this branch, a button with icon and text has `min-width: calc(4ch + 24px)`, so not the same.

The result is that the min-width can stretch the width where we wouldn't expect and make it look a little lopsided:

<img width="77" height="62" alt="image" src="https://github.com/user-attachments/assets/da6d38a4-d1c4-4f16-ad04-c02f6a997230" />

As far as I can tell, it may only affect single-character labels, which wouldn't be very common, but we probably don't want the min-width at all.
