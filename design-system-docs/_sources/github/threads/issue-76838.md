## Body

**Task:** Rename typography tokens.

**Background:**

Typography tokens are defined in [`typography.json`](https://github.com/WordPress/gutenberg/blob/trunk/packages/theme/tokens/typography.json) under the `wpds-font` grouping.

This continues discussion from:

- https://github.com/WordPress/gutenberg/pull/73931#discussion_r2643875814
- https://github.com/WordPress/gutenberg/pull/74980#issuecomment-3820222272

As discussed, the current naming is problematic because properties like line-height and prospective tokens like letter-spacing are not aspects of font. There's also an inconsistency between the file name and the property grouping.

Last this left off, there was a ["relatively strong preference"](https://github.com/WordPress/gutenberg/pull/74980#issuecomment-3850027548) from @mirka toward naming these tokens `typography`. Unclear if @ciampo 's " 👍 " reaction is directed to this suggestion. I'm personally fine with it.

As I started looking at implementing this, another related question is whether to maintain the `font-` segment for properties which _are_ aspects of font (in particular: "font family", "font size", "font weight"). Also mentioned at https://github.com/WordPress/gutenberg/pull/74980#issuecomment-3820222272.

e.g. `--wpds-typography-family-body` or `--wpds-typography-font-family-body`

My opinion (lightly held) is to maintain `font-` for these properties, so we'd have:

```jsonc
{
  "wpds-typography": {
    "font-family": { /* ... */ },
    "font-size": { /* ... */ },
    "font-weight": { /* ... */ },
    "line-height": { /* ... */ }
  }
}
```

(or maybe `font` as a parent object containing `family`, `size`, `weight`. more an implementation detail though)
