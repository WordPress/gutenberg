# Issue #75916: Add Field Groups to DataForm

- URL: https://github.com/WordPress/gutenberg/issues/75916
- Author: jameskoster
- Created: 2026-02-25T15:47:06Z
- Updated: 2026-03-31T14:35:20Z
- Comments: 5 of 5

## Body

### Proposal

Add a `FieldGroup` abstraction within `DataForm` that represents a meaningful grouping of related fields e.g. Address, or Credit card inputs.

This would map to semantic `fieldset` and `legend` elements in the markup, giving clearer structure and built-in accessibility.

`FieldGroup`s can be visually separated from other fields using dividers or some other style technique.

---

### Why

* Aligns useful visual separation of fields with meaningful structure.
* Adopts semantic HTML (`fieldset` / `legend`)
* Scales better as forms grow in complexity

---

### Open Questions

* Should `FieldGroup` require a legend?
* Do we allow visually hidden legends?
* Do we need support for nested groups?
* Would `FieldGroup` require any special rules for specific layout options (e.g. in `row` layout it may make sense for `FieldGroup` to always occupy a full row.

**Environment**
WordPress: trunk
Gutenberg: latest plugin
Browser: Chrome

**Steps to test**

1. Open a WordPress admin screen that uses DataForm.
2. Create or inspect a form with multiple related fields (for example, address or payment information).
3. Observe how the fields are rendered and organized in the interface.

**Observation**
Related fields are currently presented as individual inputs without a clear grouping abstraction.
As forms grow in complexity, this makes it harder to visually scan related inputs and reduces the semantic relationship between them.

From a UX perspective, forms containing logically connected fields feel less structured because there is no clear grouping pattern.

**Suggestion**
Introduce a **FieldGroup abstraction** in DataForm so related inputs can be grouped semantically and visually.

**Possible approach:**

* Use **`fieldset` and `legend`** elements to provide semantic grouping.
* Allow optional visual separators or spacing patterns to differentiate grouped sections.
* Support layout rules so grouped fields can span a full row when necessary.

**Benefits:**

* Improves form readability and scanning.
* Enhances accessibility through semantic grouping.
* Aligns with common form patterns used across modern UI systems.

I’d be happy to explore a potential implementation and share a code proposal for review.

Hi, the [DataForm `form` property](https://developer.wordpress.org/block-editor/reference-guides/packages/packages-dataviews/#form-object) already provides a nested mechanic, note the `status` field example in the docs:

```tsx
const form = {
    layout: {
        type: 'panel',
        labelPosition: 'side',
    },
    fields: [
        'title',
        'data',
        {
            id: 'status',
            label: 'Status & Visibility',
            children: [ 'status', 'password' ],
        },
        {
            id: 'featured_media',
            layout: 'regular',
        },
    ],
};
```

I think we need more details about what a group means. Some questions for brainstorm: how would this "groups concept" would work at the form-config level? What would be the difference from the existing grouping? Can this grouping be applied to any layout or just regular? Perhaps is there some concrete examples to work with and derive the rules from them?

I dig how this issue is focused on attaching meaning to groups (visually and semantically). Thanks for exploring it from this angle. I'd like to get clarity on the specifics before jumping into implementation — I want to make sure we implement for the right use cases, and that we don't spend time implementing something that ends up not being used anywhere.
