## What?
<!-- In a few words, what is the PR actually doing? -->

### ciampo on 2022-06-02T10:33:43Z

URL: https://github.com/WordPress/gutenberg/pull/41271#issuecomment-1144707434

Hey @sunil25393 ,

thank you for the detailed explanation!

Basically what's happening is the following:
- opening the dropdown causes the sidebar content's to overflow its container
- therefore, a scrollbar is shown
- depending on how each browser/OS handles the sidebar, the appearance of the sidebar can cause the layout to shift / change width
- when this happens, the size of the components inside of the sidebar adapts in a responsive way
- this resizing causes the backdrop element in the `ToggleGroupControl` component to adapt to its new position — the resizing of the backdrop happens via an animation, which makes it more visible (which is what is describe in https://github.com/WordPress/gutenberg/issues/40708)

I personally believe that layout shift caused by scrolling content (like in this case) are an expected behaviour/feature of the responsive web, and that #40708 should be fixed by working on the `ToggleGroupControl` component itself

### ciampo on 2022-06-05T17:08:04Z

URL: https://github.com/WordPress/gutenberg/pull/41271#issuecomment-1146850000

> We have same functionality on post sidebar. Where sidebar shift when scrollbar is active. We cant have same for style sidebar also ?

Even if the sidebars used in the post editor and in the side editor share the same wrapper, the contents are different in the two editors — in particular, the sidebar in the site editor uses the `Navigator` component, while the sidebar in the post editor doesn't at the moment.

What you point out is true — the behaviour of the 2 sidebars is slightly different when it comes to resizing after a scrollbar is made visible. At the same time:

- I still believe that the root of this issue is in the `ToggleGroupControl` component, animating its backdrop even when not necessary
- the site editor is still a relatively new feature, and the controls in the Global Styles sidebar are still marked as experimental (and therefore, I'd argue that it's expected to have these slight discrepancies across global styles sidebar in the site editor, and sidebar in the post editor)
- the changes introduced by this PR introduce a regression in the `Navigator` component, since they show the horizontal scrollbars during an animation from a screen to another (which is also flagged by the code comments just before the line where you applied your changes)

> if we update/remove animation from ToggleGroupControl, won't it affect at every places ( also where this issue doesn't appear ) ?

Mine was a suggestion on how to solve the issue (I haven't tried implementing a solution myself) — but what I'm suggesting is to remove the animation from the backdrop when it's not needed. The backdrop would still animate as expected when the selected item changes.
