# Issue #38845: InputControl: Replace `composeStateReducers()` with a standard implementation

- URL: https://github.com/WordPress/gutenberg/issues/38845
- Author: mirka
- Created: 2022-02-16T01:25:24Z
- Updated: 2022-03-15T00:27:39Z
- Comments: 2 of 2

## Body

There is a quirk in the current implementation of `composeStateReducers()`, in that it requires each reducer to [mutate](https://github.com/WordPress/gutenberg/pull/37164/files#r801084302) the original `state` object. It can cause bugs in the reducer chain if a reducer returns a fresh state object instead.

https://github.com/WordPress/gutenberg/blob/7a3e37a3e0f11e0a05eb2ab36d34427e1c0c5b4f/packages/components/src/input-control/reducer/reducer.ts#L51-L58

This can be confusing for people writing reducers to be composed by this, because it diverges from "standard" reducer-composing functions like `wp.data.compose()` (aka Lodash `flowRight`) or Redux `compose()`.

I've long wanted to suggest `composeStateReducers` should be removed in favor of inline coupling of reducers. There's no instance of composing more than two at a time. Any reducer that allows extension can call the optional extending reducer as part of its process. I've tried such changes but figured it wasn't important enough to make a PR for it.
