## Body

![Screen Capture on 2021-01-28 at 16-14-19](https://user-images.githubusercontent.com/2322354/106201451-79afac00-6186-11eb-92fb-6e0016714ca4.gif)

This update adds a couple of low-level Form components for the [new Component System](https://github.com/WordPress/gutenberg/issues/27484), as part of https://github.com/WordPress/gutenberg/issues/28399

This 2 components are at the heart of creating form-based UI, such as those found with attribute controls / design tools:

<img width="227" alt="Screen Shot 2021-01-28 at 4 34 20 PM" src="https://user-images.githubusercontent.com/2322354/106201600-aebbfe80-6186-11eb-93df-089b8a5ac377.png">

Compatible components (coming soon) would automatically be bound with labels (as well as `htmlFor` ids for a11y).
This is done through the internal `FormGroupContext`, resulting in a very minimal component API setup that looks like this:

```jsx
<FormGroup label="First name">
    <TextInput />
</FormGroup>
```

The example above would automatically render a `label` and  a unique `id`. That `id` would then be bound between the `label` (via `htmlFor`) and the `<TextInput />`.

In the [next Component System](https://github.com/ItsJonQ/g2/tree/main/packages/components/src), **all form based components** are pre-connected to this `FormGroupContext`, allowing them to work out of the box with zero setup.
