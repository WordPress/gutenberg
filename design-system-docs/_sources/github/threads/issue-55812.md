## Body

### Description

The `NavigableToolbar` component implements the ARIA toolbar pattern, which comes with is own expectd keyboard interaction pattern.
When the preference 'Show button text labels' is enabled, the expected keyboard interaction appeears to be completely broken.

Expected:
- The ARIA toolbar has only one Tab stop.
- Right arrow key: moves focus to the next button.
- Left arrow key: moves focus to the previous button.
- Arrows navigation 'cycles' through the buttons.
- Home key: moves focus to the first button.
- End key: moves focus to the last button.

Actual with 'Show button text labels' enabled:
- On some buttons, it is necessary to press Right or Left arrows multiple times to move focus.
- Sometimes, some buttons are skipped.
- It appears to happen randomly.

I tested on WordPress 6.2 where it works as expected. It's broken starting from WordPress 6.3. Marking as a regression.
I'm not sure whether this comes from changes in the component or something in the block editor package.

It would be great to have E2E tests in place to test the keyboard interaction with all the editor UI states including 'Show button text labels' enabled.

### Step-by-step reproduction instructions

- Edit a post.
- Use the keyboard to navigate the ARiA toolbar i.e. the group of buttons that starts with the Inserter and ends with the Document Overview.
- Observe keyboard navigation works as described above.
- Go to Options > Preferences, and enable 'Show button text labels' .
- The ARIA toolbar buttons now display text instead of icons. Screenshot:

![Screenshot 2023-11-02 at 15 35 57](https://github.com/WordPress/gutenberg/assets/1682452/8ead50d0-96f2-4f21-a7e1-afdb971a0c5f)

- Test again keyboard navigation in the ARIA toolbar.
- Observe the keyboard navigation is broken in unexpected / unpredictable ways.
