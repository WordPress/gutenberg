# Issue #64588: Components: Standardize and document conventions around TypeScript type testing

- URL: https://github.com/WordPress/gutenberg/issues/64588
- Author: mirka
- Created: 2024-08-16T21:46:19Z
- Updated: 2024-08-16T21:46:20Z
- Comments: 0 of 0

## Body

## What problem does this address?

We have a slowly growing number of "unit tests" in the components package where the intent is to statically check the correctness of our TypeScript types when they are somewhat complex. It's a simple setup, but it's about time we standardize some conventions around this and document it in the contributing guide.

## What is your proposed solution?

Some [ideas](https://github.com/WordPress/gutenberg/pull/64412#discussion_r1715089804) from @tyxla:

> I wonder if we should start putting these type-checking pseudo-tests in a separate file under `/test` (types.tsx for example).
> 
> Then we could add a global ESLint disable rule for `jest/expect-expect` and we'll no longer have to do it every time.
