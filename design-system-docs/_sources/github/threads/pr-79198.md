## Body

## What?

See #77462 (point A5).

Adds `--wpds-color-stroke-surface-caution` and `--wpds-color-stroke-surface-caution-strong` so the `caution` tone has the same stroke coverage as the other status tones.

## Why?

`caution` had `background-surface-*` and `foreground-content-*` tokens but, unlike `success`, `info`, `warning`, and `error`, no `stroke-surface-*` tokens. This closes that gap.

## How?

Added the two tokens to `tokens/color.json` and regenerated the prebuilt files.

<details>
<summary>Details</summary>

The new tokens map to the existing `caution` primitives, mirroring the other tones (e.g. `warning`):

| Token | Primitive | Value |
| - | - | - |
| `--wpds-color-stroke-surface-caution` | `caution.stroke1` | `#cfc28d` |
| `--wpds-color-stroke-surface-caution-strong` | `caution.stroke3` | `#826a00` |

Only `tokens/color.json` is hand-edited; the remaining files are regenerated by `npm run build`.

</details>

### jasmussen on 2026-06-16T12:56:03Z

URL: https://github.com/WordPress/gutenberg/pull/79198#issuecomment-4718958055

To be short, I'm reluctant to revisit the Badge while Jay is out, as I'm certain he put a lot of thought into the precise structure. And to hesitate a guess, it's that really: color isn't necessarily that useful in denoting the urgency of something. If something is truly destructive or urgent or needing a fix, there are more potent mechanisms for getting someone's attention. And because you could have a badge that is between neutral and warning in its _power_. 

Ultimately these are just that, badges/chips that are utilitarian in the design you create, whether it's a product board that has an unfulfilled order, or a contrast issue in context of a block. There is an argument to be made that expanding the flexibility there, is useful. 

That said, the notice/warning/error trio has been on my mind lately as far as how the JS console denotes items, or how we might denote the same using a linting tool (i.e. #76996). In such an implementation, the implementation itself would need to specify the color/urgency of the badge, and the icon, in order to create those same three levels. And the badge can accommodate that, and more. 

Finally, there's [this helpful doc](https://wordpress.github.io/gutenberg/?path=/docs/design-system-components-badge-choosing-intent--docs), which captures the granularity reasonably well.
