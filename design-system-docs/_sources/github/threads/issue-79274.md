# Issue #79274: Components: Apply Button minimum width styles from UI component

- Created: 2026-06-17T12:33:12Z

## Body

## What problem does this address?

Button pairings where one label is much shorter than the other can create awkward design balance and risk deemphasizing the primary action.

For example, in the "Add Pattern" dialog, observe how the "Add" occupies much less space than "Cancel":

<img width="433" height="448" alt="Image" src="https://github.com/user-attachments/assets/b9230547-a473-4065-9b76-4c8878357ba7" />

Same in [the ConfirmDialog Storybook story](https://wordpress.github.io/gutenberg/?path=/docs/components-confirmdialog--docs) with "OK" vs. "Cancel":

<img width="377" height="173" alt="Image" src="https://github.com/user-attachments/assets/99f595aa-c58d-49cd-9c6b-b9976a2ef7cd" />

In #75133, we applied a minimum width to the new `Button` implementation in `@wordpress/ui` for this reason:

> For better UI balance, especially when buttons with very short labels are paired with button with longer labels

In turn, this creates a secondary problem where the styling between Buttons in `@wordpress/ui` and `@wordpress/components` is out of sync, where the intention is to keep them aligned to avoid inconsistencies when new and old components are used together on the same interface. This was [acknowledged in the original pull request](https://github.com/WordPress/gutenberg/pull/75133#issuecomment-3836083915), but at the time we chose to accept the divergence.

## What is your proposed solution?

We should apply minimum width styling to `@wordpress/components` Button component to align with `@wordpress/ui`.

Additional factors to consider:

- The `@wordpress/components` implementation is more complex in how it has baked-in behaviors for handling variations like an "icon button", and these will need to be handled in Button's own styles.
- While this should be a relatively "safe" change, we should do due diligence to review impacted styling in the interface. One example is the "Save" button in the editor toolbar and how this affects the layout of the header, though this should be fine since it already needs to adapt to longer button label text like "Publish".
