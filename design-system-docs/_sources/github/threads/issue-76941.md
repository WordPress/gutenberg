## Body

This issue serves as the iteration / tracking issue for planned stabilization of design system theming supports for WordPress 7.1.

This is part of overall design system efforts described in the overview issue: #71196

Expected outcome: External plugins and projects can start to use design system theming, including design tokens (CSS properties) and theming configurability exposed by `@wordpress/theme`'s `ThemeProvider` component.

**Update as of June 2026:**

**Overview:** This work is progressing nicely and I have high confidence it should be ready in time for beta 1. We already have [the pull request to mark the relevant APIs as stable](https://github.com/WordPress/gutenberg/pull/78958).

**Completed:**

In lieu of a changelog, the issue https://github.com/WordPress/gutenberg/issues/77462 is a best reference for where we've been focusing efforts in maturing theming in a broad sense. Not all of these are blockers. Checked items are those that are merged and considered complete.

**Blockers and open questions:**

Source: "Priorities" section of https://github.com/WordPress/gutenberg/issues/77462, specifically "block stabillization"

Remaining blockers:

- [ ] https://github.com/WordPress/gutenberg/issues/76840 (PR: https://github.com/WordPress/gutenberg/pull/78958)
- [ ] Drop --wpds-dimension-base from the public surface ("T-N1" from #77462, PR: #79254)

No open questions, though worth noting that a lot of our focus has been around general stability of the design tokens themselves (CSS properties), and the actual `ThemeProvider` component availability is a trivial change we can do at any point. The idea here being that CSS properties are a secondary public API that we expect plugin authors to use, so we need to finalize these ahead of the release and expect that we will not be able to make breaking changes from that point forward.
