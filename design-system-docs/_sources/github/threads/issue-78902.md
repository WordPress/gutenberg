# Issue #78902: Admin UI: support footers

- URL: https://github.com/WordPress/gutenberg/issues/78902
- Author: simison
- Created: 2026-06-03T09:13:19Z
- Updated: 2026-06-10T15:55:34Z

## Body

Parent issue: https://github.com/WordPress/gutenberg/issues/77628


Currently, it's complicated for consumers to add _sticky footers_ to pages and dashboards using `Page` component because it basically requires overwriting various pre-existing container styles in WP Admin and `Page`.

Sometimes implementation requires guestimating header+tabs implementation height, [like is done at WP Fonts page](https://github.com/WordPress/gutenberg/blob/f091de947bb46e331a52c9dd501e0a3644da9c64/routes/font-list/style.scss#L15-L17).

It's also possible to get it wrong, and a longer navigation sidebar with modified container styles can affect how sidebar dropdowns are positioned ([example](https://github.com/Automattic/jetpack/pull/44391)).

Here's how the Fonts page footer implementation looks:

https://github.com/user-attachments/assets/b401fa3a-89e7-42bd-aa14-0c0718169f6c

That page might not _need_ footer, but it's typical for plugin developers to add consistent footer in their plugin pages.

WordPress itself even has a footer, but currently, any WP Built page does not support the regular WP Admin footer, which may or may not be by design. :-) (cc @jasmussen you might know?)

<img width="2700" height="1414" alt="Image" src="https://github.com/user-attachments/assets/797256f9-af53-4ff9-821f-ade4effa9bbf" />

### Solutions

- At minimum, a canonical footer component which just allows inserting _any content_ to the footer, which then behaves correctly with [Page padding](https://github.com/WordPress/gutenberg/issues/78881), tabs, header sizes and so on.
- A core footer, injected into WP Build pages in WordPress
- A footer component, which is our visual recommendation of how the footer should look. Includes background color, padding, and border matching the header and thus getting updated when we change the header design.
