## What?
Resolves: https://github.com/WordPress/gutenberg/issues/49277

In this PR when we have the `Global Styles` panel open in site editor, the selected block opens the respective block type panel.

In order to do that without messing with writing flow, I've introduced a new navigate option(`skipFocus`). This way the focus is preserved on the block. 

I think such an option can be useful in similar cases, where we programmatically navigate to other screens in outside components. 

## Testing Instructions
1. In site editor open the Global Styles panel
2. select any block in the editor or through the list view

### jasmussen on 2023-05-03T08:25:41Z

URL: https://github.com/WordPress/gutenberg/pull/49350#issuecomment-1532635201

Bea brings up a great point. The feature here is really cool, but it does make it more likely that you style the wrong level of the block hierarchy — the block level — when you are very commonly better served with styling the top global/root level.

I wonder if there's a way to keep the basic behavior, without entirely reverting this feature. 

* Would it be fine to omit the paragraph from the inspector behavior? I.e. clicking a paragraph does not take you to the paragraph block. That seems to be the primary point of concern. Are there other blocks we might omit, like Heading?
* Could it be a double-click behavior to go there? 

One known problem we have is that it is not always obvious to a casual user that you have the _global styles_ inspector open, and not just the regular inserter. I've seen a user wanting to colorize a single paragraph on a page, then clicking the "Colors" button in Global Styles, because that was the last inspector they had open. A couple of options I've explored for making that split clearer is these two, the latter of which is a bit provocative and too crazy, but nevertheless represents a clearer split between the two inspector types:

If we were to implement something like this — just as a baseline, invoking the "focus mode" with the resize handles when global styles is open — could we then change the behavior of the blocks in the canvas, where perhaps the block toolbar simply had an "edit" button that takes you into the global styles → [block]? Or is that going too far?
