## What is your proposed solution?

As far as I know, no option exists to make the `DropdownMenuItemV2` color red. I imagine that something like the `isDestructive` prop of the button component could be used for these use cases.

## Issue comments

### mirka on 2024-04-25T10:48:08Z

URL: https://github.com/WordPress/gutenberg/issues/61079#issuecomment-2076897112

My gut feeling is to avoid adding `isDestructive` as a prop, since that can lead to prop bloat like we can see in the current [Button](https://wordpress.github.io/gutenberg/?path=/docs/components-button--docs) API. This is just a color variant, so ideally it would be done through a color-related API.

However, there is still a lot of uncertainty around how we want to deal with colors in a systematic way. The components package has an [experimental way](https://wordpress.github.io/gutenberg/?path=/docs/components-experimental-theme--docs) of doing that, based on CSS variables. But I know @SaxonF has also been working on a color token system.

For the time being, especially since DropdownMenuV2 is still private, I wonder if we should stick to directly overriding CSS variables from the consumer code, rather than adding a new API to DropdownMenuItem.

cc @DaniGuardiola

### ciampo on 2024-12-04T10:12:35Z

URL: https://github.com/WordPress/gutenberg/issues/61079#issuecomment-2516825028

FWIW, I would also be very cautious with adding props for the same reasons listed by @mirka  — especially if what differentiates a "destructive" item from a standard one is just the text color.

Until we have more clarity on a few aspects (theming, specs of destructive menu items), I would suggest applying the text color directly to `Menu.Item` or `Menu.ItemLabel`
