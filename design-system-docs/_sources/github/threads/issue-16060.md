### swissspidy on 2019-06-10T14:24:22Z

URL: https://github.com/WordPress/gutenberg/issues/16060#issuecomment-500435642

Gutenberg does not really do any type checking, and as such does not really contain a lot of "idiot-proof" checks that would unnecessarily bloat up the code. In this specific instance the component expects an array and it's up to you as a developer to provide the data in the right format.

Some projects leverage runtime type checking using [prop types](https://www.npmjs.com/package/prop-types), but that's currently not used in Gutenberg.

> And if so, isn't there a way to make this component accessible w/out having to count on an instanceID being supplied?

Not really. IDs are required for accessibility. But you don't have to pass an instanceID anyway. `withInstanceId` does that for you automatically.

### mikeybinns on 2024-03-25T10:38:01Z

URL: https://github.com/WordPress/gutenberg/issues/16060#issuecomment-2017695454

Components now exports types for the select control which may help with this, however they only accept "string" as an option value, with no way to narrow this, e.g. if used in a block, you may want to narrow the options to the possible values of an attribute.
We could improve the type-checking in TypeScript by allowing a generic for option value type, with a fallback if not provided to "string".
I'm happy to work on this as a PR and I'll link it to this issue when I've done it 🙂

Quick example of what I mean:
```tsx
type InterpretedAttributes = {
  size: "small" | "large";
}

<SelectControl<InterpretedAttributes["size"]>
  label="Block size"
  value={size} // can only be "small" | "large"
  options={[
    {
      label: "Small",
      value: "small", // can only be "small" | "large"
    },
    {
      label: "Large",
      value: "large", // can only be "small" | "large"
    },
  ]}
/>
```
