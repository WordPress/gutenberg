# Issue #75266: Theme: Elevation tokens should adapt to darker color palettes

- URL: https://github.com/WordPress/gutenberg/issues/75266

- Created: 2026-02-05T20:33:30Z
- Updated: 2026-06-22T12:25:44Z

## Body

Related discussion: https://github.com/WordPress/gutenberg/pull/75103#issuecomment-3848441002

## What problem does this address?

The current [design system elevation tokens](https://github.com/WordPress/gutenberg/blob/db3b37a28f9e548043c345620cae425be3667249/packages/theme/tokens/elevation.json) define a set of semi-transparent black shadows that can be used to create an elevated effect on surfaces. Because they are based on black, the effect may not be noticeable on darker background colors.

## What is your proposed solution?

The elevation tokens should adapt to the current theme color palette to ensure that the shadows provide a distinctive elevated effect. This could potentially mean even darker or inverted lighter shadows. 

Implementation-wise, this should probably be handled inside `ThemeProvider`, overriding the [default CSS properties](https://github.com/WordPress/gutenberg/blob/db3b37a28f9e548043c345620cae425be3667249/packages/theme/src/prebuilt/css/design-tokens.css#L118-L125) generated from the theme tokens with updated values tailored to the current theme color palette.

**Needs Design:** How should we convey elevation for elements which are displayed on top of dark background content?

### ciampo on 2026-06-16T14:19:39Z

URL: https://github.com/WordPress/gutenberg/issues/75266#issuecomment-4719768538

Let's not forget that in `@wordpress/theme` (and through its related tokens) there's no clear concept of a "dark theme"; consumers can pick any color as the background seed, and the internal theme engine determines whether the color ramps should get darker or lighter depending on what direction gives the highest available "lightness range".

As such, we need to have a systematic approach — it may not be simple to "remove shadows for dark themes".
