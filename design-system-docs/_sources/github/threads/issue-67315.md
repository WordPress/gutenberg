## Body

The [DataViews page in Storybook](https://wordpress.github.io/gutenberg/?path=/docs/dataviews-dataviews--docs) includes many nice examples, but there's no guidance around how the component and its various features should be used.

### Layout

I've seen this play out recently in some confusion around how to use the different layout types. 

I’m thinking it could be beneficial to document the high-level purpose for each DataViews layout so we have something to refer to when these discussions come up. This can also help guide consumers around whether or not to support a particular layout, and the inclusion of any new features.

Here’s a quick draft:

- List: Optimized for browsing, selecting and performing actions on a single record.
- Table: Data-centric, structured in rows and columns, optimised for applying bulk actions/edits.
- Grid: Optimized for managing records that are generally visual in nature (e.g. Media).

- [ ] Document layout

### More

There is much more to DataViews than layout. Configuration of fields and view options, filters, and so on, should also be documented.
