# Issue #73360: Theme: Add support for density configuration

- Updated: 2025-11-20T18:51:24Z

## Body

Sub-issue of #71196

## What problem does this address?

Some components (e.g. `Card`, `DataView`) support configurable spacing aspect, allowing the consumer to control the density with which the information is presented. This usually affects spacing aspects like padding, row height, gaps, etc. 

The current approach is rather limited:

- The implementation is limited to each individual component, and there are no guarantees that the APIs and behaviors are consistent between components
- This puts the responsibility on the consuming developer to handle, rather than providing good, context-aware default behaviors

A design system should seek to unify these spacing behaviors across components and make the system more predictable and maintainable, without embedding layout logic in individual components.

## What is your proposed solution?

Introduce density configuration as a theme-level option, applied through the existing `ThemeProvider` in the `@wordpress/theme` package.

As with color configuration, density should be applied through the use of semantic design token values. These semantic tokens should be named in consistent human-readable terms (e.g. "small", etc.), and internally map to a set of private, primitive values based on a base scaling convention (e.g. `space-10`, etc.).

Implemented this way, a component with "small" spacing would have its effective spacing affected by the closest `ThemeProvider` that has a configured density (if one exists).
