## What?

Simplifies how we coordinate focus styles in the `InputBase` primitive component so it can be done "automatically" with just CSS, without relying on React props/state.

No visual/behavioral changes are intended.

## Why?

InputBase is an internal component used to style the standard borders for an input, as well as handle the layout for prefix/suffix elements.

I'd like to reuse InputBase for styling CustomSelectControlV2, like we currently do with v1. This is a good opportunity to simplify this focus handling in there, lest we add even more unnecessary state management.

## How?

Use `:focus-within` selectors to detect inner focus declaratively, rather than keeping track of it imperatively through focus/blur listeners.

## Testing Instructions

There shouldn't have been any visual changes in focus behavior.

### Affected components worth testing

- InputControl — Also test with the `disabled` prop enabled.
- CustomSelectControl (v1) — Given the non-trivial changes in this one, it should be tested in the editor as well, for example the Appearance dropdown in the block inspector Typography tools, or the Position dropdown in the block inspector of a Row block.
- UnitControl — When focus moves to the unit selector dropdown, the focus indicator should also move there.
- SearchControl — Uses the borderless variant of InputBase.
- ColorPicker — The color format dropdown (Hex/RGB/HSL) uses the borderless variant of InputBase.

### Affected but low chance of regressions

- NumberControl
- SelectControl
- TreeSelect

#### Affected through style overrides of relevant elements

- The time input fields in TimePicker
- The color name input field when in Edit mode of PaletteEdit

### Testing Instructions for Keyboard

Test <kbd>Tab</kbd> and arrow keys to navigate elements, especially UnitControl and CustomSelectControl (v1).
