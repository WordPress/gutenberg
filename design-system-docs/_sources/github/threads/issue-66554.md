### ptesei on 2024-11-09T08:24:51Z

I agree with @jameskoster from the accessibility point of view, adding an extra element of distinction is a best practice. And also it will look familiar to the "legacy" users ^^
I'm not a big fan of font weight changes because it changes the width of the text and in some cases with long titles can cause the text to wrap on multiple lines.

![Image](https://github.com/user-attachments/assets/ddcb9ae1-04f3-45cd-ae51-643d09cac83c)

![Image](https://github.com/user-attachments/assets/e16d189a-905c-4685-b8e5-3eeffb06dda1)

Here some A11y guidelines: 

https://www.w3.org/WAI/WCAG21/Techniques/failures/F73
Check that each link in the page that is identifiable by color (hue) is visually identifiable via some other means (e.g., underlined, bolded, italicized, sufficient difference in lightness, etc).

https://accessibility.huit.harvard.edu/technique-accessible-current-page-indication
So it's important to use an additional means to differentiate the "active" link. One way would be to provide an additional underline.



The other approach is to go in the opposite direction. In the gurenberg UI many selected items look like buttons. 
For example:
- current selected block
- current content
- current style

The left border does not match any other pattern the editor uses, so I would not support doing that. Semibold text can work well and is common practice in similar cases.
