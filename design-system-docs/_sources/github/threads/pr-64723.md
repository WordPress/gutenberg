Ideally, I'd like to find ways for consumers of the component to achieve the desired behaviour without the need for the `store` (or any store state / store methods). This could be mostly achieved by using the `Composite` component in controlled mode specifically to certain props (like `activeId`) — after all, that's how other ariakit-based components work too.

For example:

- [need to reset the active id](https://github.com/WordPress/gutenberg/pull/64723#discussion_r1727757331)? Instead of calling `store.setActiveId()`, just control the `activeId` prop on `Composite`
- [need to focus the first composite item](https://github.com/WordPress/gutenberg/pull/64723#discussion_r1727771015)? You can grab a ref to it and explicitly call `elementRef.current.focus()` and, if needed, set the `activeId` prop on `Composite`
- [need to select a new item when the current one is removed from the list](https://github.com/WordPress/gutenberg/pull/64723/files#r1728790178)? Hopefully, that could also be done with some custom logic + controlling the `activeId` prop

I'll see if I can apply these ideas into practice in this PR
