# Issue #76221: Replace `cursor: pointer` usage with design token

## Body

The `--wpds-cursor-control` token (added in #75697) allows the cursor style for interactive non-link controls to be configured via the design system. All instances in the codebase should be replaced with this token so a global switch is possible.

### mirka on 2026-04-14T12:47:13Z

URL: https://github.com/WordPress/gutenberg/issues/76221#issuecomment-4243980744

Great question. The initial approach at the moment is that we don't actually have the tokens defined globally yet, and instead we just inject fallback values at build time in wp-build (turning `var(--wpds-cursor-control)` into `var(--wpds-cursor-control, pointer)`)! We'll start loading global token stylesheets at a later time.

So what you're seeing is expected, don't worry about it 👍

### mirka on 2026-04-15T12:22:20Z

URL: https://github.com/WordPress/gutenberg/issues/76221#issuecomment-4251938773

> I do have one more question here, since the tokens are not defined globally yet, so how `@wordpress/components` packages defines those variables? as we see in storybook, when checking the components we have the variables present and chaging it from the theme works as expected, or is it just for the storybook context (which I don'nt think would be).

That part is Storybook-specific.

For `components-*` stories, Storybook wraps them with a `ThemeProvider`, so the `--wpds-*` variables are available there and the theme toolbar can change them. That is why you can see the variables in Storybook even though we are not yet loading the design token stylesheet globally in normal package/runtime contexts.
