## Body

## What?

Resets `will-change` from `transform` to `auto` once a popover receives the `.is-positioned` class.

## Why?

On Chrome with certain GPU/driver combos, keeping `will-change: transform` active after the popover is placed causes the browser to render popover contents on a blurry compositing layer. Multiple contributors confirmed this on macOS/Chrome and Windows/Chrome.

Fixes #76899

## How?

One CSS rule — `.components-popover.is-positioned { will-change: auto; }`. The `.is-positioned` class is already applied after placement finishes, so this only drops the compositing hint once the popover is in its final spot. The initial `will-change: transform` still helps avoid repaint during the opening animation.

## Testing Instructions

1. Open WordPress Playground: https://playground.wordpress.net/?php=8.3&wp=beta
2. Create a post, add a block, open any popover (e.g., block settings, link editing).
3. **Before this PR**: popover contents may appear blurry (especially on Chrome).
4. **After this PR**: popover renders sharp.

### Kgupta62 on 2026-04-19T10:06:21Z

URL: https://github.com/WordPress/gutenberg/pull/77359#issuecomment-4275676702

@aduth t-hamano's comment was about the issue existing since WP 6.7, which predates any `will-change` changes — so `will-change: transform` isn't the *root* cause, it's a Chrome/GPU rendering glitch. But resetting it after positioning consistently fixes the symptom.

From the thread:
- @Mamaduka confirmed on macOS/Chrome that disabling `will-change: transform` improves rendering
- @ktmn confirmed `.is-positioned { will-change: initial; }` fixes it on Windows/Chrome, and the issue doesn't repro on Firefox
- @ciampo could reproduce the blurriness and confirmed removing `will-change` fixes it

The `will-change: transform` hint only helps during initial positioning anyway — once `.is-positioned` is applied, keeping it active just forces the browser to maintain a separate compositing layer for no reason. So this is the right thing to do regardless of the blurriness bug.

I've also added a CHANGELOG entry per ciampo's request.
