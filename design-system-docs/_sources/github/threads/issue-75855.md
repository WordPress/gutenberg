It seems like `FormTokenField` and `SelectControl` would _already_ be prone to this, since the `line-height` already existed in these form styles (and inherited into the component styles), just that the value was changed.

### mirka on 2026-02-25T08:04:25Z

URL: https://github.com/WordPress/gutenberg/issues/75855#issuecomment-3957504885

Unfortunately I'm seeing a lot of breakage (not necessarily due to the [recent changes](https://core.trac.wordpress.org/changeset/61645)) in `@wordpress/ui` components due to the `common` and `form` stylesheets. It's unfortunate that we not only have to continue working with these wildly overscoped styles being loaded everywhere, but that we are going to continue changing them, which can alter all our UIs (not just first-party component libraries) in unexpected ways. This is not very sustainable.

Aside from making hot fixes on the `@wordpress/components` side for 7.0, I wonder if we can add an opt-out scope to these `common`/`form` stylesheets? For example:

```css
:where(:not([data-no-forms-css])) {
  /* The current content of forms.css */
}
```

Otherwise, placing them in an `@layer` may also mitigate specificity issues.

Without either of these, it's going to be a nightmare to counteract within `@wordpress/ui` (mostly because we are placing styles in `@layer`s — these will always lose to the unlayered styles in common/forms.css).
