# Issue #42699: NumberControl accepts non-numeric values in Firefox

## Body

### Description

[NumberControl](https://wordpress.github.io/gutenberg/?path=/story/components-experimental-numbercontrol--default) accepts non-numeric values in Firefox.

### Step-by-step reproduction instructions

1. Start Firefox
2. Open the [storybook link for NumberControl](https://wordpress.github.io/gutenberg/?path=/story/components-experimental-numbercontrol--default)
3. Try in non-numeric values
4. Repeat the above steps in Chrome

NumberControl accepts non-numeric inputs in Firefox, while not in Chrome (which should be the expected result for Firefox too)

I can reproduce those instructions on Windows 10 Firefox. It looks to me like this is an [implementation bug in Firefox](https://bugzilla.mozilla.org/show_bug.cgi?id=1398528) for `<input type="number">` rather than a problem with the component.

### mrwweb on 2022-07-28T22:56:40Z

URL: https://github.com/WordPress/gutenberg/issues/42699#issuecomment-1198705424

If you read the linked bugzilla thread, there's disagreement over the correct implementation and it seems like Safari, at least at the time, was as bad or worse (could someone test that)?

MDN (somewhat ironically!) [flags the issue](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input/number#using_number_inputs):

> Warning: Logically, you should not be able to enter characters inside a number input other than numbers. Some browsers allow invalid characters, others do not; see [bug 1398528](https://bugzilla.mozilla.org/show_bug.cgi?id=1398528).

I see no momentum on the upstream issue, so if enough people feel like it degrades the block editor experience, it feels like this could be worth trying to smooth over. On the other hand, it's not obvious how to solve it given that decimals, commas, and other characters might be considered valid.
