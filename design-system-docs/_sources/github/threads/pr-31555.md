## Description
Shortcut previously did not support the `as` prop that all `ViewOwnProps` components support. This fixes that. To do so we have to cast `View` to a `PolymorphicComponent` because `Emotion`'s `as` prop doesn't work correctly with the types (it doesn't give you the correct types for the component when you pass `as`)

## How has this been tested?
Unit tests continue to pass and usages of Shortcut can now correctly use the `as` prop.

It's used for component interpolation, so for the following:

```js

const Text = createComponent( { useHook: useText, name: 'Text, as: 'span' } );

const Wrapper = styled.div`
  ${ Text.selector } {
    color: blue;
  }
`;
```

Because the Emotion babel plugin only supports interpolating styled components, we needed this workaround to be able to fake interpolation of components that are part of the component system but outside of styled components.

The reason it's forced to be a class based selector is because it's dependent on the automagically generated classes that are added to components when they're run through `useContextSystem`. That same class is applied as the `selector` value by `contextConnect`. It follows the format of `components-component-name` which is the pre-established pattern in the `@wordpress/components` package.

Making it the same type as `Parameters<typeof document.querySelector>` I think would be misleading, considering it's an auto-generated property. I think encoding it as specifically a class-based selector makes sense given the use case.

Where do you think this information would be best saved? I'm happy to add some documentation around it but it's sort of an internal thing rather than something we wanted to expose publicly.
