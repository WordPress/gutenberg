To allow it to be used.


## Testing Instructions
In a react component add:

```

    return (
```

### ciampo on 2023-09-13T13:03:30Z

URL: https://github.com/WordPress/gutenberg/pull/54404#issuecomment-1717592326

Hey folks, I have a couple of comments:

- Let's not export components anymore with the `__experimental` prefix, since it has been determined that code merged into WordPress core can't be assumed as experimental, regardless of naming conventions. A couple of alternatives:
  - If we feel that the component is still experimental, we should instead use the lock/unlock APIs ([example](https://github.com/WordPress/gutenberg/blob/162eb4b561b7f5ccc6da6f8c5e32ebd722f779f5/packages/components/src/private-apis.ts))
  - Otherwise, if the component is mature enough, we could export it without the additional `__experimental` prefix
- the CHANGELOG entry should always be under a sub-section (in this case, `### Experimental` if we keep the component as an experiment, or otherwise `### New feature`)

Hey @tyxla , since you worked on the component, do you have a feeling on whether we should consider it as experimental or not?

Nevermind my previous comment, I have just noticed that `ProgressBar` is indeed [already exported via private APIs ](https://github.com/WordPress/gutenberg/blob/162eb4b561b7f5ccc6da6f8c5e32ebd722f779f5/packages/components/src/private-apis.ts#L50) and [used in other parts of the editor](https://github.com/WordPress/gutenberg/blob/2af5a244678f1e191b43ba8d03530ea5b6c27690/packages/edit-site/src/components/canvas-loader/index.js#L15).

I will therefore open a new PR reverting the changes from the current one.

Please let's be careful in the future when exposing new APIs from the package (and approving such changes); given the WordPress strict backwards compatibility policy, it's really hard (if not impossible) to undo such changes.

In case the current way of consuming the `ProgressBar` was somehow not enough, let's discuss in a separate issue.
