## What?
<!-- In a few words, what is the PR actually doing? -->
Follow-up for #43206.

Two packages used pinned versions for npm dependencies. Let's relax that requirement to let 3rd party projects use any further bug fixes for those packages.

## Why?
<!-- Why is this PR necessary? What problem is it solving? Reference any existing previous issue(s) or PR(s), but please add a short summary here, too -->

3rd party project aren't be able to install newer version of pinned dependencies even when critical bug fixes would get released. It's a good practice.

## How?
<!-- How is your PR addressing the issue at hand? What are the implementation details? -->

Add `^` sign to the dependencies defined in `@wordpress/components` and `@wordpress/block-library`.
