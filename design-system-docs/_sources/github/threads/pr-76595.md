## Body

## What?
Closes https://github.com/WordPress/gutenberg/issues/72433

## Why?
When we switch the gradient type in color picket from linear to radial and then back to linear the selected angle in linear resets.

## How?
Add logic to memoize the last angle selected.

`lastLinearOrientation` is initialized from `gradientAST.orientation` via an `as AngularNode` cast. For radial gradients, `orientation` can be an array / non-angular value (see `serializeGradientOrientation` explicitly handling `Array.isArray( orientation )`), so this ref can end up holding a value that’s not a valid linear-gradient orientation.

To keep this type-safe (and avoid odd behavior if the picker ever needs to handle additional gradient AST shapes), initialize the ref with a known angular node and only copy from `gradientAST.orientation` when it’s a non-array angular node (or store just the numeric angle in the ref and rebuild an angular node when switching back to linear).

This PR introduces a subtle behaviour change: before this PR, switching from radial → linear for the first time used `HORIZONTAL_GRADIENT_ORIENTATION` (90°, i.e. left-to-right). With the new code, the fallback is `DEFAULT_LINEAR_GRADIENT_ANGLE` (180°, i.e. top-to-bottom).

- change the code to restore the original behaviour;
- document it explicitly in the changelog
