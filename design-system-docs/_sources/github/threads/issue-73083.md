# Issue #73083: Padding controls behave inconsistently with fractional pixels

## Body

### Description

The editor padding controls (BoxControl?) rounds fractional pixels - enter 14.8 and it'll change it to 15 on blur. However if you first change the units and then set them back again to pixels it will allow the fractional pixels to remain. 

tl;dr:
 * The rounding behaviour is only applied on blur
 * The validation message is subtle and hardly likely to be seen

### Step-by-step reproduction instructions

1. In the site editor select a block that supports dimensions / padding
2. Under Dimensions → Padding in the block sidebar, press the button to allow manual value entry
3. Enter a value in fractional pixels e.g `3.14`
4. Tab out - note the value is reset to `3`
5. Click `px` and change the units to `em`
6. Enter 3.14 again
7. Change the units back to px, note it says `3.14`
8. Hover over the input and it will tell you 3.14 is an invalid value.
9. Hit save and reload, note the `3.14px` is preserved
10. Click inside the input and click out again, note the `3.14` is rounded to `3`

(Personally leaning towards the latter — it should be much simpler to work with, design-wise.)

### jasmussen on 2025-11-12T12:59:52Z

URL: https://github.com/WordPress/gutenberg/issues/73083#issuecomment-3521824720

Whether it matters or not, I'm instinctively leaning towards not being too smart with our componentry here. I.e. unless fractional values simply don't work, it seems simplest to just avoid any rounding. I ccould be missing nuance.

If a value is rounded up by the browser, it's handled gracefully and transparently, whereas if we are too smart about our rounding features, we may end up simply frustrating people who want a 3 digit em value, as well as build up complex unit rounding heuristics. And specifically in the case of em-based values, I've seen some typescales that end up with 3 digit values organically, even if the rendered result will never have that granularity.

### mirka on 2025-11-18T13:59:14Z

URL: https://github.com/WordPress/gutenberg/issues/73083#issuecomment-3547767050

One nuance here is that the rounding behavior is not  _strictly_ for validation, it can also be considered a side effect of wanting an appropriate [stepping behavior](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/step) when using up/down arrow keys to change the number values. It's possible that no one ever even wanted to enforce validation — we just wanted appropriate stepping behavior.
