### jasmussen on 2019-09-30T09:11:15Z

URL: https://github.com/WordPress/gutenberg/pull/17645#issuecomment-536474694

<strike>Okay, so it seems the need for the explicit aria-disabled specificity may be the right approach after all. There are use cases where we need a Button that is `aria-disabled`, but not `disabled`. In those cases, we want to keep the code relatively simple, without having to create too long selectors to account for active, hover and other states. Doubling the selector accomplishes that.

It still means we need to test this as well as we can, with as many different plugins as we can. </strike>

See https://github.com/WordPress/gutenberg/pull/17645#issuecomment-536475651

### jasmussen on 2019-09-30T09:13:38Z

URL: https://github.com/WordPress/gutenberg/pull/17645#issuecomment-536475651

So, actually. I just changed it to this:

```
		&:disabled,
		&:disabled:active:enabled,
		&[aria-disabled="true"],
		&[aria-disabled="true"]:enabled, // This catches a situation where a Button is aria-disabled, but not disabled.
		&[aria-disabled="true"]:active:enabled {
```

This seems to work well. And it is more specific to the use case in question, so it's less likely to catch all sorts of plugins and customizations. I actually feel quite a bit better about this one, and it appears to accomplish the same. 

I suppose that makes this one ready for final review!
