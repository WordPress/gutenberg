# PR #67000: SlotFill: fix a bug with storing stale fillProps

## Body

Fixes a `SlotFill` bug where a slot is sometimes rendered with old stale `fillProps`. It's described and discussed here: https://github.com/WordPress/gutenberg/pull/65907#issuecomment-2461140952. In short, the `updateSlot` method needs to check a `ref` value to determine if it's still the current registered slot. When an old slot is unregistered and new slot is registered, there is a short period of time where both are semi-registered and special care is needed.

The `updateSlot` method is used in the `Slot` component. Called on every render, in a effect without dependencies, to make sure that the latest `fillProps` is always synced promptly to the registry.

The bug being fixed is triggered when, for any reason, the `Slot` is rerendered one more time before unmounting. Then `updateSlot` would store a stale `fillProps` value at a time when a new `Slot` is already being mounted. The `unregisterSlot` method already has exactly the same `ref` check.
