# Issue #65102: Modal: Update size and positioning of Close button

- URL: https://github.com/WordPress/gutenberg/issues/65102
- Author: mirka
- Created: 2024-09-05T19:18:55Z
- Updated: 2024-11-05T14:06:38Z
- Comments: 5 of 5

## Body

## What problem does this address?

Currently, the Modal component renders a Close button in the old 36px size, and at a slight offset relative to the modal content width.

<img src="https://github.com/user-attachments/assets/71a60fac-79ca-43ea-9f5d-c9420bb7bbb0" alt="Modal header" width="610">

In accordance with the new sizing scheme, we need to change the button size to either the 40px or 32px variant.

## What is your proposed solution?

- I think the 32px variant (`"compact"`) would be the better fit for this use case.
- Should we reconsider the offset as well? I feel like it could be flush with the content width and not be weird, especially with the more compact size.

Pinging @WordPress/gutenberg-design for direction, and to note that I'm seeing somewhat conflicting mockups around the modal close button in the Figma ([Buttons exploration](https://www.figma.com/design/804HN2REV2iap2ytjRQ055/Core-System-Library?node-id=3174-20995&t=dcIIokBYsEnz4ivg-4) that explicitly uses a 40px variant, and the [Modal](https://www.figma.com/design/804HN2REV2iap2ytjRQ055/Core-System-Library?node-id=2036-43132) mockups that use a raw icon and not an actual Button component).

---

When implementing this change, remember that this has consistency implications with buttons that can potentially be in the `headerActions` slot next to the close button. This may warrant a Dev Note. In Gutenberg, there are some Modals that inject a "Fullscreen mode" icon button here, so we'll need to update the sizes for that accordingly.

One easy way to achieve alignment is to use a title line-height that matches the button size, and apply equal padding to the modal itself. 

As an example this is `24px` padding, `small` button, and a title with `24px` line-height ('Heading XL' according to the proposal in https://github.com/WordPress/gutenberg/issues/64340#issuecomment-2293705925):

<img width="569" alt="Screenshot 2024-09-06 at 15 30 10" src="https://github.com/user-attachments/assets/eaaf28ce-2d33-4036-beff-87d80d9956b6">

I'm unsure about tap target requirements as it's often easier to close modals in other ways; 'Cancel' button, press <kbd>esc</kbd>, click outside the modal.

One other detail is to avoid overlap between text in a title-less modal and the close button. Though that perhaps falls into `ConfirmDialog` territory and may warrant a different design.

As noted in https://github.com/WordPress/gutenberg/issues/66277

I disagree with the change in https://github.com/WordPress/gutenberg/pull/65131 as it makes the X close button target size unnecessarily too small. The 32px variant would have been better.

I have to note that the target size is an important accessibility feature and neither this issue nor the related PR https://github.com/WordPress/gutenberg/pull/65131 have any `accessibility` label or any consideration about potential impact on accessibility, which is, honestly, disappointing.

I will propose to change this size to 32 pixel  in https://github.com/WordPress/gutenberg/issues/66277. For the future, I'd like to suggest to refrain from making changes that introduce, de facto, a reduced level of accessibility without discussing it with specialists. This process is far from ideal as we'll need now to change it again in a future release and publish one more dev note and ask extenders to adapt again. Thanks.
