## Body

## What?

Fixes #75855 

Updates `SelectControl` and `FormTokenField` components to explicitly specify their own `line-height` styles, to avoid inheriting [base form CSS values](https://github.com/WordPress/wordpress-develop/blob/trunk/src/wp-admin/css/forms.css) which recently changed in Core's [r61645](https://core.trac.wordpress.org/changeset/61645), causing visual regressions in some combinations of these components.

## Why?

Restore original intended appearance of these components.

## Testing Instructions

Review Storybook stories of affected components, specifically reviewing variants, as well as visual styles applied under the styles toolbar dropdown ([see screenshot](https://github.com/user-attachments/assets/7f41ef7d-75e7-4e03-9597-da663ae5d481)):

1. Run `npm run storybook:dev`
2. Go to http://localhost:50240/?path=/story/components-selectcontrol--default&args=size:small&globals=css:wordpress
3. Observe that select option label is centered correctly
4. Go to http://localhost:50240/?path=/docs/components-formtokenfield--docs&args=size:small&globals=css:wordpress
5. Observe that the token field container is 40px tall

Compare against live versions in https://wordpress.github.io/gutenberg/ to see differences.

I went with `line-height: 1.2` to try to get the best of all worlds:

- Large enough to avoid descender clipping

As [noted above](https://github.com/WordPress/gutenberg/pull/75880#discussion_r2855067849), `line-height` has no effect here, but if it did, we'd still want our `line-height` to take precedence over `forms.css`.
