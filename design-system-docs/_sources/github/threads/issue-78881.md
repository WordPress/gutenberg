## Body

Parent issue: https://github.com/WordPress/gutenberg/issues/77628

The current version of the `Page` component supports regular mode with padding, and the "no padding" component prop `<Page noPadding />`.


Currently, plugins and Gutenberg itself implement settings pages in various ways. Examples: [AI settings](https://github.com/WordPress/ai/blob/7edda9c2f1a70ad7982ee537a120ffc2ce1932d0/routes/ai-home/style.scss#L1-L6), [Gutenberg experiments](https://github.com/WordPress/gutenberg/blob/f091de947bb46e331a52c9dd501e0a3644da9c64/routes/experiments-home/style.scss#L3-L7), [Gutenberg connectors](https://github.com/WordPress/gutenberg/blob/f091de947bb46e331a52c9dd501e0a3644da9c64/routes/connectors-home/style.scss#L7-L12) and as a 3rd party plugin example [Jetpack Newsletter settings](https://github.com/Automattic/jetpack/blob/71a4bcabcdcc6fe30fd89755cc93103790183930/projects/packages/newsletter/src/settings/style.scss#L55-L57). Since these pages are often built with similar components (DataForms, UI Cards, etc), it would make sense to have something that helps them stay more consistent.

The containers should take into account any other features of the Page, such as footers, tabs, depending a bit on how we design APIs for those features. See [overview issue](https://github.com/WordPress/gutenberg/issues/77628) for more.

_Note that this is a draft for discussion, not a final spec._

## Mixed

Sub-components can be freely mixed, too. Full bleed adapts to bottom/top margins automatically, then.

```jsx
<Page>
    <Page.FullBleed>
        Full page Banner
    </Page.FullBleed>
    <Page.Narrow>
        Settings
    </Page.Narrow>
    <Page.FullBleed>
        Full page Banner
    </Page.FullBleed>
</Page>
```
