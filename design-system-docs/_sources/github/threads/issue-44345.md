## Body

## What problem does this address?

TypeScript is throwing an error because experimental features are not exported by `@types/wordpress__...` packages. Are there any plans to support experimental feature types, or should we not use them?

`TS2305: Module '"@wordpress/components"' has no exported member '__experimentalNumberControl'.`

## What is your proposed solution?

Ideally, experimental features would also be added to the types packages.

Can be suppressed with `// @ts-ignore`

### mirka on 2022-10-14T11:53:47Z

URL: https://github.com/WordPress/gutenberg/issues/44345#issuecomment-1278903427

Good question! The fact that NumberControl isn't included in `@types/wordpress__components` is not intentional, as far as I know. I think you could even submit it to the [DefinitelyTyped repo](https://github.com/DefinitelyTyped/DefinitelyTyped/tree/master/types/wordpress__components) if you wanted to. I don't think anybody is actively making sure that the WP packages types on DefinitelyTyped are up to date, and so they're always quite unreliable.

The reliance on DefinitelyTyped is just a stopgap until we get to a point where we can officially ship the type data with the Components package itself. We're actively working towards that goal (#35744), and we're getting closer. Basically we need to finish typing every component left in this [exclude list](https://github.com/WordPress/gutenberg/blob/569241a3e1b7d0cc0567fccb92b1b57eb1b5b9c5/packages/components/tsconfig.json#L43-L77).

Whether or not you _should_ use experimental components is a different matter — you're free to use it as long as you understand that there are no guarantees around breaking changes 🙂
