I really wanted to do this! 😅

If you use a conditional type TypeScript doesn't allow you to `return useSelectControl ? ... : ...` because it doesn't know the value of `useSelectControl` at compile-time.

If you use an overload then TypeScript doesn't allow you to call `getFontSizeOptions( shouldUseSelectControl )` ([here](https://github.com/WordPress/gutenberg/blob/b3f0881f5902dc9a2a7b5469ce8c901ae059baee/packages/components/src/font-size-picker/index.tsx#L101)) because it doesn't know the value of `shouldUseSelectControl` at compile-time.

My third idea was to rely on narrowing because although TypeScript doesn't know the value of the boolean at compile-time it, in theory, could infer it based on what branch in `if( shouldUseSelectControl ) { ... } else { ... }` we're in. For this the language gives you [type predicates](https://www.typescriptlang.org/docs/handbook/2/narrowing.html#using-type-predicates) but unfortunately they can only be used as a return type, not a param type.

To be honest I think we should just not use a param here at all and instead have two separate functions. I wanted to limit this PR to only adding types, though, so will do that as a follow-up.
