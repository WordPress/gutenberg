# Issue #73424: DataViews button interactions feel slightly "laggy"

- URL: https://github.com/WordPress/gutenberg/issues/73424
- Author: fabiankaegy
- Created: 2025-11-19T07:43:54Z
- Updated: 2026-03-12T13:55:19Z
- Comments: 15 of 15

## Body

As I've been using the DataViews more and more recently I cannot shake the feeling that the UI interactions (mostly dropdown openings) feel somewhat laggy.

I've added a video below what tries to capture what I am seeing. (In the video you can see the moment I clicked via the circle that appears by the cursor. And there is a clear delay between the click and when the dropdown renders)

https://github.com/user-attachments/assets/43a7164e-4cfe-48ba-8b0b-4b2cd681a25e

To me this makes the UI feel like there is something wrong. Like my device is struggling to keep up because there are a few too many milliseconds between my actually triggering the click to the actual dropdown appearing. 

I'm not sure if it is just the enter animation timing or if there is something else happening here. But it does feel like laggy resource intensive old JS used to feel. 

And given how crucial this UI will be for modern WP I though to bring it up :)

Agree on the animation, this has bugged me for a while as well!

The menu click behavior is a bit tricky. The interaction you describe already exists in some components and can be a bit problematic. For example in the block inspector; if you open the color swatch popover then click on the canvas to dismiss it, that click passes though and you often end up unintentionally selecting a different block which causes the entire inspector to change. It's not a great experience imo. Similarly, in the DataViews case clicking outside a menu can result in selecting a row in table layout, or navigating in grid layout if you click on a thumbnail. This may not be ideal? I'm here for either approach, it definitely feels more responsive when the menu isn't modal, but we should be aware of the trade-offs.

Maybe it's a detail to discuss in a dedicated issue that considers wider `Menu` usage, in case we want to be consistent across.
