### 1. Add the committed patch — `patches/storybook+10.2.17.patch`
Generated the canonical way: edit `node_modules/storybook/dist/manager/runtime.js`, then `npx patch-package storybook`. Two minimal hunks:
- `searchItem` gains a synonyms string sourced from the global:

```js
var searchItem = (item, ref) => ({
  ...item, refId: ref.id, path: getPath(item, ref),
  synonyms: ( globalThis.__WP_DS_SYNONYMS__?.[ item.title ] ?? [] ).join( ' ' ),
});
```

- Fuse keys add a `synonyms` key (weights must total <= 1; runtime throws otherwise):

```js
{ name: "name", weight: 0.6 }, { name: "path", weight: 0.2 }, { name: "synonyms", weight: 0.2 }
```

### 2. Delete the mutation script
Remove [storybook/scripts/patch-manager-search.mjs](storybook/scripts/patch-manager-search.mjs). The runtime no longer needs the dual-pattern "already patched?" logic, the post-build re-patch of `sb-manager/runtime.js`, or the `console.warn` fallback.

### 3. Repurpose the collector to emit JSON (and address aduth's note)
Change [storybook/scripts/collect-ui-story-synonyms.mjs](storybook/scripts/collect-ui-story-synonyms.mjs) to **write** `storybook/synonyms.generated.json` instead of exporting for the patcher. While here, source files from the same globs `main.ts` uses rather than hard-coding `packages/ui/src` + `.story.tsx` (aduth's review point).

### 4. Wire data through the supported manager entry
In [storybook/manager.js](storybook/manager.js):

```js
import synonyms from './synonyms.generated.json';
globalThis.__WP_DS_SYNONYMS__ = synonyms;
```

(esbuild manager build handles JSON imports; `manager.js` already imports local `badges`/`sidebar`/`theme`.)

### 5. Update scripts in `storybook/package.json`
Run the collector before dev/build; drop the post-build patch call (postinstall handles the vendor patch):

```jsonc
"storybook:build": "node ./scripts/collect-ui-story-synonyms.mjs && NODE_OPTIONS=--max-old-space-size=8192 storybook build -c . -o ./build",
"storybook:dev":   "node ./scripts/collect-ui-story-synonyms.mjs && storybook dev -c . -p 50240"
```

### 6. Housekeeping
- Add `storybook/synonyms.generated.json` to `.gitignore`.
- Add a `patches/README.md` entry describing/justifying the Storybook patch and linking the PR (matching existing entries).
- Keep unchanged: the `synonyms` metadata on each story meta and the TS module augmentation ([packages/ui/storybook.d.ts](packages/ui/storybook.d.ts), [storybook/types.d.ts](storybook/types.d.ts)).
- Revert the unrelated [packages/theme/tsconfig.json](packages/theme/tsconfig.json) change (aduth questioned it; out of scope).

## Trade-offs vs. the current approach

- Better: vendor edit is declarative, version-pinned, auto-applied, and visible in review; no in-place mutation or per-run rewrite; data path is supported (manager entry), not string-injection.
- Same residual risk: it still patches third-party bundle code, so a Storybook upgrade can require regenerating the patch — but now it **fails loudly** (patch won't apply) instead of silently dropping synonyms. This is acceptable as a bridge until the author's planned upstream Storybook PR lands.
- Still parses story files for data, but only to emit JSON (low-risk) rather than to rewrite executable vendor code.

## Open questions

- Fuse weight tuning (`name`/`path`/`synonyms`) — addresses jasmussen's "bump name weight back up" note; 0.6/0.2/0.2 suggested.
- Global name (`__WP_DS_SYNONYMS__`) is arbitrary; confirm at implementation that a global set in `manager.js` is in scope when the Fuse list is built at search time (expected: yes, manager entries run at bootstrap, search builds lazily on open).
