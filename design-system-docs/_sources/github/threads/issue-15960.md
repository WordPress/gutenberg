# Issue #15960: Components: Stop using unstable props in DropdownMenu

- URL: https://github.com/WordPress/gutenberg/issues/15960
- Author: gziolo
- Created: 2019-06-03T07:46:21Z
- Updated: 2019-08-12T12:44:26Z
- Comments: 0 of 0

## Body

There were 4 unstable props introduced temporarily in n #14843:
https://github.com/WordPress/gutenberg/blob/c2768eccc3ef53be437ad90fece0c43c8a843ce3/packages/components/src/dropdown-menu/index.js#L27-L30

They were added for backward compatibility. We should further explore how to approach it differently. Some considerations discussed in the PR: https://github.com/WordPress/gutenberg/pull/14843#discussion_r275369685. Let me also highlight some good ideas from @aduth:

https://github.com/WordPress/gutenberg/pull/14843#discussion_r276428231:

> Interesting, it hadn't occurred to me the need to provide customization options for the rendered toggle. My next thought was whether we could just expose renderToggle as a render prop to be customized by the consuming renderer. I guess the problem with that is how to manage on their behalf some of the best practice behaviors (i.e. ArrowDown to open), as I don't think it would be wise to leave open the option that this be possible to overlook (footgun).

https://github.com/WordPress/gutenberg/pull/14843#discussion_r276429937:

> Understanding the desire to retain existing behaviors, I do wonder how we could limit or consolidate the customization options. Something like labelPosition, for example, seems to only exist where otherwise if we allow the standard "top" behavior to apply for the "More Menu", it might escape the page in a way which is undesirable. But it's the sort of thing we try to build-in to the behavior of Popover (auto-reverse when otherwise the popover would exceed bounds), so it seems like something which should be programmatically determined.
