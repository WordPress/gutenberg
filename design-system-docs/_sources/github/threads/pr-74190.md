Good question. By default there are certain component props that Storybook ([`react-docgen-typescript`](https://github.com/styleguidist/react-docgen-typescript) internally) filters out from the props tables in the Storybook docs. One category of that is prop types originating in `node_modules` (this would include our underlying libraries like Ariakit), and another is built-in HTML attributes that have no JSDoc description.

`disabled` has been one of those HTML attributes that are used commonly enough by consumers to be worth exposing in the props table, and it's useful to have a Storybook control for it to check styles and behavior in the browser.

So it's an optimization for our documentation, rather than it being purely about types.
