# Issue #77275: Packages: Fix sideEffects for any package using CSS modules

- URL: https://github.com/WordPress/gutenberg/issues/77275
- Author: aduth
- Created: 2026-04-13T19:15:32Z
- Updated: 2026-04-13T19:15:32Z
- Comments: 0 of 0

## Body

Follow-up to https://github.com/WordPress/gutenberg/pull/76609#issuecomment-4133661142

## What problem does this address?

Packages which use [CSS modules](https://github.com/css-modules/css-modules) (i.e. contain `*.module.css` or `*.module.scss` files) have side effects by virtue of the fact that the built JavaScript includes a mechanism for injecting stylesheets dynamically on import (added in [#72242](https://github.com/WordPress/gutenberg/pull/72242) and iterated in [#74651](https://github.com/WordPress/gutenberg/pull/74651)).

Therefore, it may be wrong that packages define `sideEffects: false` if it includes code that relies on this mechanism (e.g. React components that use CSS modules styling, such as in `@wordpress/ui`).

## What is your proposed solution?

First, we should validate the assumptions described above:

* Why is it not broken currently? Are these side effects safe insofar as they accompany the precise import (component) that someone _is_ using from a package? Or is it something about `@wordpress/build` internals that makes it work, that may not be true in other bundler contexts?
* If the usage today _is_ safe, is it stable enough to rely on while still specifying `sideEffects: false` ?

A safer alternative would be to specify the files that have side-effects, i.e. the components themselves. Ideally we avoid `sideEffects: true` (or removing `sideEffects` altogether) as this would likely inflate the size of bundles that include these packages, pulling in all code whether or not it's actually used.
