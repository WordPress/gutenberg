## Body

<img width="509" alt="Screenshot of the InputControl component in Storybook" src="https://user-images.githubusercontent.com/2322354/93109920-a3a67d00-f682-11ea-9629-e2de572271f9.png">

This update **removes** the floating label variant for the `InputControl` component.

The reason for this is because the previous implementation relied on a HTML setup that was invalid and impeded a11y. The effect was achieved by leveraging `fieldset` and `legend` to achieve the "cutout" effect for the floating label. Semantically, this isn't ideal for an individual `input` field.

We took at other solutions with more appropriate HTML markup (e.g. Google/GMail). There was a tiny implementation detail that prevent us from moving forward with those solutions. Notably, the "cutout" effect was achieved by having a background defined (hard-coded) and set on the floating label. On predictable backgrounds (e.g. white), this is fine as the text label background blends with the application background (white on white). This makes it more complic
ated to synchronize backgrounds if/when the `InputControl` may be used on backgrounds that isn't white and/or if the input background (`Backdrop`) changes colours (e.g. in disabled state, or autofill/autocomplete).

Since we currently aren't using floating labels in Gutenberg, it's probably simpler to remove for now. If we need this feature, we can come back to it in the future.

For context, the floating labels were originally developed as part of `BoxControl`. The cluster of inputs within `BoxControl` evolved a lot during the design process. The result (which was merged) dropped the floating label featu
re.

The issue regarding HTML structure and a11y was originally raised by @afercia here:
https://github.com/WordPress/gutenberg/pull/22329#issuecomment-691481613

## Other Enhancements/Fixes

### Focus issue

Noted by @afercia here (https://github.com/WordPress/gutenberg/pull/22329#issuecomment-692155667), clicking the label does not focus the `input`. This has been resolved. This was previously broken due to `pointer-event` interception.

### Toned down border styles

The border styles have been adjusted to match the other input/select controls (using the `gray700` from `base-styles`).
