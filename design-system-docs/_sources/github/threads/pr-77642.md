## Body

## What?

Part of #74178

Adds a low-level `Autocomplete` primitive to `@wordpress/ui` with the same composable building blocks used elsewhere in the form primitive set.

> [!NOTE]
> This is more like a variation on a `combobox`, and not meant as a replacement for the `Autocomplete` component in `@wordpress/components`, which is basically a block editor-specific component. 

## Why?
`@wordpress/ui` already has overlay and field primitives that can be composed into higher-level inputs, but it does not yet expose an autocomplete primitive with matching styling and behavior.

## Testing Instructions
1. Run `npm run test:unit -- packages/ui/src/form/primitives/autocomplete/test/index.test.tsx`.
2. Open the `Design System/Components/Form/Primitives/Autocomplete` stories in Storybook.
3. Verify the popup opens with matching items as you type, the empty state appears when there are no matches, and the clear button resets the input.
4. Verify the popup remains keyboard navigable with arrow keys and selection still works as expected.
5. Verify a custom portal target still works when `portal={ <Autocomplete.Portal container={ ... } /> }` is passed to `Autocomplete.Popup`.
