# Issue #32336: Toolbar custom component warning persists even after moving custom components inside ToolbarItem

## Body

## Description
Due to warning messages over the deprecation of using custom components as toolbar controls, I've been trying to convert existing toolbars into ones that won't trigger those messages. This has been successful with button components (by turning them into ToolbarButtons), but the warning message still comes up when using ToolbarItems with other components. [A code sample in the official documentation wraps DropdownMenu inside ToolbarItem](https://developer.wordpress.org/block-editor/reference-guides/components/toolbar-item/#render-prop), but it doesn't work either, and not until after activating the Gutenberg plugin did I found out that a separate ToolbarDropdownMenu element has to be used.

### talldan on 2023-04-12T08:52:26Z

URL: https://github.com/WordPress/gutenberg/issues/32336#issuecomment-1504903473

I haven't been working on it. I just know a few things about the Toolbar that I've picked up along the way.

Looking back, my original reply wasn't that great. I missed a few things in the OP's message.

> [A code sample in the official documentation wraps DropdownMenu inside ToolbarItem](https://developer.wordpress.org/block-editor/reference-guides/components/toolbar-item/#render-prop), but it doesn't work either, and not until after activating the Gutenberg plugin did I found out that a separate ToolbarDropdownMenu element has to be used.

The docs do show examples for using `ToolbarItem` with dropdowns and buttons, but there are existing `ToolbarDropdownMenu` and `ToolbarButton` components, so those example are not really worth it. The examples would be better if they showed how `ToolbarItem` can work with a custom component.

> RangeControl inside ToolbarItem

This isn't a great idea, as I think a RangeControl will hijack the left/right arrow keys that are usually used for toolbar navigation.

> ToggleControl inside ToolbarItem

This may also not be a good idea, as these are quite opinionated components that are wrapped in a `BaseControl`, so they're intended for other parts of a UI.

The underlying technical issue is that [`ToggleControl` doesn't accept the props that `ToolbarItem` passes to it](https://github.com/WordPress/gutenberg/blob/3317ba195da0149d0bae221dc3516cd76f536c5d/packages/components/src/toggle-control/index.tsx#L44-L52). From what I can tell it needs to accept `data-toolbar-item`, `id` and `tabIndex` and possibly a range of event handlers. This is what react dev tools says regarding the props that `ToolbarButton` passes to `Button`:
```json
{
  "id": "id-8j1m8g-7",
  "tabIndex": -1,
  "onClickCapture": "ƒ () {}",
  "onMouseDownCapture": "ƒ () {}",
  "onMouseDown": "ƒ () {}",
  "onKeyPressCapture": "ƒ () {}",
  "onKeyDown": "ƒ () {}",
  "onKeyUp": "ƒ () {}",
  "onFocus": "ƒ () {}",
  "onBlurCapture": "ƒ () {}",
  "onClick": "ƒ () {}",
  "data-toolbar-item": true
}
```

`Button` works because it passes [all unknown props it receives to the html element it renders](https://github.com/WordPress/gutenberg/blob/3317ba195da0149d0bae221dc3516cd76f536c5d/packages/components/src/button/index.tsx#L210).

I could solve this in this way with custom components:

```js
import { ToolbarGroup, ToolbarItem, Button as WpButton } from '@wordpress/components';

...

return (
            <>
                <BlockControls key="controls" group="default">
                    <ToolbarGroup>
                        <ToolbarItem>
                            { ( toolbarItemHTMLProps, ref ) => (
                                <Popover>
                                    <Popover.Trigger>
                                        <WpButton 
                                            ref={ref} /* <--- */
                                            label={__('Use preset block style')} 
                                            isPressed={currentBlockStyle ? true : false} 
                                            {...toolbarItemHTMLProps} /* <--- */>
                                            <Icon name="styles" />
                                        </WpButton>
                                    </Popover.Trigger>
                                    <Popover.Content>
                                        <BlockStylesPicker
                                            value={currentBlockStyle} 
                                            onChange={onChangeBlockStyle} 
                                        />                                                               
                                    </Popover.Content>
                                </Popover>                                
                            ) }
                        </ToolbarItem>
                    </ToolbarGroup>
                </BlockControls>
                <BlockEdit {...props} />
            </>
        );
```

This message disappears if `toolbarItemHTMLProps, ref` props are applied to the `<WpButton />` component in my case.
