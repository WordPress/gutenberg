# Issue #62283: Global Styles: Pagination buttons must have a tooltip

- URL: https://github.com/WordPress/gutenberg/issues/62283
- Author: afercia
- Created: 2024-06-04T13:56:48Z
- Updated: 2024-06-10T08:40:35Z

## Body

### Description

Any icon button must visually expose the button accessible name via a tooltip. Worth mentioning tooltips are already a compromise for accessibility, as visible text is always preferred.

The Global styles pagination buttons are an interesting case, as the implementation breaks the logic of the Button component in the first place. To me, this is a sign that the component can be misused. Cc @mirka  

The Button component logic is, shortly:
- When the Button has a text children, it doesn't show a tooltip (unless there's a keyboard shortcut that needs to be shown in the tooltip).
- When the Button only shows an icon, the `lebel` prop is used for the tooltip.

Turns out the Global styles pagination buttons contain text children, but [they're unicode characters for the chevrons](https://github.com/WordPress/gutenberg/blob/a9fd33c99b69ef6ea747fed96569ad837632aedb/packages/edit-site/src/components/pagination/index.js#L46-L54): `«, ‹, ›, »`.

As such, even by changing the buttons `aria-label` to `label`, the tooltip is not rendered because the Button component _thinks_ there is visible text.

Unfortunately, the 'visible' text is just glyphs that are visually equivalent to icons. There is no accessible name exposed.

This is clearly a misuse of the component but it could happen in other scenarios as well, then the 'text' isn't meaningful text that exposes the control's accessible name.

In this specific case, a quick fix would be replacing the `«, ‹, ›, »` with actual icons by the means of the `icon` prop.

### Step-by-step reproduction instructions

- Go to Site editor > Styles > Revisions.
- Make sure there's enough revisions to show the pagination buttons ad the end of the revisions list.
- Hoer or focus the pagination buttons.
- Observe no tooltips appear.
