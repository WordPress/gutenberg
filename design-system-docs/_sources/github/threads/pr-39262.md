## Body

## What
Removes `composeStateReducers` and replaces it with direct coupling. That has the effect of changing the order of a couple of reducer stacks. That breaks the one in `LineHeightControl` so a fix is included here too.

## Why
To resolve #38845 and also make the order that the reducers run in the expected order.

## How
Couples the reducers together directly.

## Testing Instructions
Make sure all components with specializing reducers based on `InputControl` work as expected. That is `NumberControl`, `UnitControl`, `LineHeightControl`.

```javascript
			__unstableStateReducer={ 
				compose( [
					( args ) => stateReducer( ...args ),
					( state, action ) => [
						numberControlStateReducer( state, action ),
						action,
					]
				] )
			}
```

<details><summary>So I dug around and realized maybe you meant `combineReducers` from the data package. That looks nice but creates nested state objects so needs a final pass to merge them.
</summary>

```javascript
	let usedStateReducer = numberControlStateReducer;
	if ( stateReducer ) {
		const combinedReducer = combineReducers( {
			outer: stateReducer,
			inner: numberControlStateReducer,
		} );
		usedStateReducer = ( state, action ) => {
			const result = combinedStateReducer( state, action );
			return { ...result.outer, ...result.inner };
		};
	}
```
</details>

<details><summary>Employing either `compose` or `combineReducers` here gets a bit verbose and begs to be generalized into a replacement for`composeStateReducers`. But a dynamic compose-like utility is still overkill for the established pattern in which no more than two are ever combined at once. If we must have a helper my vote would be for something like `pairStateReducers( b, a )`</summary>

```javascript
const pairStateReducers = ( outer, inner ) => ( state, action ) => {
	const baseState = inner( state, action );
	return outer?.( baseState, action ) ?? baseState;
};
```
</details>

Directly coupling each pair may be a bit verbose but it's plain to see which one runs before the other. For now, I've stuck with that approach but moved the coupling to outside the reducers themselves.
