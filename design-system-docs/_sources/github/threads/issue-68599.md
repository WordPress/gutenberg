# Issue #68599: Limited precision for font sizes with relative units in the WordPress block editor

- URL: https://github.com/WordPress/gutenberg/issues/68599
- Author: deryckoe
- Created: 2025-01-10T12:57:07Z
- Updated: 2025-02-05T14:32:33Z
- Comments: 6 of 6

## Body

## What problem does this address?
The WordPress Block Editor currently restricts REM values to two decimal places, automatically rounding any entered value to this limit. This restriction makes it impossible to use exact font sizes that require more precision. For example, a font size of 22px equals 1.375rem, but the editor forces users to round this to 1.37rem or 1.38rem, leading to inaccuracies.

This automatic modification limits user control and makes it difficult to maintain precise and consistent typography. It also forces users to use px units as a workaround, which is not ideal for responsive design.

https://github.com/user-attachments/assets/0c6ed57b-9594-4432-b4df-b2854e9334ff

## What is your proposed solution?
Remove the automatic rounding of REM values in the WordPress Block Editor. Allow users to input REM values as they choose, without the editor modifying or rounding them. For example, if a user enters 1.375rem, it should be retained as-is, preserving the exact value.

This solution would provide users with the flexibility and precision needed to create pixel-perfect designs while adhering to best practices for responsive design.

### afercia on 2025-02-04T08:27:23Z

URL: https://github.com/WordPress/gutenberg/issues/68599#issuecomment-2633201929

Changing the step value from 0.01 to 0.001 would be terrible for keyboard users who use Up and Down arrow keys to change the value. That would require dozens and dozens of key presses or holding the key for a very long time, which makes the input change very sluggish.
On the other hand, I'd agree this is a _custom_ font size that should allow any valid value. I'm not sure it makes sense to provide users with an UI where they can set a _custom_ value and then be opinionated by restricting to two decimals for `em` and `rem` and to 1 decimal for `vw` and `vh`.

The custom font size picker has other issues as well, as reported in https://github.com/WordPress/gutenberg/issues/69012.
- While the input has a step value of `0.01` for `em` and `rem`, the range slider has a step of `0.1` so that when using the slider, the second decimal gets removed and the user input is lost.
- For 'em', 'rem', 'vw', 'vh' the max value is limited to `10` and for pixels it's limited to `100`.  Again, this is opinionated. Though rare, there may be cases where users need to set a value higher than 100 pixels or higher than 10 for the relative units.
- A range slider should only be used for values that are, well... in a _range_ of known values. It's not an appropriate control to use for values that are potentially infinite. For example. the input allows to enter values that are higher than the maximum value allowed by the slider. In this scenario:
  - The UI shows two different values.
  - As soon as using the slider with the keyboard, the value is restricted to the max value.

![Image](https://github.com/user-attachments/assets/5624d076-14e3-4241-95d1-7ee9b4b9ed28)

This happens also for other settings in the editor, but it's very evident for the font size picker.

Overall, I'd tend to think the control to use for the custom size should be reconsidered entirely. This control is supposd to allow users to set a _custom_ size. It should only worry to make sure the entered value is valid and not be opinionated.

It may be good to collect all the reported issues in a new issue to allow for some broader discussion.
