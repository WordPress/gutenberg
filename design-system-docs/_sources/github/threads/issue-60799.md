# Issue #60799: CheckboxControl, RadioControl, ToggleControl: Support accessible, flexible layouts

- URL: https://github.com/WordPress/gutenberg/issues/60799
- Author: mirka
- Created: 2024-04-16T23:03:38Z
- Updated: 2024-07-03T19:00:58Z
- Comments: 2 of 2

## Body

## What problem does this address?

CheckboxControl, RadioControl, and ToggleControl do not properly support our layout needs, and developers are forced to roll their own solutions or override the component in fragile ways, which can result in slower iteration speeds and accessibility issues.

### Examples of the problems we're encountering

#### CheckboxControl

- https://github.com/WordPress/gutenberg/issues/51740#issuecomment-1853473714
- https://github.com/WordPress/gutenberg/pull/60475#discussion_r1563194757

#### RadioControl

- #52890
- https://github.com/WordPress/gutenberg/pull/60456#issuecomment-2037815338

#### ToggleControl

- #63094

## What is your proposed solution?

This can potentially be addressed in multiple ways, so we need to assess what is the best way forward. Possible approaches include:

- Improve the documentation (e.g. Storybook examples) so that they show how to accessibly implement common custom layouts.
- Moving to a more modular API based on subcomponents, taking inspiration from (or directly use) Ariakit components.
- Keeping the current APIs, but also exporting more modular subcomponents like we do with [`BaseControl.VisualLabel`](https://wordpress.github.io/gutenberg/?path=/docs/components-basecontrol--docs#with-visual-label). This must be coupled with clear usage guidance for accessibility.
