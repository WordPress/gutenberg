## Body

- Fix #45599 
- Part of #45605 

## What?
This PR fixes a problem where duplicate values are set when characters are entered into `FormTokenField` in languages that use IME composition.

## Why?
This is because the `enter` key, which is used to confirm the entry of a character, is considered a token decision.
For more context, see [here](https://github.com/WordPress/gutenberg/issues/45605#issue-1440281357).

## How?
Replaced `event.code` with `event.key`.

## Testing Instructions

1. Create some post tags.
2. Open the post Editor.
3. Enter text in IME composition mode in the "ADD TAG" sidebar.
4. Confrim that the Enter key to decide your input does NOT insert a token.
5. Confirm that pressing the Enter key again sets the token.

Ok, we have another complication, sorry I didn't notice it the first time.

On Mac Safari, the <kbd>Enter</kbd> or <kbd>Backspace</kbd> that ends IME composition is `isComposing=false` 🙃 This causes these keydowns to immediately commit the token or erase the previous token, when that is not the user intent.


https://user-images.githubusercontent.com/555336/200918022-4eaa0342-ef5e-4f70-82d2-a9139cb0a8d4.mp4

<img width="175" alt="event output of the video" src="https://user-images.githubusercontent.com/555336/200918030-979dfb11-f340-4e00-a5ea-bc06d2135996.png">

☝️ `console.log( event.key, event.keyCode, event.nativeEvent.isComposing )`

At this point I'd consider reverting to the `event.keyCode` method, but maybe we can try a hybrid approach, given that `event.keyCode` could theoretically be removed from browsers at any time.

How about we add a `event.keyCode === 229` check in the guard? This way, even if `event.keyCode` is removed from browsers at some point, the damage will be limited to Safari.

```suggestion
		if (
			event.defaultPrevented ||
			// Ignore keydowns from IMEs
			event.nativeEvent.isComposing ||
			// Workaround for Mac Safari where the final Enter/Backspace of an IME composition
			// is `isComposing=false`, even though it's technically still part of the composition.
			// These can only be detected by keyCode.
			event.keyCode === 229
		) {
```
