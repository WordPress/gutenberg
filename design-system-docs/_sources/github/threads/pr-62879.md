### DaniGuardiola on 2024-07-09T15:08:44Z

Thanks for the heads up @jasmussen. In line with the best practices we're trying to achieve regarding the components package (mostly aimed at reducing custom style overrides that cause breakages and high maintenance costs down the line), I would suggest considering the following in order of preference:

- Whether this UI can use the styles built into the Tabs, and do away with the custom ones.
- If not, whether it makes sense to add what is currently custom styled as a variant to Tabs. This should be thought through and compromised on, as we can't just add a variant for each new design. Future designs should stick to the existing variants moving forward as much as possible, and be mindful that any new addition to the base styles has a high cost.
- If that doesn't work either, it suggests that this is a highly custom, one-off UI that could be addressed with Ariakit directly with custom styles. This comes with a few trade-offs, so ideally we'd settle on one of the above options.

If none of these three options work, we can always address this as a regression and tweak the custom styles as you propose, though I think it's a good chance to address it at a more fundamental level. Of course, that doesn't merit blocking a fix so happy to take the simpler route in the short term. Let me know what you think from a design standpoint :)
