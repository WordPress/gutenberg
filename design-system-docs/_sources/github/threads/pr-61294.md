## What?
<!-- In a few words, what is the PR actually doing? -->

This PR supports disabled items for the `<ComboboxControl / >` component.

## Why?
<!-- Why is this PR necessary? What problem is it solving? Reference any existing previous issue(s) or PR(s), but please add a short summary here, too -->

Because the `disable` option for a Combobox component is a common requirement when using it for the UI.

## How?
<!-- How is your PR addressing the issue at hand? What are the implementation details? -->

The `<ComboboxControl />` now accepts the `disabled` property, which is propagated to the `SuggestionsList` one.
The implementation checks if the option is disabled. If so, it does not allow selection in the respective event handler functions.

Let's remark that the disable options are not selectable (by clicking on it or pressing the `enter` key), but they are discoverable and can make the implementation a11y-friendly.
