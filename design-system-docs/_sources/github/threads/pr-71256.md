## Why?
<!-- Why is this PR necessary? What problem is it solving? Reference any existing previous issue(s) or PR(s), but please add a short summary here, too -->

When focus is moved outside an element that has the `useFocusOutside` hook, the callback should run, even if it's removed due to unmounting.

## How?
<!-- How is your PR addressing the issue at hand? What are the implementation details? -->
The current `trunk` implementation of `useFocusOutside` works by:

- Attaching `onFocus` and `onBlur` listeners to the container
- `onBlur` will run anytime focus is moved and queue a cancellable timeout that will run after focus has resolved.
- `onFocus` runs before the timeout settles. If the container runs this `onFocus` check, then focus is resolving within the container. This focus event cancels the onFocusOutside callback from the blur event.
- If no focus event happens within the container, then the blur event runs.

This PR tries removing the onFocus check and setTimeout cancellation system with one onBlur event. This onBlur event checks `event.currentTarget` for access to the container to check if focus is within the container. Additionally, if the container spawns another popover, the popover will remain open because it also checks to see if there is an element within it that is marked as `aria-expanded=true` and `aria-haspopover=true`

I think running the callback on blur is the wrong approach. It should run after focus resolves, because we'll get into weird states where the onClose callback sets states before the onMouseUp event finishes. This means you can't click a button to open the popover, then click the same button to close it (the popover will reopen). I think the `trunk` approach of queueing and canceling timeouts is a really clever and correct approach to this. 

I opened https://github.com/WordPress/gutenberg/pull/71294/ on top of this branch to remove all the extra browser hacks that I don't think are necessary anymore. It would simplify the code if we can remove it all. I'm not 100% sure if we still support a browser that needs that code though.
