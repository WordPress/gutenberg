I feel like this test deviates a little bit from the _exact_ contract we want to guarantee, which is:

1. The `onChange` is called when the toggle is clicked.
2. The first arg passed to the `onChange` call should be the Event.

The second point I think is the most important to test for because it is the current behavior, and if anyone changes that behavior it should sound alarms as a breaking change. And this behavior is notably different from other (newer?) components, which simply pass the new value as the first arg instead of the Event. (And LOL that the readme was wrong about this too! 😂)

So, while I do think a lot of consumers are writing their `onChange` functions like your example, I think we can provide better coverage by assuming that some consumers are using the Event in their `onChange` functions.

How about something like this?

```jsx
			const onChange = jest.fn();
			render( <ControlledFormToggle onChange={ onChange } /> );

			const input = getInput();

			await userEvent.click( input );
			expect( onChange.mock.calls[ 0 ][ 0 ].target ).toBeInTheDocument(); // no strong opinion on what this assertion should be, but something that reasonably asserts that it's an Event

			// and so on...
```
