# Issue #42925: Components: Autocomplete continues matching after selection when `triggerPrefix` is included in output

- URL: https://github.com/WordPress/gutenberg/issues/42925
- Author: chad1008
- Created: 2022-08-03T11:46:37Z
- Updated: 2026-04-20T09:09:20Z

## Body

### Description

The `Autocomplete` component utilizes an array of individual completers. Each of these completers defines its own data/options, and may also declare a `getOptionCompletion` callback to define how the completed text should be handled.

Some completers, like the default user mention completer, retain their `triggerPrefix`. In other words, when you initiate a user mention with `@`, the `@` character is retained when the selection is complete. The presence of that `triggerPrefix` causes the component to refire and try to match again even after a selection.

This manifests in two ways:

**Selection via click event**

After clicking on a name in the user mention list, the component immediately begins trying to match again. Since a match was just selected, there will usually only be one, unless you happen to have a selected a shoter user name that matches a substring of a longer user name.

For example, if you had a username `@john` on your site, and you clicked on it in the autocompleter, you'd be presented with `@john` in the autocompleter again. If you _also_ had a username `@johndoe`, you would see both `@john` and  `@johndoe` after clicking on `@john`.

**Selection via keypress event**

This one is less prominent, and only triggers in the example above with two usernames sharing the same substring. After pressing `enter/return` to select an option, if there's only one match (the item that was just selected) the autocompleter does _not_ reappear. If, however, there are multiple possible matches, as in the case described above, the matching is reattempted as soon as you hit `space`. It's less of a problem here because focus is still on the element receiving your input, so you can just ignore the completer and keep typing.

In short, the problem is that after selecting an option, if the `triggerPrefix` is in the output, the component re-triggers and resumes matching. Ideally, the component would ideally recognize that the user has already made a selection and not reopen until the next time the `triggerPrefix` is typed.

### Step-by-step reproduction instructions

1. Create two new users. One named `john` and one name `johndoe`
2. Create a new post
3. In a paragraph block, type `@` to lauch the user mention completer
4. Click on `john`
5. Notice that the completer opens again immediately, with both test users listed
6. Create a new paragraph block and launch the completer with `@` again
7. Click on `johndoe`
8. Notice that the completer now opens with just the one option (because it's the only match)
9. Create one more new paragraph and type `@` again
10. Select `john` using keypresses (arrows and enter/return)
11. Press space and resume typing
12. Notice that when you hit space, the completer reappears
