# Issue #42540: Improve accessibility linting of styled/polymorphic components

## Body

## What problem does this address?

As surfaced in #42461, our current [`jsx-a11y`](https://github.com/jsx-eslint/eslint-plugin-jsx-a11y) setup does not provide coverage for Emotion styled components and polymorphic (`as` prop) components. This is problematic as more of our codebase is moving toward styled/polymorphic components.

## What is your proposed solution?

Some possibilities:

- [eslint-plugin-styled-components-a11y](https://github.com/brendanmorrell/eslint-plugin-styled-components-a11y): Apparently this is supposed to [work](https://github.com/brendanmorrell/eslint-plugin-styled-components-a11y/issues/6#issuecomment-634207659) with Emotion.
- [Custom component mapping](https://github.com/jsx-eslint/eslint-plugin-jsx-a11y#usage) in the `jsx-a11y` configuration: This is a bit tedious and is not very reliable since it doesn't detect the `as` prop. But it's easy and possibly better than nothing.
- Writing our own lint rule (adapter?) that transforms the `as` prop into HTML elements before passing it through `jsx-a11y`: Unknown difficulty.
