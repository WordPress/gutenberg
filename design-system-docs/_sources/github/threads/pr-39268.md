## Description
<!-- Please describe what you have changed or added -->
Fixes #39267

This PR adds a `onInputFileClick` prop on the `FormFileUpload`.

Currently when there's an error on the `FormFileUpload` and you need to upload the same file again, it doesn't emit the `onChange` event and the user get stuck until choose another file.

With this change, we can add `<FormFileUpload onInputFileChange={ (e) => e.target.value }>` on the parent component, this way the `<input type="file">` inside `FormFileUpload` will empty its file after click, allowing to upload the same file again.

I didn't make it runs by default for compatibility purposes.

> But I don't think it's a bug that needs to be fixed.

Definitely not a bug, but an enhancement to allow a common pattern which is to null out the value on file input clicks. Passing your own component via `render` prop won't work because to null out the value you need a reference to the `<input>`, not the `<button>`. Because this is a [relatively common use case with an established solution](https://stackoverflow.com/questions/4109276/), I do think it would be nice to have `FormFileUpload` support that simple solution (instead of providing some other kind of ref-passing API).

```js
// Necessary assertion for the test to be correct
expect( onChange ).toHaveBeenCalledTimes( 1 );

// Additional assertions that are largely interchangeable in this case
expect( onChange ).toHaveBeenNthCalledWith( 1, fakePath );
expect( onChange ).toHaveBeenCalledWith( fakePath );
```
