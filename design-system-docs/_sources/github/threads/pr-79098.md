# PR #79098: theme: rename `bg`/`fg` design token groups to `background`/`foreground`

## Body

## What?

Rename the `bg` and `fg` semantic color token groups in `@wordpress/theme` to `background` and `foreground`. As a result:

- All `--wpds-color-bg-*` custom properties become `--wpds-color-background-*`.
- All `--wpds-color-fg-*` custom properties become `--wpds-color-foreground-*`.

## Why?

Follow-up to #79007. While renaming the `ThemeProvider` `color.bg` prop to `color.background`, the question came up of whether the DS token names should be consistent too. The consensus in that discussion ([1](https://github.com/WordPress/gutenberg/pull/79007#issuecomment), [2](https://github.com/WordPress/gutenberg/pull/79007)) was that the abbreviation doesn't buy much (some token names are very long regardless, e.g. `--wpds-color-bg-interactive-neutral-strong-disabled`) and the inconsistency is confusing (e.g. `surface` is already spelled out). Spelling out `background`/`foreground` is clearer and reads more naturally.

This was intentionally split out of #79007 to keep that PR contained and to settle the approach here.

## How?

- Rename the `bg` → `background` and `fg` → `foreground` semantic groups in `tokens/color.json`.
- Update the corresponding TypeScript-type generation patterns in `terrazzo.config.ts`.
- Regenerate the prebuilt token artifacts (`design-tokens.css`, `design-tokens.mjs`, `design-token-fallbacks.mjs`, `color-tokens.ts`, `token-types.ts`) and `docs/tokens.md`.
- Update every in-repo consumer of the renamed custom properties (`@wordpress/admin-ui`, `@wordpress/boot`, `@wordpress/ui`, `@wordpress/components`, `@wordpress/dataviews`, `@wordpress/edit-site`, `@wordpress/grid`, Storybook decorators/stories, eslint/stylelint fixtures and snapshots).
- Update the hard-coded fallback overrides and the docs preamble example to the new names.

The **primitive** ramp group/property names (e.g. `primitive.bg`, `bgFill1`, `fgSurface4`) intentionally keep their abbreviated form: they are internal building blocks and are not exposed as design tokens.

This is a breaking change, documented in the `@wordpress/theme` CHANGELOG.

## Testing Instructions

1. Run the `@wordpress/theme` and `@wordpress/eslint-plugin` unit tests.
2. In Storybook, open a `ThemeProvider`/DS component story and confirm background/foreground colors still apply correctly.
3. Confirm there are no remaining references to `--wpds-color-bg-*` / `--wpds-color-fg-*` in the repo (outside historical CHANGELOG entries).
