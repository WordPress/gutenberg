## Body

## What?
Follow up to #77462, P2/Q2 and P3/Q1.

Cleans the `@wordpress/theme` npm publish surface and validates the actual `npm pack` tarball so accidental test/internal files, missing packed non-JavaScript entrypoint targets, and broken package export/type resolution are caught before publishing.

## Why?
`npm pack --dry-run` was including tests, stories, fixtures, snapshots, and test/story declaration output.

The package also had export `types` paths that did not match the generated `.d.mts` declaration files, and the root type declaration re-exported `token-types` without including that declaration in the packed package.

## How?
- Keep generated runtime output folders (`build`, `build-module`) included as folders.
- Include only the generated declaration files needed by package metadata and public root types.
- Include public source-side plugin folders and prebuilt CSS/JS assets by pattern.
- Keep tests and stories typechecked, but exclude test, story, fixture, and snapshot output from the packed package.
- Align exported type paths with the generated `.d.mts` declaration files.
- Add a generic `tools/validation/validate-package-contents.mjs` validator, with `@wordpress/theme` as the first opt-in package.
- Validate the packed tarball with `@arethetypeswrong/cli`.
- Keep a narrow custom target check only for entrypoints explicitly excluded from `attw` because `attw` does not model non-JavaScript entrypoints such as CSS or Sass.
- Run package contents validation from the Static Analysis workflow after `npm run build`, not as part of the build command itself.

## Testing Instructions
1. Run `npm run --workspace @wordpress/theme build`.
2. Run `npx tsgo --build packages/theme/tsconfig.json`.
3. Run `npm run lint:package-contents`.
4. Run `npm run --workspace @wordpress/validation-tools test-package-contents`.
5. Run `npm run lint:lockfile`.
6. Run `npm run lint:deps`.
7. Run `npm run lint:pkg-json -- packages/theme/package.json tools/validation/package.json`.
8. Run `npm run lint:published-deps`.
