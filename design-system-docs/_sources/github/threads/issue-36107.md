# Issue #36107: FlexItem wraps a div around items

- Updated: 2021-12-13T11:39:38Z

## Body

Extracting from https://github.com/WordPress/gutenberg/pull/35857#issuecomment-952483679, we had some problems using the FlexItem component for spacing things out. Quoting from the converesation:

<blockquote>
The problem with the Flex component is that FlexItem wraps an element around our buttons, so instead of having

```
<Flex>
    <button />
    <button />
</Flex>
```
which would allow us to style the buttons as flex children, we end up with

```
<Flex>
    <div>
        <button />
    </div>
    <div>
        <button />
    </div>
</Flex>
```
and because Flex is set up to use CSS-in-JS, we can't just hook some extra CSS to its classnames. We can pass the styles inline to FlexItem, but at that point it's easier (and much less messy) to not use Flex at all, and attach the CSS directly to our LinkControlTransforms markup.
</blockquote>

and

<blockquote>
Yeah, seems like FlexItem should have an `as` prop:
```jsx
<FlexItem as={ Button }>
```
But it doesn't right now. It always renders as a `View`, which is a `div`.
</blockquote>

Feel free to edit the description or title of this ticket if need be.

That shouldn't be the case, and I'd be curious to know why this didn't work out for the folks quoted above.

`FlexItem` props [are of type `WordPressComponentProps`](https://github.com/WordPress/gutenberg/blob/trunk/packages/components/src/flex/flex-item/component.js#L9), which means that [the component accepts the `as` prop](https://github.com/WordPress/gutenberg/blob/trunk/packages/components/src/ui/context/wordpress-component.ts#L22).

You can see the `as` prop being used on the `FlexItem` component in the [`ItemGroup` "Complex Layouts" example](https://wordpress.github.io/gutenberg/?path=/story/components-experimental-itemgroup--complex-layouts).

To double-check this, I also quickly put together this example in Storybook:

```jsx
<Flex>
	<FlexItem as="button">Item</FlexItem>
	<FlexItem as="button">Item</FlexItem>
</Flex>
```

And everything seems to work as expected:

### tellthemachines on 2021-12-13T05:06:19Z

> That shouldn't be the case, and I'd be curious to know why this didn't work out for the folks quoted above.

@ciampo the issue is not the ability to choose the tag rendered by FlexItem, it's with FlexItem rendering a tag at all. We shouldn't need an extra markup element wrapped around each flex child.

The other issue is we often need to add specific properties to one or more of the flex children, e.g. `flex-grow` or `flex-basis`. Using Flex and FlexItem, we can pass those properties as inline styles to FlexItem, but if the point of these components is to avoid writing additional CSS, then that sort of defeats the purpose.
