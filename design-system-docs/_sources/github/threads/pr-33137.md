I've seen 3 variations of this hook:

### `useLazyRef`

```ts
export function useLazyRef<T>(init: () => T) {
  const ref = useRef<T>();
  if (ref.current === undefined) {
    ref.current = init();
  }
  return ref.current;
}
```

`useLazyRef` is useful when we need to instantiate something only in the first render. This is one of the few cases where accessing `ref.current` in the render phase will not break React's concurrent mode.
```js
const set = useLazyRef(() => new Set());
```

Reference: https://twitter.com/dan_abramov/status/1149120970856075264

### `useLiveRef`

```ts
export function useLiveRef<T>(value: T) {
  const ref = useRef(value);
  useLayoutEffect(() => {
    ref.current = value;
  });
  return ref;
}
```

`useLiveRef`, which looks more like the implementation in this PR, is useful when we need to use some value in an effect or memorized callback, but we don't want to re-run the effect when they change.

For example, in the component below, the effect will run not only when `value` changes, but also when the `onChange` prop is updated. Since the `onChange` prop is passed as an inline function (as usually it is), that will trigger the effect and call `onChange` every time `Parent` is re-rendered.
```jsx
function Component({ onChange }) {
  const [value, setValue] = useState("");
  useEffect(() => {
    onChange?.(value);
  }, [onChange, value]);
  ...
}

function Parent() {
  return <Component onChange={() => {}} />;
}
```

You can see that happening here: https://codesandbox.io/s/aged-fire-un639?file=/src/App.js (clicking on "Re-render parent component" triggers `onChange`).

We could prevent that by omitting the `onChange` prop in the effect deps:

```diff
  useEffect(() => {
    onChange?.(value);
- }, [onChange, value]);
+ }, [value]);
```

That works, but [React recommends against doing that](https://reactjs.org/docs/hooks-faq.html#is-it-safe-to-omit-functions-from-the-list-of-dependencies). To be honest, though, I haven't found any issues with that when using callback props.

However, we can use this `useLiveRef` hook (or `usePropRef` in this PR) to store the current value of the prop and safely omit it from the effect dependencies:

```jsx
function Component({ onChange }) {
  const [value, setValue] = useState("");
  const onChangeRef = useLiveRef(onChange);
  useEffect(() => {
    onChangeRef.current?.(value);
  }, [value]);
}
```

You can see that clicking on "Re-render parent component" doesn't trigger the `onChange` prop anymore: https://codesandbox.io/s/recursing-drake-o761c?file=/src/App.js

That's useful not only for callbacks or props, but any value that you don't want to trigger the effect on change, but you still want to use them inside the effect. For example, [here we want to focus the element when a move has been performed and the element is the current active item](https://github.com/reakit/reakit/blob/f05d36daa6fbcc52c70cf2c71baea69025aa2402/packages/reakit/src/Composite/CompositeItem.ts#L174-L182), but we don't want to do that when the currently active item has been changed without a move. So we ignore changes on the `isCurrentItem` value by [using `useLiveRef`](https://github.com/reakit/reakit/blob/f05d36daa6fbcc52c70cf2c71baea69025aa2402/packages/reakit/src/Composite/CompositeItem.ts#L139-L140).

Since this can be used for more things than just props, I would call it `useLiveRef` or `useLatestRef` (which I think is more common) instead of `usePropRef`.

### `useEventCallback`

```ts
export function useEventCallback<T extends (...args: any) => any>(callback?: T) {
  // @ts-ignore
  const ref = useRef<T | undefined>(() => {
    throw new Error("Cannot call an event handler while rendering.");
  });
  useLayoutEffect(() => {
    ref.current = callback;
  });
  return useCallback(
    (...args: Parameters<T>): ReturnType<T> => ref.current?.(...args),
    []
  );
}
```

`useEventCallback` is a more specialized version of `useLiveRef` for callbacks. This always returns a memorized function (and not a ref) and throws an error if the user tries to call it in the render phase (that is, before layout effects are applied), as this would likely break React concurrent mode.

It's also a bit more convenient than `useLiveRef`:

```jsx
function Component({ onChange: onChangeProp }) {
  const [value, setValue] = useState("");
  const onChange = useEventCallback(onChangeProp);
  useEffect(() => {
    onChange(value);
  // we put the callback in the deps array, but the callback's reference will never change.
  }, [onChange, value]);
}
```
