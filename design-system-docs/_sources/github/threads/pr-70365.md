### ciampo on 2026-04-10T11:07:02Z

URL: https://github.com/WordPress/gutenberg/pull/70365#issuecomment-4223191078

Thanks for working on this! A few additional items I noticed beyond what Copilot flagged:

---

### Formatting (alignment with existing READMEs)

1. **List markers — use `-` instead of `*`**
   The existing `DateTimePicker` README (and virtually all other component READMEs) use hyphens for metadata lines. Both new files use asterisks. For example:
   ```diff
   -* Required: No
   +- Required: No
   ```

2. **Missing blank line before code fence** (`date/README.md`)
   After "Render a DatePicker." there's no blank line before the opening code fence. Other READMEs always have one.

3. **Orphaned "best practices" bullet** (`date/README.md`)
   There's a stray `* Use smart defaults and highlight the current date.` after the component description, without a section heading. Either wrap it in a `## Best practices` section (like the parent `DateTimePicker` README) or remove it.

4. **Import source** — both READMEs import `useState` from `@wordpress/element`, but the parent `DateTimePicker` README imports from `'react'`. For consistency, these should match:
   ```diff
   -import { useState } from '@wordpress/element';
   +import { useState } from 'react';
   ```

5. **Redundant `Type:` lines** — several props include the type in the heading _and_ a separate `* Type:` line (e.g. `events`, `is12Hour`, `hideLabelFromVision`). The parent README only puts the type in the heading. The extra line can be removed.

6. **Extra blank line in TimePicker example** — there's a blank line between `const MyTimePicker = () => {` and `const [ time, setTime ]...` that other examples don't have.

---

### Accuracy

7. **`events` type notation** (`date/README.md`)
   The heading uses `[{ date: Date }]` (a tuple of exactly one element). It should be `{ date: Date }[]` (an array), matching both the TypeScript types and the parent README.

---

### Completeness

8. **Missing `TimePicker.TimeInput` documentation** — `TimePicker` exposes a compound sub-component (`TimePicker.TimeInput`) that isn't mentioned in the new README. Worth at least a brief section or a note pointing to it.

9. **Manifest titles** (`docs/manifest.json`)
   The new entries use `"Date"` and `"Time"` as titles, but the components are `DatePicker` and `TimePicker`. The sibling entry uses `"DateTime"` for `DateTimePicker`, so `"DatePicker"` and `"TimePicker"` would be more consistent and discoverable.
