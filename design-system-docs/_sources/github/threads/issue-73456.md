# Issue #73456: RangeControl reset produces undefined but UI still displays previous numeric value (controlled state mismatch)

- URL: https://github.com/WordPress/gutenberg/issues/73456

- Updated: 2026-01-02T10:09:15Z

## Body

### Description

When using `RangeControl` from `@wordpress/components` with `allowReset={true}`, the component behaves inconsistently when the current value is `0` **and the block has been saved and reloaded**.

Specifically:

* After setting the value to `0` and saving the post, the block reloads with `pcSize = 0` as the initial attribute value.
* Pressing the **Reset** button correctly triggers `onChange(undefined)` and updates the block attribute to `undefined` using `setAttributes`.
* **However, the UI does not update**:

  * The numeric input still displays `0`.
  * The slider thumb remains at the 0 position.

This results in a mismatch between the **actual stored value (`undefined`)** and the **UI’s displayed value (`0`)**, indicating that `RangeControl` does not properly behave as a fully controlled component when transitioning from a saved numeric value to `undefined` after a reset.

This issue only occurs after saving and reloading the block, suggesting that the problem is triggered when the initial value originates from saved post content rather than from editor-side state alone.


### Step-by-step Reproduction Instructions

1. Register a block using the code provided in the reproduction snippet, including a numeric attribute (e.g., `pcSize`).
2. Insert the block into a post.
3. Set the `RangeControl` value (PC size) to `0`.
4. Save the post.
5. Reload the editor so the block is loaded from the saved post content.

   * At this point, the block attribute `pcSize` is initialized as `0` from saved markup.
6. Open the browser console to observe the `onChange` output.
7. Click the **Reset** button on the `RangeControl`.
8. Observe the following behavior:

   * The console logs `onChange -> undefined`.
   * `setAttributes({ pcSize: undefined })` updates the attribute as expected.
   * **However, the UI still displays `0`, and the slider thumb remains at the 0 position.**
9. Expected behavior:

   * After resetting to `undefined`, the UI should reflect an "unset" or blank state instead of keeping the previous `0` value.

		}

		<div { ...useBlockProps() }>

				label="PC size"
				value={ pcSize }
				onChange={ handleValueChange }

				max={ 100 }

For the slider, the problem is that a range slider does not have an "undefined" state. The indicator needs to be somewhere between the ends of the track. The second issue is the number input. In [isolated examples](https://wordpress.github.io/gutenberg/?path=/docs/components-rangecontrol--docs), I can see that the reset button does indeed clear the number input (if `initialPosition` is undefined). So it seems like this issue is triggered somewhere in the consumer data flow. ### Root Cause

The issue stems from how `useControlledState` handles the transition between controlled and uncontrolled modes:

1. **Initial state**: `valueProp = 0` (a defined value)
   - Component is in **controlled mode** (`hasCurrentState = true`)
   - Internal state tracks the value

2. **First reset click**: 
   - `setValue(null)` is called internally
   - However, `useControlledState`'s `setState` callback checks `if (!hasCurrentState)` before updating internal state
   - Since we're in controlled mode, `setInternalState(null)` does nothing
   - `onChange(undefined)` is called, parent updates attribute
   
3. **After parent re-renders**: `valueProp = undefined/null`
   - Component switches to **uncontrolled mode** (`hasCurrentState = false`)
   - `getDefinedValue([null, 0, initial], fallback)` is evaluated
   - The internal state still contains the stale value `0` from step 1
   - `getDefinedValue` returns `0` (first defined value found)
   - Component still displays `0` instead of reset state

4. **Second reset click**:
   - Now in uncontrolled mode, `setInternalState(null)` works
   - Value finally resets to `null`


### Solution

Added a synchronous check in `useControlledRangeValue` to detect when `valueProp` transitions from a defined value to `null`/`undefined` and immediately clear the internal state:

```typescript
const prevValuePropRef = useRef< typeof valueProp >();

// Clear stale internal state when valueProp transitions from a number to null/undefined
useEffect( () => {
	const isTransitionToNull =
		typeof prevValuePropRef.current === 'number' &&
		( valueProp === null || valueProp === undefined );

	if ( isTransitionToNull ) {
		setInternalState( null );
	}

	// Update ref after checking the condition
	prevValuePropRef.current = valueProp;
}, [ valueProp, setInternalState ] );
```
