## Body

## What?
This PR fixes how we use the `Ariakit.useTooltipStore` hook in the `Tooltip` component.

## Why?
Previously, we were circumventing an ESLint error because the hook was conditionally called. I recall I suggested this workaround, so I'm glad I'm the one to suggest removing it now (see https://github.com/WordPress/gutenberg/pull/57202#discussion_r1443170682).

The workaround is no longer necessary since the hook is no longer called conditionally.

The motivation is that I'm fixing it to resolve a couple of ESLint errors that were raised by the React Compiler ESLint plugin in https://github.com/WordPress/gutenberg/pull/61788

## How?
Just using the hook directly.

### tyxla on 2024-05-22T11:49:59Z

URL: https://github.com/WordPress/gutenberg/pull/61858#issuecomment-2124600735

We're trying out the new React Compiler ESLint plugin in https://github.com/WordPress/gutenberg/pull/61788

It will complain that hooks can't be just dynamically declared or assigned somewhere. So in code like @Mamaduka [provided above](https://github.com/WordPress/gutenberg/pull/61858#pullrequestreview-2070931233):

```
const compositeStore = useCompositeStore();
const activeId = compositeStore.useState( 'activeId' );
```

it will complain because the `useState` hook reference can potentially change, and that's against the rules of hooks - more details [here](https://react.dev/reference/rules/react-calls-components-and-hooks#dont-dynamically-use-hooks). 

To solve this issue, `useState` must be recognized by the React Compiler as a stable, static reference. My conclusion is that we might need a different API for that (as I roughly suggested above), but I'm curious if you have any other ideas.

### diegohaz on 2024-05-22T12:01:15Z

I see. Ariakit has an experimental `useStoreState` function (currently exported by `@ariakit/react-core/utils/store`) that can be used like this:

```js
const activeId = useStoreState(compositeStore, 'activeId');
```

This is essentially what `compositeStore.useState` does internally. There are no plans to promote this API to `@ariakit/react` soon, but it might happen if this is a general issue.
