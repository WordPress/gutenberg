## Description
<!-- Please describe what you have changed or added -->

_Following the conversation in #37063 and the exploratory work done in #37223, this PR is the first step towards adding support for advanced focus restoration in `Navigator`. The plan is to have the work split across 3 PRs:_
- _introduce location history support (#37416)_
- _add advanced focus restoration (#38149)_
- _add `NavigationButton` and `NavigationBackButton` components (this PR)_ 

---

This PR contains the following changes:

- Add two new components: `NavigatorButton` and `NavigatorBackButton`
- Update tests, storybook examples and documentation of the `Navigator` family
- Update usages in Gutenberg of the `Navigator` component (in the post editor's preferences modal, and in the Global Styles sidebar)

Note: compared to before, the HTML attribute used for the focus restoration is `id` (as opposed to a custom `data` attribute). This can be changed through the `attributeName` prop on the `NavigatorLink` component, in case.

Since the `path` prop is used as the [value for an HTML attribute](https://github.com/WordPress/gutenberg/blob/f821819e850cb043c300cf7b65fbcd8bea4911b2/packages/components/src/navigator/navigator-button/hook.ts#L51) (part of the focus restoration logic), the value of `path` needs to be a valid value for HTML attributes (meaning it can't contain a series of characters like single/double quotes, spaces, etc).

Therefore, the value of `path` is escaped to make sure that it can be safely applied as an HTML attribute  — and this test checks that behaviour
