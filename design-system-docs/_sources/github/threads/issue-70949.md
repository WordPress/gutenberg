# Issue #70949: ToolsPanel: dropdownMenuProps type requires unnecessary label property

## Body

## What problem does this address?

The `dropdownMenuProps` prop of the `ToolsPanel` component is passed internally to the `DropdownMenu` component in the `ToolsPanelHeader`:

https://github.com/WordPress/gutenberg/blob/424c8e93b4fcc0ee394fe5684bfe9b3bbd41cebf/packages/components/src/tools-panel/tools-panel-header/component.tsx#L196-L199

The `dropdownMenuProps` has been used heavily to drive the refactoring of the block sidebar in particular: https://github.com/WordPress/gutenberg/issues/67813

The internal `DropdownMenu` component uses the `label` prop of the `ToolsPanel` component itself, so even though `dropdownMenuProps.label` is a required field, it is not used at all.

As a result, you'll get a type error when creating a component like this:

```jsx
import { __experimentalToolsPanel as ToolsPanel } from '@wordpress/components';

const Component = () => {
	return (
		<ToolsPanel
			label="Dropdown Label"
			resetAll={ () => {} }
			dropdownMenuProps={ {
				popoverProps: {
					placement: 'left-start',
				},
			} }
		>
			Hello World
		</ToolsPanel>
	);
};
export default Component;
```

## What is your proposed solution?

I would suggest either approach.

1. Omit the `label` field from the `dropdownMenuProps` property.

2. Use the `dropdownMenuPropslabel` as a fallback. Example:

```javascript
const ToolsPanelHeader = () => {
	const {
		// ...
		label: labelText,
		dropdownMenuProps,
		// ...
	} = useToolsPanelHeader( props );
	// ...
	const dropDownMenuLabelText =
		dropdownMenuProps?.label ||
		sprintf(
			// translators: %s: The name of the tool e.g. "Color" or "Typography".
			_x( '%s options', 'Button label to reveal tool panel options' ),
			labelText || ''
		);
	// ...
};
```
