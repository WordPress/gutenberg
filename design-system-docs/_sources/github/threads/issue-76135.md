# Issue #76135: Prepare `@wordpress/ui` for use in Gutenberg

## Body

> [!NOTE]
> The canonical source of component readiness is now the `@wordpress/use-recommended-components` lint rule. If you _don't_ get a lint error for a given `@wordpress/ui` component, it's ready for use.

These are the remaining tasks before we can start using `@wordpress/ui` components in the Gutenberg app. Any other blockers will be added to this list as we discover them.

- [x] Fix [common/form CSS](https://github.com/WordPress/gutenberg/issues/75855#issuecomment-3957504885) situation #76783
- [x] Lint rule to restrict certain component imports #76222
- [ ] Stabilize and confirm text overflow behavior (especially `Button`, `Badge`)
- [x] Tabs: Indicator color consistency with legacy tab components #78418
- [x] `VisuallyHidden`: Needs to work with [`isElementVisible()`] #77191(https://github.com/WordPress/gutenberg/blob/9eec2234e3ac0a582112e7826c7083f0fcf3c373/packages/block-editor/src/utils/dom.js#L83)
- [ ] Apply new focus ring styles to `@wordpress/components`
- [ ] Overlay components (popovers, dialogs, modals, tooltips, dropdowns...) need a compat layer
- [x] Update [cursor styles](https://github.com/WordPress/gutenberg/pull/75697) in `@wordpress/components` #76762
- [x] Lint rule to use consistent import names for `@wordpress/components` with conflicting names #77389

The official introduction of `ThemeProvider` and design tokens stylesheet needs separate planning, but is not technically a blocker to start component adoption.

### mirka on 2026-04-08T12:58:07Z

URL: https://github.com/WordPress/gutenberg/issues/76135#issuecomment-4206392006

A component goes in the allowlist when someone has verified to the best of their ability that it will work as expected in a WordPress environment, with no jarring differences between it and any `@wordpress/components` equivalent. I'm still finding new problems as I try to add components to the allowlist 😅 I can look at `Link` next — the only blocker I'm aware of was #76783, and with that out of the way hopefully it's just a matter of adding some migration guidance to the `ExternalLink` docs.

Allowlist means ready to ship in Gutenberg. Not in allowlist means it's already known to be not ready to ship in Gutenberg, or nobody has verified it yet either way.
