## Body

## What?

Updates Jest unit tests code transforms to apply [`babel-plugin-transform-import-meta`](https://www.npmjs.com/package/babel-plugin-transform-import-meta).

Related: https://github.com/WordPress/gutenberg/pull/79153#discussion_r3416144873

## Why?

We write our tests as if they're ESM, but we continue to use `__dirname` in tests despite the fact that [`__dirname` doesn't exist in true ESM](https://nodejs.org/api/esm.html#no-__filename-or-__dirname). And we can't _not_ use `__dirname` because `import.meta` doesn't exist when the test code is transpiled to CommonJS.

This creates two problems:

- Each new instance of `__dirname` is even more technical debt that we eventually need to clean up once we migrate toward actual ESM (whether that's [Jest](https://jestjs.io/docs/ecmascript-modules) or otherwise)
- Even if someone wanted to avoid `__dirname`, they can't use `import.meta.dirname` today

## How?

`babel-plugin-transform-import-meta` lets us pretend that `import.meta.dirname` exists in tests, so that the code is future-compatible when the tests are actually run as ESM.

Updates a single test case (the one mentioned in https://github.com/WordPress/gutenberg/pull/79153#discussion_r3416144873) as a proof-of-concept. A follow-up pull request could do a mass migration of `__dirname` -> `import.meta.dirname` and `__filename` -> `import.meta.filename`, and perhaps even lint to forbid continued use of the legacy globals.
