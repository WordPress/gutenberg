However, I'm not sure whether this is a bug or not. [This document](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html) states the following:

> ### Inactive User Interface Components
> 
> User Interface Components that are not available for user interaction (e.g., a disabled control in HTML) are **not required to meet contrast requirements**. An inactive user interface component is visible but not currently operable. An example would be a submit button at the bottom of a form that is visible but cannot be activated until all the required fields in the form are completed.

cc @WordPress/gutenberg-components

### joedolson on 2025-11-04T13:16:09Z

URL: https://github.com/WordPress/gutenberg/issues/72962#issuecomment-3485961953

It is permitted under WCAG for disabled components to have lower contrast, but this should still be considered judiciously. The allowance is because lower contrast is a helpful affordance that the component is disabled, but making it nearly impossible to see isn't really helpful. 

While decreasing the prominence of the disabled button makes sense, I think we should  try to make it a bit more readable than this. We should at least maintain the contrast we had before this change.
