# Issue #77731: Modal: no way to veto a close before the exit animation runs

## Body

## Problem


> [!NOTE]
>  Framing this as a question as I might be completely off here. Please close if it can't or shouldn't be fix.

`Modal`'s `onRequestClose` fires _after_ the close animation completes. Consumers that want to show a "discard changes?" confirm dialog on close end up with a visible flicker: the modal animates away, the confirm appears, and if the user picks "keep editing" the modal snaps back into place.

All four close paths run`closeModal().then(onRequestClose)`:

- X button (`packages/components/src/modal/index.tsx:330`)
- ESC key (`:200`)
- Backdrop click (`:239`)

There's no prop to intercept the close intent before the animation, so the consumer has no way to cancel without paying the visual cost.

https://github.com/user-attachments/assets/6c3f3a22-3f07-4d57-a09b-303d29866b35


## Workarounds today

In #77730 (media editor) we ended up:

- Setting `isDismissible={false}` and rendering a custom X in `headerActions`.
- Setting `shouldCloseOnEsc` `shouldCloseOnClickOutside` to `false` while there are unsaved changes (so ESC/backdrop become no-ops rather than flickering).

That works but reimplements behavior that should belong to `Modal`, and means each consumer reinvents it.

## Proposal

Add an opt-in prop that fires _before_ the exit animation and can veto the close:

```ts
onConfirmClose?: () => boolean | Promise<boolean>;
```

Returning `false` cancels the close (no animation, no `onRequestClose`). Returning `true` (or omitting the prop) preserves today's flow.

Alternatives considered: `onBeforeClose(close)` callback-style, but `onConfirmClose` is narrower and matches similar patterns in router/dialog libs.

Use cases beyond media editor: post editor unsaved-changes prompts, custom forms in modals, anywhere the consumer wants to inspect state at close time.
