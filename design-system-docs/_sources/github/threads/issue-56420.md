# Issue #56420: Tooltip: consider adding support for rendering in legacy popover slot

- URL: https://github.com/WordPress/gutenberg/issues/56420
- Author: ciampo
- Created: 2023-11-22T08:54:44Z
- Updated: 2023-11-23T16:16:15Z
- Comments: 1 of 1

## Body

As noted in https://github.com/WordPress/gutenberg/issues/47614#issuecomment-1818476114, the recent [refactor of `Tooltip`](https://github.com/WordPress/gutenberg/issues/48222) introduced a change to where the tooltip's contents render in the page.

Prior to the refactor, `Tooltip` was using `Popover` internally, and as a consequence, the tooltip's contents were rendered inside the matching `<Popover.Slot />`.

After the refactor, the tooltip's contents render in a new dom node added by `ariakit`.

As a consequence, we should understand:

- whether we should tweak the `Tooltip` component so that it renders in a `Popover.Slot` if there is a matching one (and in a new portal as fallback)
- what consequences would that have on the editor (see https://github.com/WordPress/gutenberg/issues/55894), superficially when tooltips are rendered inside other modal UI

As per https://github.com/WordPress/gutenberg/issues/56482, we should NOT have the `Tooltip` component render in the `Popover.Slot` by default.

At most, we could expose the `portal` and `portalElement` props to allow users to customize which DOM node should the tooltip render in.
