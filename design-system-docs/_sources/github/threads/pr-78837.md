## Body

## What?

Refactors the `withFallbackStyles` higher-order component from a class component to a function component with hooks. Part of #22890.

## Why?

#22890 tracks converting the remaining class components in `@wordpress/components` to function components with hooks. `withFallbackStyles` was one of the last class components left in `packages/components/src/higher-order`.

## How?

- Constructor state becomes two `useState` hooks (`fallbackStyles`, `grabStylesCompleted`).
- The `this.nodeRef` instance variable becomes a `useRef`, and the bound `bindRef` method becomes a stable `useCallback` ref callback.
- `componentDidMount` and `componentDidUpdate` both called `grabFallbackStyles` unconditionally (i.e. after every render, synchronously before paint). These map to a single `useIsomorphicLayoutEffect` with no dependency array. I used `useIsomorphicLayoutEffect` (from `@wordpress/compose`) rather than `useEffect` to preserve the original before-paint timing, so the grabbed fallback styles still apply without a flash, while staying SSR-safe.
- The internal guard (`grabStylesCompleted` plus the `fastDeepEqual` check) is unchanged, so there is no extra work or render loop.
- Dropped the now-unused `State` type.

This is a pure refactor with no intended behavioral change.

## Testing Instructions

`withFallbackStyles` has no internal consumers in the repo (it is exported as a public API), so this is best verified through the added unit tests:

```
npm run test:unit -- --testPathPattern with-fallback-styles
```

The component previously had no tests. This PR adds regression coverage for both render paths (the internal ref-wrapper path and the `node`-prop path) and asserts that the mapped fallback styles are passed to the wrapped component.
