# Issue #15524: Don't use `disabled` on focusable UI controls e.g. "Reset" buttons

- URL: https://github.com/WordPress/gutenberg/issues/15524
- Author: afercia
- Created: 2019-05-09T08:29:37Z
- Updated: 2023-07-24T13:17:21Z
- Comments: 6 of 6

## Body

Noticed while reviewing #14919 for the Range Control, see https://github.com/WordPress/gutenberg/pull/14919#issuecomment-490796943, and applies to other buttons as well, for example the Font Size picker "Reset" button.

The Reset button in the font size picker:

<img width="895" alt="Screenshot 2019-05-09 at 09 24 31" src="https://user-images.githubusercontent.com/1682452/57438233-bfef0a00-7243-11e9-9dc9-80a2a1b5537e.png">

When using the keyboard and pressing the Reset button, the button gets a `disabled` HTML attribute. Thus, it's not focusable any longer and a focus loss occurs.

Worth noting modern browsers try to implement a smart behavior by the means of a so called [sequential focus navigation starting point](https://bugs.chromium.org/p/chromium/issues/detail?id=454172). Among other things, this feature is meant to help in this kind of situations: pressing Tab again should make the tab order start (more or less) from the place where focus was.

However, this is not guaranteed to work with assistive technologies. Not to mention some browsers don't have this feature (typically IE 11).

To avoid this kind of focus loss, Gutenberg uses a different pattern in a few places. Instead of using the HTML attribute `disabled`:
- noop the button
- use `aria-disabled` to communicate the button inert state
- style the button as it was disabled

This pattern should be extended to all the cases where a UI control that currently has focus gets disabled. Starting from these "Reset" buttons, I'd like to propose to review all the cases where `disabled` is used across the codebase.

The font size picker mentioned on this issue is just an example of the pattern that needs to be fixed. More controls do have a 'Reset' button or other buttons that get a `disabled` attribute _while_ they're focused. Using the `disabled` attribute is the pattern that should be checked everywhere.

Specifically, the font size picker now has a [withReset](https://github.com/WordPress/gutenberg/blob/a538973fb340d21a454aee2dabd6f689b012d9df/packages/block-editor/src/components/global-styles/typography-panel.js#L357) property set to false so that it doesn't show the Reset button.  However, [the component still uses the disabled attribute](https://github.com/WordPress/gutenberg/blob/a538973fb340d21a454aee2dabd6f689b012d9df/packages/components/src/font-size-picker/index.tsx#L271-L281), thus potentially triggering a focus loss.
