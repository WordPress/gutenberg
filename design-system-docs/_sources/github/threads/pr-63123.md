## What?
<!-- In a few words, what is the PR actually doing? -->

Tweak the ESLint configuration to allow, only for the components package, importing from `ariakit` and `framer-motion`, as initially suggested in https://github.com/WordPress/gutenberg/pull/62919#discussion_r1665489822

## Why?
<!-- Why is this PR necessary? What problem is it solving? Reference any existing previous issue(s) or PR(s), but please add a short summary here, too -->

For better DevEx. The reason they are disabled in the first place is that they should be only consumer by the `@wordpress/components` package, so this ESlint config change just puts that advice in practive.

## How?
<!-- How is your PR addressing the issue at hand? What are the implementation details? -->

- Added a rule override in the ESLint config
- Removed unnecessary `eslint-disable` comments for `ariakit` and `framer-motion` imports in the components package

## Testing Instructions
<!-- Please include step by step instructions on how to test this PR. -->
<!-- 1. Open a post or page. -->
<!-- 2. Insert a heading block. -->
<!-- 3. etc. -->

- Make sure that the project builds without ESLint errors
- Make sure that there are no leftover unnecessary `eslint-disable` comments left in the components package
- Make sure that `ariakit` and `framer-motion` imports still generate an ESLint error when imported outside of the components package
