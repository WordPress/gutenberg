# Issue #71725: ColorPalette: deselecting color should respect the clearable property

- URL: https://github.com/WordPress/gutenberg/issues/71725
- Author: ssang
- Created: 2025-09-17T17:58:18Z
- Updated: 2025-10-22T14:42:24Z

## Body

### Description

The expectation of setting `clearable={false}` would be that deselecting a color is not possible as that is the same thing as clearing the selection. Currently, it goes on to call the `clearColor` function.

### Step-by-step reproduction instructions

1. Setup `ColorPalette` with `clearable` set to false
2. Select and deselect color

### Screenshots, screen recording, code snippet

Issue seems to be on line 81 of the component

```
onClick={
    isSelected ? clearColor : () => onChange( color, index )
}
```

### mirka on 2025-10-13T17:12:25Z

URL: https://github.com/WordPress/gutenberg/issues/71725#issuecomment-3398385371

Unfortunately the description for the `clearable` prop in this component (as well as in `GradientPicker`) states that this  prop is about **whether the "Clear" button is available**, not whether the value itself is clearable. And since this prop is already used everywhere, changing this behavior now is going to have back compat implications.

Can this be worked around on the consumer side by blocking deselection in the `onChange` handler?
