# Issue #53541: Storybook: Make sure that subcomponents are properly documented

- URL: https://github.com/WordPress/gutenberg/issues/53541
- Author: mirka
- Created: 2023-08-10T20:15:31Z
- Updated: 2025-03-18T18:39:05Z
- Comments: 7 of 7

## Body

Storybook 7 (#53520) does not support the display of subcomponents in the props tables, so they had to be removed.

We should go through the affected components and make sure that they are appropriately documented in some way or another. Simple subcomponents may be sufficiently documented just as a story of the parent component (e.g. [`DropdownContentWrapper`](https://wordpress.github.io/gutenberg/?path=/docs/components-dropdown--with-more-padding)). More complex subcomponents may warrant their own story pages. Maybe there are other ways as well.

FYI, you will need the prop `story` for ArgsTable to show controls for the main story, you can explicitly set its value as 
```
<ArgsTable story="^" />
```

or import PRIMARY_STORY from `addon-docs`
```
{
     PRIMARY_STORY
 } from '@storybook/addon-docs';
<ArgsTable story={PRIMARY_STORY} />
```

Found similar usage in [equinor/design-system](https://github.com/equinor/design-system), they used a [PropsTable](https://github.com/equinor/design-system/blob/dc8c22fcf950bab923ed11f9432bdb76e7891924/packages/eds-lab-react/.storybook/components/PropsTable.tsx#L3) in mdx stories. Example [Navigation-tabs stories](https://storybook.eds.equinor.com/?path=/docs/navigation-tabs--docs)
