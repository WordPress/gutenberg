## Body

## What?

See #77462 (point **T1**).

Adds the first unit tests for the `@wordpress/theme` runtime — `ThemeProvider` and the `useThemeProviderStyles` hook.

## Why?

These are central to the package but were untested: coverage of defaults, setting inheritance, nested providers, and the `isRoot` behavior before stabilizing.

These tests help gaining confidence when making future changes to the package.

## How?

Two test files under `packages/theme/src/test/`, plus `@testing-library/react` as a dev dependency. The two suites have distinct, non-overlapping responsibilities:

- **`theme-provider.test.tsx`** asserts the _behavior_ users get: the resolved CSS custom property values produced by the provider.
- **`use-theme-provider-styles.test.tsx`** asserts the hook's _resolution contract_ and the legacy token bridge.

<details>
<summary>What the tests cover</summary>

**`theme-provider.test.tsx`** (component) — reads resolved CSS custom properties rather than implementation details:

- Renders children.
- Defines the brand token from `color.primary` and the surface token from `color.background` within its subtree, and does **not** define them outside the provider (scoping is contained).
- Applies `--wpds-cursor-control` from `cursor.control`.
- **`isRoot`** — defines the token on the document root when set, and leaves the root untouched by default.
- **Nested providers** — a nested provider inherits the parent's values, can override them, and resolves each setting independently (overriding `color.primary` still inherits `color.background` and `cursor`).

**`use-theme-provider-styles.test.tsx`** (hook):

- **`resolvedSettings`** — resolution precedence per setting: local prop > inherited from a parent provider > built-in default.
- **Legacy bridge** — derives `--wp-admin-theme-color*` from the primary seed and wires the `--wp-components-color-*` aliases onto the `wp-admin` and semantic tokens.
- **`cursor`** — sets / omits `--wpds-cursor-control`.

Semantic `--wpds-*` token _values_ are covered once, by the component suite; the hook suite owns the resolution logic and legacy bridge. Seed-adjustment/ramp math is out of scope here (it belongs to the color-ramps tests).

The CSS module is mocked with a real class name so jsdom can match the generated rules and compute the custom properties (the global Jest mock would otherwise leave the class `undefined`).

</details>

<details>
<summary>Note on jsdom</summary>

jsdom does not cascade custom properties to descendant elements, so values are asserted on the provider's own scoping element (where the property is defined and from which real children inherit) and on the document root for `isRoot`.

</details>
