# Lists (✨ new)

![List](https://user-images.githubusercontent.com/618551/61067028-45ba3d80-a3cc-11e9-955a-5ed575b980df.png)

## Audit

I'm starting this issue with a new component because many of the same concepts and patterns found within **Menus** and **Panel** can be generalized into a new component. By creating a more generalized component, we can standardize the visuals and functionality of common patterns. Lists can be broken down into these sub-components:

- **List**
- **ListGroup** (similar to the existing MenuGroup)
- **ListItem** (similar to the existing MenuItem)
- **CollapsibleList** (similar to the existing Panel)

The libraries that most resemble this can be seen in [MDC React](https://github.com/material-components/material-components-web-react/tree/master/packages/list), [Material UI](https://material-ui.com/components/lists/#lists), and [RMWC](https://rmwc.io/lists). The closest Polaris example I could find is their [Resource List](https://polaris.shopify.com/components/lists-and-tables/resource-list). Ant has a [List](https://ant.design/components/list/) component as well.

### ListGroup

![image](https://user-images.githubusercontent.com/618551/61074848-44920c00-a3de-11e9-9d8e-828ebbd2d442.png)

- Similar to MenuGroup. It groups lists together.

Example structure:
```
ListGroup

── ListItem
```

### ListItem

![image](https://user-images.githubusercontent.com/618551/61075954-b408fb00-a3e0-11e9-9faa-89223d2953a9.png)

- Similar to MenuItem. An individual item in a List.
- Provides text and graphics either as props or separate ListItemText, ListItemGraphic (similar to the `icon` prop on MenuItem), and ListItemMeta (similar to the `shortcut` prop on MenuItem) components.

Structure:
```
List
─ ListItem
── ListItemGraphic
── ListItemText
── ListItemMeta
```

## Audit

Menus mirror the List components above except for the additional "Menu" component. Because of this, I won’t go into detail for each component. All of the same props are available for each component. This is how Material implements Menus in their [React library](https://href.li/?https://github.com/material-components/material-components-web-react/tree/master/packages/menu). I’m not sure how it works technically, but they share the same props. Is there a term for this type of component? A component with a shared API?

- **Menu** 
- **MenuList** = List
- **MenuListGroup** (previously: [MenuGroup](https://github.com/WordPress/gutenberg/tree/master/packages/components/src/menu-group)) = ListGroup 
- **MenuListItem** (previously: [MenuItem](https://github.com/WordPress/gutenberg/tree/master/packages/components/src/menu-item)) = ListItem 

### Note on [MenuItemsChoice](https://github.com/WordPress/gutenberg/tree/master/packages/components/src/menu-items-choice)

Choosing one option from a list, either exclusively (radio) or multiple (checkbox), is a common pattern, but I think it could be built with the proposed component additions and changes:

![image](https://user-images.githubusercontent.com/618551/61085857-f3dadd00-a3f6-11e9-91bf-f19369c0dcdd.png)

I suggest that this exclusive/multiple choice selection be a prop on the **MenuList** component instead of its own separate component. For example:

```jsx
<MenuList exclusive>
     <MenuListItem />
     <MenuListItem />
</MenuList>
```

An alternative may be to provide the prop on MenuListGroup instead:

```jsx
<MenuListGroup exclusive>
     <MenuList>
          <MenuListItem />
          <MenuListItem />
     </MenuList>
</MenuListGroup>
```

### [DropdownMenu](https://github.com/WordPress/gutenberg/tree/master/packages/components/src/dropdown-menu) and [Dropdown](https://github.com/WordPress/gutenberg/tree/master/packages/components/src/dropdown)

One big difference between Menus and Lists is that Menus have a shadowed container (usually activated by a button) that appears once clicked.

I could use some help figuring out the best approach for handling the element that activates the Menu. Some systems have a **MenuSurfaceAnchor** or **MenuSurface** components and I’m having a hard time sorting it out. For example, I don’t know exactly what DropdownMenu and Dropdown are and how they are different. I couldn't figure it out from the documentation, which leads me to think it could be improved.

# Feedback

The feedback I'm looking for is related to naming, structure, and composition. I'm not looking for visual feedback of the components. I'm also not examining each prop for each component; only the ones that I think are relevant for the audit. I know this issue is a lot to take in, and I appreciate any feedback you have.

- Is it viable to have a generic List component?
- I could use some help structuring the Collapse component. Seems like we might want the same collapse functionality for other components. Should it be some sort of wrapper component?
- Is there a name for components that share props? Shared API?
- What's the difference between DropdownMenu and Dropdown?

# Props audit

As an addendum, here is a deeper evaluation of the props for these components. This is an effort to expand the components to be more useful and to answer the [question](https://github.com/WordPress/gutenberg/issues/16367), "Are properties well thought out and consistently applied?" This only covers visual props. Event handler props will be evaluated at a later date.

### Menu/List

Because these components are almost the same, I'll audit the props together. Example of props we could include in the new List component:

#### Props

**List**
- **dense**
- **avatarList**: uses larger leading graphics, suitable for avatars.
- **twoLine**: two lines of text for the ListItems.
- **checkboxList**: multiple selection in a list.
- **radioList**: exclusive selection in a list.

**ListItemText**
- **primaryText**: primary dark text
- **secondaryText**: secondary lighter text

**ListItemGraphic** and **ListItemMeta** components can accept text, image, or a component.
