# Issue #71316: Components: Remove pointer styling from Button component

## Body

## What problem does this address?

The hand cursor on buttons [applied via `cursor: pointer` styling](https://github.com/WordPress/gutenberg/blob/88f16d8c030f9b7480abbe36eb24b342a26adf7b/packages/components/src/button/style.scss#L15) is redundant and can confuse users who might expect pointer cursors to signify a link, since buttons benefit from strong visual affordance (unlike links).

Related resources:

- [W3C User interface guidelines](https://www.w3.org/TR/CSS2/ui.html#propdef-cursor)
   - > pointer: The cursor is a pointer that indicates a link.
- [Apple Design: Pointing devices](https://developer.apple.com/design/human-interface-guidelines/pointing-devices)
   - > Pointing hand: The content beneath the pointer is a URL link to a webpage, document, or other item.
- [Microsoft](https://learn.microsoft.com/en-us/windows/win32/uxguide/inter-mouse?redirectedfrom=MSDN)
   - > Buttons and sliders have strong affordance. [...] Text and graphics links use a hand or "link select" pointer (a hand with the index finger pointing screen shot of hand with index finger pointing ) because of their weak affordance. [...] To avoid confusion, it is imperative not to use the hand pointer for other purposes. For example, command buttons already have a strong affordance, so they don't need a hand pointer
- ["Buttons shouldn't have a hand cursor"](https://medium.com/simple-human/buttons-shouldnt-have-a-hand-cursor-b11e99ca374b#.b33l7fivt)

Previous discussions:

- https://github.com/WordPress/gutenberg/issues/63856#issuecomment-2262657171 (@jameskoster )
   - > Contentious: cursor: default on resting state. Some more context https://github.com/WordPress/gutenberg/issues/63756#issuecomment-2245456088, which essentially boils down to "only links should use the pointer cursor". I think there's a nuance here, since there are several examples of buttons in the site editor that change the URL on click. Let's discuss.
- https://github.com/WordPress/gutenberg/issues/63756#issuecomment-2245456088 (@mirka )
   - > I'll also add that the https://github.com/tailwindlabs/tailwindcss/issues/8961#issuecomment-1533249212 is to use cursor: pointer for links only.

## What is your proposed solution?

Remove the default pointer cursor styling on the `Button` component:

https://github.com/WordPress/gutenberg/blob/88f16d8c030f9b7480abbe36eb24b342a26adf7b/packages/components/src/button/style.scss#L15

Open questions:

- What about `Button`s that specify a `href` prop?
- What about [tertiary buttons](https://wordpress.github.io/gutenberg/?path=/story/components-button--tertiary)? Do they provide enough visual affordance without a pointer?
- As @jameskoster described in https://github.com/WordPress/gutenberg/issues/63856#issuecomment-2262657171 , what about buttons that aren't links, but behave as links in how they incur page navigations?

### RohithMacharla11 on 2025-08-25T17:29:15Z

URL: https://github.com/WordPress/gutenberg/issues/71316#issuecomment-3221127629

Thanks for the feedback @aduth @mirka 🙏

I believe removing cursor: pointer from the Button component is the right step forward. By default, browsers render <button> elements with the default cursor, and that’s the expected UX convention. Using a pointer cursor suggests a “link-like” behavior, which can be misleading for accessibility and consistency.

If a Button is being used in places where it acts like a link, that’s really a misuse of the component. The correct approach is to use <a> or a navigation component in those cases, not a button styled as a link. Keeping the pointer cursor just to cover those cases feels like masking an implementation issue rather than solving it.

So instead of considering this a regression, I’d say it’s an improvement in semantics and accessibility, pushing us toward better markup practices.

Happy to collaborate on updating any misused Button cases if they come up, but I strongly feel this change should move forward as is.
