## Body

## Description
The `Popover` components are now refreshed every 500ms in order to recalculate their size or position.

Fixes WordPress/gutenberg#11194.

## How has this been tested?
Manually following these steps:
1. Activate the tips on More > Options > Enable tips
2. Switch to the Fullscreen Mode without dismissing the tip
3. Make sure the tip is placed under the '+' icon (see After screenshot below).

const { repositionHook } = this.props;

// packages/nux/src/components/dot-tip/index.js

I would agree this is the wrong fix for the issue at hand, as it adds complexity. It also assumes specific editor interface configurations, that although they are relatively stable might change in the future in which case this implementation will need to be revisited.

I would suggest a copule of other possible approaches to fixing this issue:

1. Toggle off the tips when fullscreen mode is engaged — similar to pressing the X button. Essentially a click that isn't dismiss or next, in this case "fullscreen", feels like an implicit "I'm done with tips" click.
2. Toggle them off and on again.
3. Change how the tips work so they are either inline, or perhaps even truly modal — i.e. you HAVE to click next or dismiss them before you can proceed. 
4. Consider this more or less a non-issue. The tips aren't _that_ disconnected, and as soon as you press Next, the subsequent tooltip is correctly positioned.

Overall, I would imagine so many changes happening to tips in Phase 2 that I don't think it would be too healthy for the code to optimize for this particular configuration right at this point. 

Option 3 is my personal favorite at it might also have benefits for accessibility. More than that, there are a bunch of issues filed in the Tips label at the moment, that are related to the fact that you _can change content below the tips without dismissing them_. For example you can toggle on or off the settings tab multiple times while still reading the tip that suggests you toggle them on.

Just to be clear though, this is not a Calypso-only fix. 🙂 
If folks toggle into fullscreen with the NUX (or any other popovers, for that matter) visible, the popover doesn't reposition.

I think this solution is still a worthwhile extension for the `Popover` component, but I have to agree the better one would be to observe the anchor position.

We already use `MutationObserver` in Gutenberg, so we might want to try listening with something roughly like this:

```es6
const observer = new MutationObserver( mutations => {
  if ( _.find( mutations, { type: 'attributes', attributeName: 'style' } ) ) {
    this.refresh();
  }
} );

observer.observe( this.anchorRef, { attributes: true } );
```

(I'm not super familiar with `MutationObserver`, maybe there's a better way to check if only the anchor position has changed, instead of any style?)

Also, I'd probably still only enable the observer if some sort of `repositionWhenAnchorRepositions` prop is true, to keep the existing behaviour untouched, and avoid performance issues.

But `IntersectionObserver` only executes a callback whenever one element intersects either the device viewport or a specified element.

So I finally went ahead with the `setInterval` idea, using a 200ms interval which apparently doesn't cause any performance issue, but it would be great if anyone else could confirm it.
