## Body

## What?

Closes #32123

Removes the `icon` prop from web `RangeControlProps`. It was added to the TypeScript types during the TS migration (#40535) but never implemented on web. `beforeIcon` and `afterIcon` are the supported web alternatives.

The prop remains supported on native (mobile), where it is passed through to `RangeCell` / `StepperCell`.

## Why?

The README documents `icon` as mobile-only, but the web types incorrectly exposed it as a valid prop. That led to the assumption it was broken on web when it was never wired up. Removing the phantom type aligns the public API with actual behavior without adding deprecation runtime overhead for a no-op prop.

## How?

1. Remove `icon` from `RangeControlProps` in [`packages/components/src/range-control/types.ts`](packages/components/src/range-control/types.ts).
1. Remove the unused `icon` Storybook argType in [`packages/components/src/range-control/stories/index.story.tsx`](packages/components/src/range-control/stories/index.story.tsx).

Native callsites (for example `columns/edit.native.js`) and the README mobile documentation are unchanged.

## Testing Instructions

1. Open a post and insert an Image block. Confirm dimension sliders still work and no console warnings appear.
1. In a TypeScript file, use `<RangeControl icon="foo" />` and confirm the type checker reports that `icon` is not a valid prop.
1. Optionally run `npm run test:unit -- packages/components/src/range-control` to confirm existing tests pass.
