### mirka on 2024-01-04T15:48:13Z

URL: https://github.com/WordPress/gutenberg/issues/57217#issuecomment-1877322573

> Perhaps there is additional context that I am missing, but I don't understand why the presence of a suffix should result in the omission of the chevron, that seems quite unrelated?

I get where you're coming from. What we're aiming for is a simple API that is predictable across similar components (e.g. InputControl and SelectControl both have this `prefix`/`suffix` API), and is generic enough to cover all use cases without needing to add more props every time a new use case is found. In this case, the single `suffix` prop entirely replacing the default chevron suffix serves a lot more use cases than not, like if you want your custom suffix to come after the chevron, or if you want to use a different chevron icon or color. And frankly, adding a suffix to a Select is pretty niche so we don't have enough established patterns to assume what "most" people would need.

> In terms of design this is what I had in mind

There are a couple of paths we can take depending on the exact requirements.

- If you need the width of the Select to dynamically adjust to the entire length of the text, we probably want to make a new custom "Pagination Select" component, or use CustomSelectControl for more design flexibility. (With a standard SelectControl, you'd need to set a fixed width on the suffix if you also want click through. This is a limitation when using standard `<select>` elements.)
- If you don't need the prefix/suffix text to be in a lighter color, we could just make it part of the `<option>` text when currently selected. This is probably the easiest compromise.
