## Body

Fixes #38241

Fixes the InputControl component's label overflow issue when translations are longer than the English version.

When using WordPress in languages with longer translations (e.g., German), the label text of InputControl-based components (like UnitControl) truncates with ellipsis instead of wrapping. This affects controls like "Letter spacing" in the block editor sidebar and is inconsistent with how ToggleGroupControl handles long labels (which wrap).

## How?
Remove text truncation styles (`overflow: hidden`, `text-overflow: ellipsis`, `white-space: nowrap`) from the BaseLabel styled component in InputControl. This ensures long labels wrap instead of truncating, matching the behavior of ToggleGroupControl labels.

### fcoveram on 2026-01-06T09:53:09Z

URL: https://github.com/WordPress/gutenberg/pull/74301#issuecomment-3714000930

The general approach that I would follow goes as:
1. **Responsive layout.** Change the layout from horizontal to vertical to stack controls when the label overflows its container
2. **Truncate text.** If yet the label overflows, keep the truncate behavior that `InputControl` has.

Text truncation has more issues than wrapping it, but I'm mentioning it as it already exists. Perhaps there is a step in between where wrapping goes before thinking of adding the ellipsis. The responsive layout should support this change.

What do you think?

### ciampo on 2026-01-07T11:29:07Z

URL: https://github.com/WordPress/gutenberg/pull/74301#issuecomment-3718449801

> we can address it at a more foundational level, not just in ToggleGroupControl.

Strongly agree

Re. what solution to adopt: detecting label overflow and change the stack direction (horizontal=>vertical) accordingly may not be trivial depending on how the layout is implemented. For example, I believe the inspector is organized in a 2-col grid layout. It may be hard to implement a solution that can be applied in a foundational level.

Re. truncating or wrapping text on 1+ lines:

- wrapping text over more lines definitely provides more information, but it can cause issues in terms of horizontal alignment with other controls. 
- truncating is the simlpest and most self-contained in terms of layout, and therefore likelky the easiest to apply holistically.

I think my preference would go towards truncating. Or, for added flexibility, defaulting to truncating and offering consumers the choice of truncating vs wrapping via an additional prop?

### jameskoster on 2026-01-07T13:31:20Z

Putting the visuals to one side I'm not the biggest fan of truncation in this case because the important information could be at the end of the label. This may be a dumb example but "Address line 1" and "Address line 2" truncated to "Address lin..." and "Address lin..." isn't great for obvious reasons. So if truncation is utilised I think it should still be possible to discover the full label somehow. I don't know if there's a reliable way to do that, maybe using a tooltip?

On balance I think I would avoid truncation. Wrapping can be a forcing function for consumers to split controls on to separate rows in cases avoiding multi-line labels is desirable. Not a strong feeling though. A prop like @ciampo suggests could work too :)
