## Body

The current set of [Admin UI components](https://github.com/WordPress/gutenberg/tree/trunk/packages/admin-ui/src) is used around Gutenberg, for example, on the new Fonts and AI Connectors pages:

| Fonts | Connectors |

We've just [adopted](https://github.com/Automattic/jetpack/pull/47313) the components also in the Jetpack plugin, where it helps a lot to bring consistency between core and our plugin!

However, we also noticed that there could be some small adjustments to improve the component's visual appearance for consumers:

- Breadcrumbs and Titles should follow the same size
- Header should support adding a logo or symbol
- Page background `#fcfcfc` instead of `#ffffff`
- No double border when tabs are used

## Breadcrumbs and Titles should follow the same size

While both work fine independently, there's an issue when one browses between multiple pages, where some use breadcrumbs, and some use titles. There's a "jump" in text size between the two currently:

<img width="490" height="148" alt="Image" src="https://github.com/user-attachments/assets/c0c79789-41ad-4877-b2f6-6ac550b50e59" />
<img width="350" height="151" alt="Image" src="https://github.com/user-attachments/assets/e30800c9-6a46-49b9-b288-4e3927b2a038" /><br/>
<img width="296" height="126" alt="Image" src="https://github.com/user-attachments/assets/e6b8ec87-c5b7-4853-8dbe-9a557bcf426f" />

Suggest using the same 20/15 from the design system for both. This makes the title slightly smaller than it is today, and breadcrumbs slightly bigger:

## Header should support adding a logo or symbol

It's currently possible to pass `title` prop a logo, which kinda works, but can be fragile in future when header has changes, particularly on mobile. Ad-hoc logo addition, of course, doesn't guarantee consistency between different consumers using the component either like officially supported would.

We propose officially supporting a logo or symbol in the header:

<img width="666" height="149" alt="Image" src="https://github.com/user-attachments/assets/97ae73e6-fb18-4d09-9ace-60769aa0e891" />

Official support would also ensure better semantic support since the logo could go _outside_ the `h2` tag:

<img width="430" height="377" alt="Image" src="https://github.com/user-attachments/assets/2be26d88-c5fa-477a-8a57-22859f670d29" />

It would also avoid [needing to pass a separate](https://github.com/WordPress/gutenberg/issues/75898) `ariaLabel` to maintain good accessibility. Title+logo obviously doesn't work for aria label, since it's not purely just a string, so currently when using logos you have to pass both `title` and `ariaLabel`.


## Page background `#fcfcfc` instead of `#ffffff`

Currently white background lacks dimension between different surfaces, such as when adding cards to the  page:

| #ffffff | #fcfcfc |
|--------|--------|
| <img width="1352" height="894" alt="Image" src="https://github.com/user-attachments/assets/94a68b63-85ee-4f0b-94f8-3a6daecd6769" /> | <img width="1350" height="873" alt="Image" src="https://github.com/user-attachments/assets/5cd36bd6-2e6a-4a01-95d2-9aad4aca1296" /> | 

Full-page containers, such as pages using DataViews tables, would still be fully `#ffffff`.

## No double border when tabs are used

Described in more detail:
- https://github.com/WordPress/gutenberg/issues/75428

By avoiding additional border _above_ tabs, the header layout looks less busy and less boxy:

<img width="1058" height="134" alt="Image" src="https://github.com/user-attachments/assets/54e68a19-2fa2-4312-9f9d-251f41706416" />
<img width="1061" height="127" alt="Image" src="https://github.com/user-attachments/assets/14c17f48-cf58-4c9b-b4fc-843eb8593e3b" />

To separate from content particularly when backgrounds are white (like in full-page DataViews) and since the header is sticky, we'd still keep the bottom-border for headers visible at all times.
