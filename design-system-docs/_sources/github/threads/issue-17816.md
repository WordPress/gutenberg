# Issue #17816: selectControl does not accept "null" as option value

- URL: https://github.com/WordPress/gutenberg/issues/17816
- Author: leorospo
- Created: 2019-10-07T15:56:03Z
- Updated: 2019-10-11T08:18:10Z
- Comments: 2 of 2

## Body

**Describe the bug**
If an option with `value: null` is provided the control will use the option label instead and save it to the DB as a sting.
In case the associated post_meta type is `integer` the editor will thow an error and not save the post at all.

**To reproduce**
Steps to reproduce the behavior:
1. Register a post meta
2. Link it to a selectControl component in the editor
3. Pass an option with `value: null`
4. Select a valid option and then the null one
5. Attempt saving

**Expected behavior**
At SAVE, if the `value: null` option is selected the associated meta value is set to null, or the post_meta row is deleted

**Desktop (please complete the following information):**
 - OS: Windows 10
 - Browser: Firefox Developer Edition
 - Version 70.0b12 (64 bit)

**Additional context**
- Wordpress version: 5.2.3 (couldn't figure out how to check gutenberg version)

Hi @leorospo, thank you for your tests and for reporting this issue.
I did some debugging around it.
I used the following test code:
```
const MySelectControl = withState( {
	size: '50%',
} )( ( { size, setState } ) => (
	<SelectControl
		label="Size"
		value={ size }
		options={ [
			{ label: '-Null', value: null },
			{ label: '-Undefined', value: undefined },
			{ label: '-Empty', value: '' },
			{ label: 'Big', value: '100%' },
			{ label: 'Medium', value: '50%' },
			{ label: 'Small', value: '25%' },
		] }
		onChange={ ( newSize ) => { setState( { size: newSize } ) } }
	/>
) );
```

And I verified the following HTML code was produced:
```
<div class="components-base-control">
    <div class="components-base-control__field">
        <label class="components-base-control__label" for="inspector-select-control-1">Size</label>
        <select id="inspector-select-control-1" class="components-select-control__input">
            <option>-Null</option>
            <option>-Undefined</option>
            <option value="">-Empty</option>
            <option value="100%">Big</option>
            <option value="50%">Medium</option>
            <option value="25%">Small</option>
        </select>
    </div>
</div>
```

The select control is just a wrapper of HTML select and options for styling purposes. Options labels and values are passed as is to the HTML option element.
Values of null and undefined are not accepted values, and they are not rendered at all in the markup.
The documentation for value attribute says:
> The content of this attribute represents the value to be submitted with the form, should this option be selected. If this attribute is omitted, the value is taken from the text content of the option element.
https://developer.mozilla.org/en-US/docs/Web/HTML/Element/option

So it seems that the fact that the label is used as value is something expected in this case.

A possible solution to the specific case you mentioned would be: When generating options, for the null option, use an empty string instead of null, which is accepted. On the onChange function, when an empty string is received, set the value to null instead of the empty string.


I hope this alternative fits your use case. I'm going to close this issue for now; if you would like to add additional details or have a follow-up comment feel free to add them.
