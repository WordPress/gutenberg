## Body

## What?
Closes #70845 

Fixes ToggleGroupControl deselectable options that are initially pressed from being deselected when clicked, preventing visual state issues where buttons become invisible (black-on-black).

## Why?
When a ToggleGroupControl option is pre-selected (like underline decoration for links) and the page is reloaded, clicking on that already-selected option would cause it to become completely invisible due to incorrect deselection logic. This created a severe usability issue where users couldn't see the button state or interact with it properly, particularly in Global Styles → Typography → Links → Decoration.

The root cause was that deselectable toggle options would deselect themselves when clicked, even if they were initially pressed, causing CSS state management conflicts that resulted in black icons on black backgrounds.

## How?

- Added `isInitiallyPressed` state tracking using `useState` and `useEffect`.
- Modified the `buttonOnClick` handler to prevent deselection of options that were pressed on initial render.
- The fix ensures that pre-selected decorations (common for links with default underline) maintain their selected state when clicked.
- Only options that were selected through user interaction (not initially pressed) can be deselected.

## Testing Instructions
1. Go to WordPress Admin → Appearance → Editor → Styles
2. Navigate to Typography → Links
3. Locate the DECORATION control with three buttons: [−] [U] [S̶]
4. Observe that the Underline (U) button is already selected (black background, white icon)
5. Click on the already-selected Underline (U) button
6. ✅ Expected: Button should remain visible and selected (blue background, white icon)
7. ❌ Before fix: Button would become invisible (black background, black icon)

### t-hamano on 2025-07-28T08:09:48Z

The `useEffect` approach doesn't seem like the right approach to me. Let me explain a bit about my findings on why this happens.

The global styles provide initial values based on the theme's default values. For example, suppose the active theme defines the following theme.json:

```json
{
	"version": 3,
	"styles": {
		"typography": {
			"textTransform": "uppercase"
		}
	}
}
```

In this case, the Styles > Typography > Text > Letter Case section applies the `underline` value prop to the `ToggleGroupControl component`:

<img width="317" height="101" alt="image" src="https://github.com/user-attachments/assets/7dd009d2-f398-49bc-8677-40206f8606bd" />

This component is deselectable, so clicking the selected option will trigger `undefined` here:

https://github.com/WordPress/gutenberg/blob/2cd7cb5670a1ce670145a7730e6ace1440e9cb9e/packages/block-editor/src/components/global-styles/typography-panel.js#L335-L343

However, because of the default text-transform style provided by theme.json, the value provided to the `ToggleGroupControl` component remains `uppercase` rather than `undefined`.

<img width="745" height="343" alt="toggle-group-control" src="https://github.com/user-attachments/assets/ba211254-94f4-4efe-a525-f035ab78b8dd" />

So I think the root cause is that **the `onChange` prop is expecting the value to become `undefined`, but we are providing a value that is not `undefined` to the `value` prop.**

I don't know if this behavior is a bug in the `ToggleGroupControl` component itself, but you can reproduce the same issue in Storybook with the following code:
