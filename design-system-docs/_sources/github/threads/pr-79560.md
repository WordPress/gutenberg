## Body

## What?
Adds a new `Menu` component to `@wordpress/ui`, backed by Base UI Menu.

## Why?
`@wordpress/ui` needs a dropdown menu primitive that follows the package's overlay conventions and can be used alongside the existing Dialog, Drawer, Popover, and form primitive overlays.

## How?
- Adds `Menu.Root`, `Trigger`, `Popup`, `Portal`, `Positioner`, item, link item, label/description, group, separator, radio/checkbox, and submenu subcomponents.
- Keeps the implementation close to Base UI while following `@wordpress/ui` overlay conventions: `ThemeProvider`, compat overlay portal slot, positioner slot, shared item-popup chrome, shared dropdown motion, and WPDS tokens.
- Aligns menu item layout with the existing `@wordpress/components` menu: a two-column grid, prefix/indicator column, content/suffix area, full-row hover highlight, and support for item labels/descriptions.
- Adds Storybook examples for default menus, rich item content, nested submenus, checkbox/radio groups, link items, and custom positioning, plus focused tests for semantics, portal/positioner slots, submenu defaults, and ref forwarding.

## Testing Instructions
1. Run `npm run test:unit packages/ui/src/menu/test/index.test.tsx -- --runInBand`.
2. Run `npm run lint:js -- packages/ui/src/menu`.
3. Run `npm run lint:css -- packages/ui/src/menu/style.module.css`.
4. Run `npx tsgo --build packages/ui/tsconfig.json`.
5. Run `npm run storybook:dev`.
6. Open **Design System / Components / Menu** and inspect the Default, Rich Items, Submenu, Checkbox Items, Radio Items, and Positioning stories.

### Testing Instructions for Keyboard
1. In the Menu Storybook stories, focus the trigger with Tab.
2. Press Enter or Space to open the menu.
3. Use Arrow keys to move between menu items.
4. Press Escape and confirm the menu closes and focus returns to the trigger.
5. In the submenu story, open the submenu and confirm keyboard navigation remains inside the menu structure.

As of now, the new `Menu` component mostly recreates the layout and functionality (eg `prefix` / `suffix` props, item label, item description, grid layout...) that were done for the ariakit-based `Menu` component in `@wordpress/components`. I then used WPDS tokens and the same styles used for other overlays/dropdowns in the `@wordpress/ui` package.

Happy to discuss next steps, for example:

- should we remove some/all these custom abstractions (eg `prefix` / `suffix` props, item label, item description, grid layout) and adhere closer to the raw base ui APIs?
- should we make design changes? For example, I remember discussing:
  - allowing a prefix alongside check/radio
  - reviewing the indicators used for checkbox and radio
