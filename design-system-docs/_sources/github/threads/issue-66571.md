## Body

> [!NOTE]
> This may only be a reproducible issue on Windows OS. Additional testing on Windows OS would be welcome.

### Description

The "Add New Pattern"  modal allows us to select a pattern category that is rendered by the `FormTokenField` component.

When I press the tab key in this pattern category, I would expect the "Synced" toggle to get focus, but instead the modal disappears and focus is lost.

I have not been able to identify the cause, but I suspect it might be an issue that occurs when the Modal component and the FormTokenField component are used together.

This issue appears to have occurred since WP 6.4, when pattern categories were implemented.

### Step-by-step reproduction instructions

- Select "Create pattern" from a block toolbar.
- Press the tab key repeatedly.

### afercia on 2025-01-29T15:05:53Z

URL: https://github.com/WordPress/gutenberg/issues/66571#issuecomment-2621912495

I'm able to reproduce on macOS Chrome as well.

My guess:
- The modal closes when it thinks focus is outside of the modal. This is the intended behavior, it's the 'click outside to close' implementation.
- At some point, when tabbing away from the `TokenInput`, the modal thinks focus is no longer inside the modal, and closes.
- Note that when tabbing bacwards (Shift+Tab) the modal works as expected.

I quickly commented out [these two lines](https://github.com/WordPress/gutenberg/blob/1a7f015462950a848ece1195f0216121e9b98dad/packages/components/src/form-token-field/token-input.tsx#L52-L53) for debugging purposes and yes it seems this `onBlurHandler` is responsible for the unexpected closing. Of course this is not a fix, it's just for debugging purposes.

Also, I noticed `TokenInput` rerenders when tabbing away from it, which may not help when inside the Modal component.

Aside:
I'm seeing this in the console and it seems to happen only the first time the Modal dialog opens:

![Image](https://github.com/user-attachments/assets/e1ae6f74-dea6-4ff3-9fca-b67a4aea4602)

I think this is a React warning that is unrelated and it happens also for the 'Rename' modal dialog. Basically whatever modal dialog that opens from an UI rendered within the `components-popover__fallback-container` element (e.g. dropdown menus) will trigger this warning. The Modal component implementation intentionally uses `aria-hidden` instead of `inert` so I tend to think the react warning is opinionated and we should ignore it.

### yogeshbhutkar on 2025-07-02T08:01:03Z

URL: https://github.com/WordPress/gutenberg/issues/66571#issuecomment-3026861700

Thanks for raising the issue!

I did some research, and here are my findings.

As already pointed out, this issue is not OS-specific and can be reliably reproduced. To do so, ensure the `SuggestionList` is displayed and then press `Tab`. Please note that the issue cannot be reproduced with the `SuggestionList` collapsed.

Example:

![Image](https://github.com/user-attachments/assets/b70efabb-6761-4416-ac10-378839b1fd1c)

I believe the focus gets lost because, by convention, `Tab` is supposed to move the focus to the next focusable element. In the current order, after `Token Input`, next in the line is `SuggestionList's` list box.

Ref:
https://github.com/WordPress/gutenberg/blob/c503fa38eadaf38d874e0c321192851d2d747a56/packages/components/src/form-token-field/index.tsx#L194-L196

Here, `hasFocusWithin` would return `False`, which would cause `isExpanded` to also be set to `False`, resulting in the list box being closed. When this happens, the focus gets lost.

To resolve this, I believe the best way is to add a `keydown` handler, which would ensure that the listbox is closed before moving the focus to the next focusable element, thereby preserving the focus.

As this bug can be traced down to the `FormTokenField` component, it should be replicable at other places where this component is used within a `Modal`. For example, a similar bug can be reproduced within the `Duplicate Pattern` Modal.

Ref:

https://github.com/user-attachments/assets/bc216e18-bb14-4cc7-8dc5-ff3663af96d1
