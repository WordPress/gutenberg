Tests are still failing, and so I looked a bit more into what could be the reason:

- the error is caused by [this line](https://github.com/react-dates/react-dates/blob/master/src/components/DayPicker.jsx#L1143) in the `DayPicker` component, because the `height` variable is `NaN`
- That values comes from [`adjustDayPickerHeight`](https://github.com/react-dates/react-dates/blob/master/src/components/DayPicker.jsx#L879), which is called by [`calculateAndSetDayPickerHeight`](https://github.com/react-dates/react-dates/blob/master/src/components/DayPicker.jsx#L901)
- In that function, the `NaN` comes from the `monthTitleHeight` height variable, which should be [stored in the component's local state](https://github.com/react-dates/react-dates/blob/master/src/components/DayPicker.jsx#L894)
- That variable is actually [set by children components of `DayPicker`](https://github.com/react-dates/react-dates/blob/master/src/components/DayPicker.jsx#L1217), in particular by the [`CalendarMonth` component](https://github.com/react-dates/react-dates/blob/9494adb4616e2b42229bd510b789694dd9711ed4/src/components/CalendarMonth.jsx#L151)
- Finally, the `NaN` value comes from the fact that [the `calculateDimensions` utility function is trying to read the `margin{Top|Left|Bottom|Right}`  property](https://github.com/react-dates/react-dates/blob/master/src/utils/calculateDimension.js#L27-L29) from the element's computed styles, but those properties don't seem to be defined on that `style` object.

Previously, not using fake timers made it so that these functions were not run (probably the expect assertion happened before them).

Not sure if there's a way to fix this on our end.

We could open an issue in the `react-dates` repository, and in the meantime:
- either use fake timers for all tests BUT this specific failing test (and leave a comment why?);
- or put this PR on pause until we hear back from `react-dates` folks
