# Issue #56548: Add backwards compatibility to Ariakit implementation of `Composite`

## Body

## What problem does this address?

The last step in migrating from `reakit` to `ariakit` (#53278) is to drop support in [`Composite`](https://github.com/WordPress/gutenberg/tree/c86154f838cef387785a948e30a5a7c7cbbae47f/packages/components/src/composite). [All of the consumers of the `reakit` implementation](https://github.com/WordPress/gutenberg/issues/55224#issuecomment-1756246824) [have been migrated](https://github.com/search?q=repo%3AWordPress%2Fgutenberg+__unstableComposite&type=code), so now we need to remove the implementation. The first step in doing this is to ensure API compatibility.


## What is your proposed solution?

In order to make the public migration smoother, we should implement support in the `ariakit` implementation for the `reakit` API. The only part currently missing is [`useCompositeState`](https://github.com/WordPress/gutenberg/blob/c86154f838cef387785a948e30a5a7c7cbbae47f/packages/components/src/composite/index.ts#L18) ([ref](https://reakit.io/docs/composite/#usecompositestate)).

As per [these thoughts on the matter](https://github.com/WordPress/gutenberg/pull/54225#issuecomment-1718713544), it will involve the following...

```js
function convertInput(props) {
  ...
}

function convertOutput(props) {
  ...
}

function useCompositeState(props) {
  const store = useCompositeStore(convertInput(props));
  const state = store.useState();
  return convertOutput({ ...store, ...state });
}
```

...where the implementation of `convertInput` and `convertOutput` will need to reference Reakit's [`useCompositeState`](https://reakit.io/docs/composite/#usecompositestate) API reference and Ariakit's [`useCompositeStore`](https://ariakit.org/reference/use-composite-store) API reference for the differences.
