## What?
Migrates `Theme` away from Emotion styles.

## Why?
This is one of the higher-risk pilot components because it validates replacing Emotion-generated CSS custom properties with non-Emotion output while preserving nested theming behavior.

## How?
- Replaces the Emotion `styles.ts` file with `style.module.scss` for the wrapper color rule.
- Converts generated theme variables into inline CSS custom properties.
- Preserves user `style` precedence over generated theme variables.
- Uses the shared `PolymorphicElement` utility so `Theme` continues to support the `as` prop previously handled by Emotion styled components.
- Adds test coverage for the `as` prop.
