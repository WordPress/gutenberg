# Issue #21745: Emotion introduces unnecessary prefix bloat

- URL: https://github.com/WordPress/gutenberg/issues/21745
- Author: tellthemachines
- Created: 2020-04-21T05:11:20Z
- Updated: 2025-12-01T11:40:19Z
- Comments: 7 of 7

## Body

**Describe the bug**

The CSS output from Emotion includes lots of prefixes for browser versions we no longer support, such as `display: -webkit-box; display: -webkit-flex; display: -ms-flexbox;` for the `flex` property. All together, they result in quite a bit of bloat:

<img width="319" alt=" " src="https://user-images.githubusercontent.com/8096000/79826899-44e51c00-83e0-11ea-8e3d-99bdad256e11.png">

The problem is that Emotion doesn't support use with Autoprefixer, and instead uses a tool called [stylis](https://github.com/thysultan/stylis.js), that doesn't support Browserslist. This means we can't feed Emotion our standard browser support list. It also means we'll be unable to leverage Autoprefixer's smart grid support when using Emotion.

I'm tempted to suggest disabling Emotion's auto inclusion of prefixes altogether, [as detailed here](https://github.com/emotion-js/emotion/issues/400), because we barely need prefixes anymore, even for IE11. 

**To reproduce**
Steps to reproduce the behavior:
1. Inspect CSS of a component in Storybook, e.g. [RangeControl](https://wordpress.github.io/gutenberg/?path=/story/components-rangecontrol--default)
2. Verify prefix bloat


**Expected behavior**

Expected prefixing to be compliant with our [Browserslist config](https://github.com/WordPress/gutenberg/blob/master/packages/browserslist-config/index.js).
