## What?
- Refactors `TabPanel` unit tests in preparation for updating offering `TabPanel` as a controlled component.

## Why?
- Ensuring we have proper test coverage of the current `TabPanel` will certify current behaviour and provide greater confidence when updating the component.
- Refactoring the `TabPanel` unit tests to use `describe.each` will make it easier to test the proposed controlled version of this component

## How?
- Attempts to find the middle ground between the new tests proposed within [#46704](https://github.com/WordPress/gutenberg/pull/46704) and current preferred approach to testing controlled/uncontrolled components
- Rather than a straight copy of the tests from [#46704](https://github.com/WordPress/gutenberg/pull/46704), this PR tweaks those tests so they match and pass with the component's current behaviour
