## Body

## What?
Add support for non-percent CSS units (rem, em, px, vw, vh) for background image position in BackgroundImagePanel (Poetry block) and Cover block focal point controls.

## Why?
Previously, background image positioning was limited to percent-based values via the FocalPointPicker. Users needed the flexibility to use other CSS units for positioning backgrounds in different scenarios (e.g., `2rem 3em` or `10px 20px`).

## Testing Instructions
1. Open a page/post and add a Poetry block (or any block with background image support)
2. Open "Settings" → "Background" panel
3. Add a background image
4. Locate the "Focal point" section with X/Y position controls
5. Test with different unit controls.

Thanks for the question! We did consider this approach. 

The current design keeps unit flexibility in the parent component (via `__experimentalHideControls`) because:

1. **FocalPointPicker's core purpose** is visual focal point selection with normalized coords (0-1), arbitrary unit conversion adds unnecessary complexity
2. **Separation of concerns**, FocalPointPicker remains focused; parents handle their specific unit requirements  
3. **Backward compatibility**, Existing consumers unaffected

We accept some code duplication across components as a trade-off for this clarity. If the team prefers unit support directly in FocalPointPicker, we can refactor it to be a general position picker.
