## Body

## What?

Extracts the IME-handing logic we added in #46827 etc. into a higher-order function for easier reuse.

### Affected components

- Autocomplete
- ComboboxControl
- FormTokenField
- Modal

## Why?

For code DRYness and clarity, as well as in preparation for fixing #58188 which will likely require another one of these.

This kind of HOF doesn't seem necessary outside of the components package yet, but we might want to consider moving it to `@wordpress/compose` if we start to see more use cases. Currently the only usage is [in the Command Palette](https://github.com/WordPress/gutenberg/blob/888c78e16212afd3ff08148512387bbdb9132e76/packages/commands/src/components/command-menu.js#L256-L262) — although I'm not exactly sure if it's still needed, since there's already a handler in the Modal. ~In any case the Escape handling in there is broken right now (#59080).~

## Testing Instructions for Keyboard

Smoke test the affected components to make sure that they're ignoring IME events as before.

For example, open a `Modal` in the Storybook and use a CJK IME to type in the text field inside the dialog. <kbd>Esc</kbd> keypresses during a composition should not close the modal.

@tyxla Not really, at least in an easy or reliable way. There is no official support for IME composition in [Puppeteer](https://github.com/puppeteer/puppeteer/issues/4981) nor [Playwright](https://github.com/microsoft/playwright/issues/5777) yet. At this stage, I think we'd have a bigger impact on QA if we focused on developer awareness, for example adding IME info to the keyboard testing guides for a11y, or adding some kind of linter rule for `onKeyDown` stuff. I'll do a keydown handler audit in the components package and see what we can do.
