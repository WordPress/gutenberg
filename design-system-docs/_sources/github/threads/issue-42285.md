# Issue #42285: Post author combo box receives focus on page load

## Body

### Description

When editing an existing post and you have at least 25 users to select from the post author combo box, focus is automatically placed on the combo box after page load is complete. I expect this to not happen.

### Step-by-step reproduction instructions

1. Ensure you have 25+ users on your site.
2. Open an existing post or page.
3. Notice how focus is moved to the post author combo box just after the page finishes loading.

### alexstine on 2022-09-22T04:09:12Z

URL: https://github.com/WordPress/gutenberg/issues/42285#issuecomment-1254498845

Thanks all for looking in to this. I think I finally found what is causing it.

https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Attributes/aria-activedescendant

The attribute itself does not seem to be the problem, but I believe the onChange is updating the currently selected index which causes a focus force because that is what the attribute is intended to do. Sadly, this is another example of how ARIA comes back to haunt us.

I am working on figuring out if there is much that can be done. I may try to inject the attribute after the initial value is set but this is getting to be quite complex.

### alexstine on 2022-09-22T06:21:36Z

URL: https://github.com/WordPress/gutenberg/issues/42285#issuecomment-1254579510

Well, my PR can in my opinion, only be described as a fun work of art. I have no idea why it works or how it works, but the important take away is this. I am simply manipulating at which point `aria-activedescendant` has a value. For example, the attribute should only exist when the user moves their focus to the combo box but not before this due to the setting of the default value. When the value changes, it updates the selection index which then tells `aria-activedescendant` to update. Whenever this attribute updates, it moves focus because that is what it is meant to do. At least immolating focus. From my understanding, most combo boxes of this type use a button to trigger them and this may be why other large projects do not see such an issue. It could also be that other combo boxes are not setting the default value async from an API.

Anyway, my thoughts at nearly 1AM. Hopefully someone follows this.

### joedolson on 2022-09-22T15:42:03Z

URL: https://github.com/WordPress/gutenberg/issues/42285#issuecomment-1255213027

Interesting. Reading the docs, this makes sense with what I was seeing. `aria-activedescendant` doesn't actually set focus, it just informs AT what element has focus. Which would align with getting information about focus, but having keyboard navigation be located at the top of the screen.

It seems to me like `aria-activedescendant` should only be set at all if the composite widget has focus. The value should probably be held in a `value` attribute and should dynamically set the active descendant only on focus. 

Since `aria-activedescendent` is specifically about setting and managing focus, I don't think it is appropriate on an unfocused element. Since the combobox uses an `input` element as the root element, it's appropriate to use `value` to track the current value.
