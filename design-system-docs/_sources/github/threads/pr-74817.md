## Body

## What

Adds Storybook documentation for content elements of fields within `DataForm`, covering labels, placeholders, help text, and validation messages.

## Why

`DataForm` consumers need clear guidance on:
- **When to use each content element** — Understanding the semantic purpose of labels vs. placeholders vs. help text prevents common mistakes like using placeholders as label replacements.
- **Accessibility requirements** — Each element serves a specific role for assistive technologies. Without documentation, developers may inadvertently create inaccessible forms.
- **Writing effective content** — Clear guidelines help maintain consistency and usability across forms.

## How

**Documentation (`content.story.mdx`):**
- Added an **Accessibility** section explaining the semantic importance of each content element for screen readers and assistive technologies
- Created sections for **High-level help text**, **Labels**, **Placeholders**, **Help text**, and **Validation messages** with explanations of when and how to use each
- Included **Do's and Don'ts tables** with practical guidelines for writing effective content

**Interactive examples (`content.story.tsx`):**
- Created five Storybook stories demonstrating each content element type using `DataForm`
- Used consistent example fields (Name, Email, Phone number) across all stories for easy comparison
- Implemented validation messages that display on load to demonstrate error states without requiring user interaction
